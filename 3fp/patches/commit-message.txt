Add a picture mode for still and animated images

3FP opens still images through the video pipeline and treats them as
finished, one-frame playback: pictures report PlaybackEnded immediately,
seeking is rejected or clamped, animated formats (animated WebP, APNG,
animated AVIF/HEIC) and JPEG XR fall through entirely, and 2:1 panoramas
race with the 360 mode. This adds a dedicated picture mode while keeping
video behaviour unchanged.

Native:
- decide still images by the frame count instead of the demuxer name, so
  AVIF/HEIC (which ride the mov demuxer) are no longer mistaken for video
- keep still images interactive: opening no longer ends playback, seeking
  a still picture is a no-op instead of an error, and oversized sources
  (>16384 pixels) are rejected up front with a clear message
- report image details through the new FFF3FP_GetImageInfo: frame count,
  animation, EXIF rotation, pixel format and bit depth, ICC presence,
  alpha, colour primaries/transfer. The API is additive only - the
  snapshot struct and PlayerApiVersion stay at 15. The details are built
  on the worker thread while the media opens and handed out under the
  snapshot lock; an older host never calls the new entry point, and a new
  host cannot create a session on an older DLL at all (version gate)
- loop animated images (GIF/WebP/APNG/AVIF/HEIC) at the session level:
  APNG wraps via a session seek (ignore_loop) because the demuxer loses a
  frame at every wrap-around, WebP loops inside its demuxer because its
  seek reports success but stops supplying packets, and AVIF/HEIC
  sequences play their animation track instead of the still cover item
- carry wide gamut instead of clipping it: Display P3 stills are
  converted to BT.2020 (zscale) and, together with HDR sources, drive a
  16-bit scRGB swap chain when the display supports it; the three
  colour-mode gates that previously disagreed are kept in step and
  arbitrated by EnsureSwapChain

Player:
- picture mode: opening an image builds the picture list from its folder,
  hides the timeline, and enables zoom, pan and prev/next navigation;
  the mode is gated off for videos and yields to the 360 mode (2:1
  panoramas stay 360, verified by regression)
- animated images play and loop; .jxr/.wdp/.hdp join the media whitelist
- file associations gain three picture tiers (39 formats, each verified
  to decode and present with the bundled kernel)
- keyboard handoff between picture, 360 and clip modes respects handled
  keys so video shortcuts are untouched
- regression switches cover the whitelist, 2:1 exclusivity and the
  association registry round-trip

Video behaviour is unchanged: every picture path sits behind the
picture-mode or still-image checks. Two documented exceptions: the pan
clamp at zoom > 1 no longer shows a black edge on one side (shared
renderer path), and re-binding the same output window re-probes the
display refresh rate (a defensive change hosts do not trigger).
Verified: kernel and host build clean; a 17-sample probe matrix covers
still/animated/HDR/wide-gamut/oversize sources; all five animated formats
loop for minutes with zero stalls; generated SDR and HDR10 videos and a
2:1 clip still play, seek and end normally; the host regression suite
reports the same results as before the change.
