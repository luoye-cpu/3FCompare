### 9.1 新增的手动开关（都写真机 HKCU，故**不进** `run_host_tests.sh` 扫描清单）

### 9.2 接管内容（真机读数，`.png`）

```
接管前 default=WPS.PIC.png   |ct=image/png   |pt=     |name=(无)         |cmd=(无)
接管后 default=FFF.Player.png|ct=image/png   |pt=image|name=PNG 图片文件|cmd="...\FFF.Player.exe" "%1"
```

### 9.3 ★ 关键结论：注册表写对 ≠ 双击走我们

Windows 双击看的是 `HKCU\...\Explorer\FileExts\<ext>\UserChoice`（带哈希保护，第三方写不进去），
它**优先于** `HKCU\Software\Classes\<ext>`。本机实测（`tools/userchoice.ps1`）：

| 扩展名 | UserChoice | 双击结果（`tools/shell_open_probe.ps1` 走 ShellExecute） |
|---|---|---|
| `.apng` | 无 | **FFF.Player 接手**，窗口标题 `probe_apng.apng` |
| `.png` | `AppXtn09g7patsyascvjgfyyx71s4parg8g3`（已失效的商店 AppX） | 系统弹出「**选取应用**」（`OpenWith.exe`），没走我们 |

⇒ 这个功能的准确定位是：**把 3FP 登记成可用的打开方式**（进「打开方式」列表与"默认应用"选择器），
而不是静默夺走已有主人的扩展名。要真夺走双击，只能由用户在"默认应用"里点一次（由系统写 UserChoice）。
上游若要"勾选即接管双击"，需要额外机制，属另一个议题。

### 9.4 启动同步 A/B（我修的 `有已启用的类别` 判据）

真机播放器 `Settings.json` 只把 `关联常见图片` 置 true（视频/音频全 false）后启动 ⇒
`HKCU\Software\Classes\.png/.apng/.gif` 全部被注册、`SupportedTypes` 14 项齐全 ⇒ **重启后关联保持**。
修复前这条路径会被"任一启用"判据整体跳过（判据只列了 6 个视频/音频选项）。

### 9.5 实机跑出来的新缺陷：注销留下空壳键（已修）

`.apng` 在本机原本**没有** `HKCU\Software\Classes\.apng` 键。勾选→取消后，它变成"存在但空"的键
（`注销文件类型` 只删值不删它自己 `CreateSubKey` 建过的键）。**空键的 default 为空会遮掉 HKLM 的同名注册**，
本机 HKLM 恰好没有 `.apng` 所以没暴露症状，但这不是可以留的东西。

修法：`注销文件类型` 在还原完值之后，收掉空的 `OpenWithProgids` 子键，再判 `键已空` ⇒ 连键一起删。
沙箱测试补两条断言（启用后 `.apng` 键存在 / 取消后不存在），**并做变异验牙**：
把 `键待删 = 键已空(...)` 改成 `False` ⇒ 当场判红 `取消图片关联后残留 .apng 空键`；改回 ⇒ 判绿。

### 9.6 四条脚手架教训（都是这一轮自己踩的，别再犯）

1. **`Async Sub` 的续作要在 `Dispose` 前排空。** 注册表已落值 ≠ 同步已排空；抢在续作前拆窗**永久挂死**。
   单变量 A/B：`FA3FP_DRAIN=pump` 通过、`sleep`（只睡不泵）与 `none` 都挂 ⇒ 卡的是"UI 线程必须泵一次消息"，
   不是"广播要 3 秒"。排空放在 `Finally`，异常路径同样排空。
2. **失败路径必须自己收尾。** 一次判红把 14 个扩展名留在接管态；现在 `Finally` 里比对指纹，
   不干净就自动跑 release（实测这条救回过一次）。
3. **比较语义要一致。** `PerceivedType` 的写入判断是大小写不敏感的（本机 `.tiff` 原值 `Image`，我们判等价就不改写），
   断言却按大小写敏感比 ⇒ 假红。断言必须跟着被测实现的比较语义走。
4. **起跑态脏了会让"恢复后 == 接管前"平凡满足。** 上一轮残留的接管态当基线用，注销还没跑完就去查 ProgID ⇒ 假红。
   现在前置断言直接拒绝"起跑时已被本程序接管"。

## 3. 三个交接之外的缺陷

### 3.1 VB 注释会截断多行数组初始化器的隐式续行

```vb
New 文件类型定义(文件关联类别.老旧音频, ".mpc", "audio/x-musepack", "audio"),
' ═══ 图片 ═══            ← 上一行以逗号结尾，这里放注释行 ⇒ 续行断掉
New 文件类型定义(文件关联类别.常见图片, ".png", "image/png", "image"),
```
报 `BC30201 应为表达式`（停在逗号后一列）+ 72 个 `BC30035 语法错误`（此后每一项都被当成语句）。
**修法**：分组说明只能写在 `创建文件类型()` 函数上方，不能写进列表中间。已在函数头留注释警告。

### 3.2 `启动后台同步` 的判据漏图片类别（真缺陷，非编译问题）

`文件关联管理器.vb` 原判据把 6 个视频/音频选项逐个列进一个数组里判 `Any`。
用户**只勾图片档**时它判成"全部未启用" ⇒ 启动同步整段跳过 ⇒ 关联不写回注册表，
且**不报错**：勾选只在当次运行有效，重启就失效。
**修法**：抽成 `有已启用的类别(选项)`，判据从 `文件关联类别` **枚举**派生，新增类别时结构上不可能再漏。
测试里用 9 个类别各单独启用一次来钉死（`Program.vb`，断言"启动同步的启用判据漏掉了某些文件关联类别"）。

### 3.3 设置页几何：独立页面的设计尺寸不是出货尺寸

- 真实显示器 144 DPI（1.5×）。每行 `Text + SubText` 实高 **62px**，九行 558px。
- 交接建议的 `y=254/293/332` 按 39px 间距算，那是**未缩放的编辑器字面值**；`Dock=Top` 下 Location 只是序列化残留，不参与最终排布。
- 我先把判据写成"独立构造 `New Form设置_文件关联()` 后量面板" ⇒ **判红**：独立页只有设计尺寸 554×419，
  面板窄一档让 SubText 多换一行、行高涨到 **75px**，九行 705px 超出可视底 598px。
  **这个红是量错构型，不是产品缺陷**——设置页在运行时被 `Dock=Fill` 进设置窗内容面板。
- 量宿主实形：页面 **954×679**、可视区 `{15,30,909,619}`、九行最底 **588** ⇒ **余量 61px，放得下**。
  判据改为量宿主页面（`Form设置` → `SelectedIndex=9` → 反射取 `文件关联页面`）。
- **两条新判据都做了变异证明有牙**：
  ① 面板底内边距 20→120 ⇒ 余量 **−89px**、判红；
  ② 把图片三项按"视觉顺序"追加到 `Controls.Add` 末尾 ⇒ 判红并打出实际顺序
  （图片档整组跑到最上且内部逆序），同时反证 §2 的反向加入规则。
  两次变异均已还原，`git diff` 对 Designer 是 **66 行纯新增、0 删除**。

## 4. 覆盖度：把清单换成实测分母

用户口径是「制作所有能解码的图片」，所以要先有分母。**判据**：随包内核
`Open` 返回 `Success(0)` **且** 快照 `presented ≥ 1`——只看 `Open` 不够，能认出容器不代表能解出并呈现像素。

**工具**（两份都入库）：
- `tools/cover_probe.sh` —— 本机 ffmpeg 当**生成器**（写得出该格式即可），`build/verify_image_mode.exe`
  加载**随包** `FFF.Native.dll`/`avformat-63.dll` 当**判据**。`--current` 反向审计已声明的 35 条，`--alias` 处理同族换皮（`.jpe/.jfif`←`.jpg`、`.cur`←`.ico`、`.pnm`←`.ppm`、`.heif`←`.heic` 字节流）。
- `tools/cover_probe_handmade.sh` —— 手工构造 ffmpeg **写不出**、只有解码侧的格式（`.xpm` 文本、`.icns` 容器、`.ora` zip）。
- 自检：先用已知真值 `samples/media/basic/01b_srgb_1920x1080.png` 跑通探针（`Open: 0 / presented=1`）再用。

**结论矩阵**（完整读数见 `build/cover_probe/`、`build/v_*.log`）：

| 结果 | 扩展名 |
|---|---|
| 实测可呈现（判据通过） | png jpg jpeg jpe jfif **apng** bmp gif webp avif avifs ico cur heic heif tiff tif jxl **jp2 j2k j2c** exr hdr tga pcx dds qoi pnm pbm pgm ppm pam **xbm** xpm xwd **dpx** sun ras sgi |
| 打开成功但**一帧不呈现** ⇒ 排除 | **`.dib`**（本机 avformat 无 `dib` demuxer；强制 `-c:v bmp` 报 `bad magic number`）、`.fits`、`.rgb`（后两个本就不在清单） |
| 本机无法构造可信样本 ⇒ 排除并记录 | **`.pcd`**（解码器实名 `photocd`，demuxer 表里没有 `.pcd` 条目，且无法伪造出能解出像素的 PPCL 载荷） |
| 未能判定（构造成本高，且当前不在清单） | `.psd` `.icns` `.ora`（我的手工夹具被判 `Invalid data`，**分不清是夹具还是能力**——见 §5 教训） |

**净变化**：图片档 35 → **39** 条（常见 14 / 不常见 13 / 老旧 12）；
对照：视频 20、音频 22。测试里加了「图片清单不得混入实测不能呈现的格式」与「不得有重复项」两条守卫。

## 5. 踩到并记下的两个取证教训

1. **报"格式不行"之前先疑自己的夹具。** `.xpm` 第一次失败是因为我写的 XPM 行宽只有 2 字符却声明 `4 4`；
   补齐行宽即 `presented=1`。`.dds` 连续两次失败，原因是漏了 `DDS_HEADER.reserved1[11]`（44 字节）
   与 pixel-format 字段序（`dwFourCC` 与 `dwRGBBitCount` 之间）；按规范补齐后 `presented=1`，
   并用本机 ffmpeg 独立转出 PNG 作**第二参照**才收工。
2. **grep 解码器名 ≠ 判"没有解码能力"。** 我按扩展名 grep `-decoders`，漏掉了
   解码器实名与扩展名不同的情况（`photocd` vs `.pcd`、`jpeg2000` vs `.jp2`），
   也会被无关子串假命中（`dib` 命中 `Audible`）。负断言要回看命中行本身。
