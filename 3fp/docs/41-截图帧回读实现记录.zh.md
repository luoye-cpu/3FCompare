## 1. 实现要点

### 1.1 新导出（不动 ABI）

```cpp
FFF3FP_CopyFrame(player, pixels, capacity, &w, &h, layout, format)
FFF3FP_GetLastCopyFrameBitDepth(player, &bitDepth)
```

| 参数 | 取值 |
|---|---|
| `layout` | `Source=0`（源分辨率，含旋转）/ `Window=1`（当前窗口） |
| `format` | `Bgra8=0`（4 B/px）/ `Rgba16Float=1`（8 B/px，线性 scRGB，1.0=80 nits） |

`PlayerApiVersion` **仍为 16** —— 沿用 VSR/旋转的约定：追加导出而非升版，
避免 `FFF3FP_Create` 的严格版本校验打断 3FC 宿主。

### 1.2 核心改造：`DrawCachedVideo` 尺寸参数化

```cpp
FFFResult DrawCachedVideo(ID3D11RenderTargetView* target,
    std::uint32_t outputWidth, std::uint32_t outputHeight) noexcept;
// 旧签名保留为内联重载，默认传 swapWidth_/swapHeight_ => 呈现路径行为不变
```

**这是整个方案成立的关键**：`DrawCachedVideo` 本来就接收任意 RTV，只是目标矩形
写死用交换链尺寸。参数化后，同一套渲染逻辑既能画到屏幕，也能画到**源分辨率的离屏纹理**
——不必新造第二条渲染路径，旋转/色调映射/scRGB 全部**自然一致**。

### 1.3 离屏表面（与交换链完全解耦）

- 私有 `offscreenTexture_` + `offscreenTarget_`，尺寸/格式不变则**复用**；
- 渲染 → `CopyResource` 到 STAGING → `Map` → 逐行 `memcpy`（去掉 RowPitch）；
- **全程不碰后缓冲** ⇒ 不受遮挡、最小化、虚拟桌面影响，也不扰动在显画面。

### 1.4 三种格式 / 两种位深的处理

| 交换链格式 | `format=Bgra8` | `format=Rgba16Float` |
|---|---|---|
| `B8G8R8A8_UNORM` | 直接拷（Windows 位图本就是 BGRA） | — |
| `R10G10B10A2_UNORM` | 由 `DrawCachedVideo` 渲染到 BGRA8 目标 | — |
| `R16G16B16A16_FLOAT` | 同上（引擎会做映射） | 直接拷 HALF，**保留线性值** |

> 关键点：**位深由"目标纹理格式"决定，而不是"交换链格式"**。
> 所以 HDR 下既能取 8-bit（映射后）也能取 16-bit（原始线性），由宿主按用途选。

## 2. ⚠️ 实测暴露的一个真实缺陷（引用计数）

**现象**：第一次截图成功；**第二次（遮挡后）访问违例 0xC0000005**。

**定位**：给探针加逐步标记，确认崩在第二次 `CopyFrame` 的"取像素"阶段
（尺寸查询返回 `-3` 正常，说明帧可用）。

**根因**：

```cpp
// AcquireOffscreenTarget 返回的是**成员指针的借用引用**
*texture = offscreenTexture_;   // 引用计数仍为 1（成员持有）
...
// CopyFrame 里用 ComPtr 接：
ComPtr<ID3D11Texture2D> texture;
AcquireOffscreenTarget(..., texture.GetAddressOf(), ...);
// ⇒ 作用域结束时 ComPtr 析构 -> Release -> 计数归 0 -> 成员变悬垂
// ⇒ 第二次调用读已释放内存 -> 崩溃
```

**修复**：拿到借用引用后**自己 AddRef**，明确"这一段归我"。

> **教训**：返回**成员指针**却让调用方用 `ComPtr` 接收，是引用计数陷阱。
> 只跑一次不会暴露——必须**连续两次调用**才现形。这也是为什么遮挡测试有价值：
> 它天然包含两次截图。

## 3. 宿主接线

| 文件 | 改动 |
|---|---|
| `Interop/播放器原生接口.vb` | 动态解析 `CopyFrame`/`GetLastCopyFrameBitDepth`（两次调用契约） |

**顺带修掉**：保存路径不再用 `Environment.CurrentDirectory`
（从快捷方式启动时可能是 `System32`），改为**媒体所在目录 → 图片目录 → 当前目录**。
