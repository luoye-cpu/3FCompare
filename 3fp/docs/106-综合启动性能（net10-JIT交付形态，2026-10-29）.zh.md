# 综合启动性能报告——net10 + JIT 交付形态（2026-10-29）

- 交付形态（用户拍板）：**net10 + JIT 默认（R2R 关）+ IAMF 强制携带 + 单文件框架依赖**；R2R 以 `-ReadyToRun` 余量开关保留。
- 对应提交：kernel main `b5a22d1`（IAMF 强制携带）、`6aaed92`（R2R 默认关/余量开关）、`d8ae827`（投影配对护栏）；已推送 fork 分支 `pub/iamf-release-carry`（非破坏；fork main 与上游 main 已分叉 28/52 笔，未强推）。
- 本报告综合 docs/103/104/105 与本轮实测；⚠ **本轮后半段机器进入极端负载**（SogouCloud/QQ/WorkBuddy/SRBMiner/AutoClaw 五邻居累计 >13 万 CPU 秒，瞬时 91%），高负载窗口读数只作上界参考，已逐条标注。

## 一、交付物与构成（实测）

- `FFF.Player.exe` 单文件：**45,589,568 B（43.5 MB）**，含：SDK.NET 27.25 + 托管 IL ~6.3（LakeUI/Svg/ExCSS/Vortice 系）+ **内核 5.62（含 IAMF 静态库）** + libass 族 ~5.5 + apphost 0.3。**IAMF_decoder_open 在位**（`-SkipIamf` 对照臂 48,865,344 B 无）。
- 伴生（不捆绑但必需）：FFmpeg 六件套 ~105 MB + 其传递依赖（libomp/libshaderc/libunwind/libwinpthread——见 docs/105 §十五）+ .NET 10 Desktop Runtime。
- 单文件首跑解压载荷实测：**10.6 MB** 原生件 → `%TEMP%` 或 `DOTNET_BUNDLE_EXTRACT_BASE_DIR`。

## 二、启动实测汇总（sample_1920.png，T0→T1 出窗 / T2 上屏）

| 形态 | 窗口负载 | T1 中位 | **T2 中位** | 样本 | 判定 |
|---|---|---:|---:|---|---|
| bin 散装 IL（JIT） | ~68-70% | 1748.0 | **1893.0** | 10+10 | 有效（本轮基线） |
| **单文件 IL（JIT，最终形态）** | **91%** | 2770.7 | **2862.5**（2568–3353，9/9） | 9 | ⚠ 高负载上界参考 |
| **单文件 IL 首跑（含 10.6 MB 解压）** | 91%（spawn 即 1735 ms） | 5066 | **5190.2**（单轮） | 1 | ⚠ 上界参考 |
| 单文件 R2R（余量开关，同 IAMF 形态） | ~70% | 1588.0 | **1717.2**（1610–1844，5/5） | 5 | 有效（较早窗口） |
| net11-rc2 bin（JIT） | 同窗 | 1811.4 | 1963.6 | 10+10 | U=43/100，与 net10 无显著差异 |

**综合结论**：
1. **当前形态（JIT）综合启动 ≈ 1.9 s 档**（干净窗口基线：bin 形态 T2 中位 1893 ms；单文件形态的干净样本被极端负载阻断，按构成推断与 bin 同档——单文件免去 ~150 个散装文件探测、但新增解压已预热吸收）。
2. **R2R 余量实测 −176 ms**（同窗 1893→1717），一键 `-ReadyToRun` 可取，代价 +7.84 MB。
3. **首跑（版本更新后第一次启动）另有 10.6 MB 原生件解压**：本轮极端负载下单轮 5190 ms（含 spawn 1735）；安静窗口预期为秒级内一次性成本，之后归零。
4. **IAMF 携带对启动零代价差异**（静态库随内核加载；-SkipIamf 对照无启动差）。
5. **net11-rc2 无收益**（U=43/100），且 R2R/AOT 被 CJK 资源名编译器崩溃阻断（docs/105 §九/§十二）。

## 三、阶段构成（形态无关部分沿用 docs/103/105 实测）

进程创建→运行时引导 ~16 ms → CLR+CoreLib ~20 ms → WinForms/DWrite ~115 ms → 托管 UI 栈/JIT ~434 ms → D3D/驱动（nvgpucomp ~704 ms）~242 ms → 托管收尾 ~363 ms → FFmpeg+内核接入 ~30 ms → 窗体收尾→T1 ~340-680 ms → **内核开图链 T1→T2 ~86-94 ms**（上传 2.0 + 软件转换 4.5 + presentWait 4.5 可归因；FFmpeg 首映射+解码+设备/交换链 ~75 ms 未细分）→ 上屏。JIT 形态的主要可压缩面仍是三段托管 JIT（~1.25 s）——R2R 余量开关即为此预留。
