# 音频输出徽章：三态循环（传统多声道 / HRTF / 源码直通）（2026-11-12）

## 一、需求

用户（2026-11-12，附截图）：底部状态条的 `HRTF` 与 `5.1` 两个徽章信息重复，合并为**一个按钮**；该按钮显示**输出侧情况**（如 `5.1`、`立体声`、`HRTF`），点击在**传统多声道 ↔ HRTF ↔ 音频直通**之间循环。补充口径：

- 直通是按钮的一个状态；按到直通时**正常弹窗**（沿用 WASAPI 独占确认框）。
- 用户拒绝直通后：**下一次按跳过直通，下下次返回当前状态，下下下次才显示直通**。
- 原双耳徽章行为（点一下 自动↔强制反向）由三态循环取代。

## 二、设计

### 状态机（Form1，点击驱动）

```
[传统] --可用--> [HRTF] --可用--> [直通] --确认--> 直通接管
   ↑                 |                |
   └────── 退出直通 ──┘               └─ 拒绝 → 置 跳过旗标
传统→HRTF→直通→传统…循环；双耳不可用（多声道端点/插槽缺席）时跳过 HRTF 直接 传统↔直通
```

- **进入直通**：共享模式 → 弹既有 `确认切换到WASAPI独占模式()`（文案改为"源码直通需要切换到 WASAPI 独占模式"）→ 切独占 + 偏好=自动。**1.5 s 后回读快照**：未接管（模块缺席/端点不支持/被占用）→ 偏好回**关** + 独占回共享 + 提示"源码直通未生效，已回退解码"；接管 → 提示"源码直通：已接管"。
- **退出直通**：偏好回关 + 独占回共享 + 双耳回"传统"。
- **拒绝跳过**：`直通跳过一次` 旗标；下一次按直通直接落到"传统"，再下一次回到拒绝前状态，第三次才重新弹窗（用户口径逐字实现）。
- **防连点**：`正在切换音频输出` 在弹窗后的切换/回退窗口内置位，期间点击忽略。

### 徽章文本（UI 呈现器，每 100 ms 刷新）

优先级写**实际输出**（延续"显示现在听到/看到的是什么，不是意愿"纪律）：

1. `快照.音频直通已接管` → **直通**（告警橙 `#FFA85A`，与独占切换提示同色）
2. `快照.IAMF已接管` → IAMF 布局名（7.1.4 等，银色）
3. `双耳状态.可用 且 期望双耳` → **HRTF**（青 `#55E7EA`，与信息图层"双耳"行同色）
4. 其余 → **传统多声道**：按内核回报的**输出声道数**（WASAPI mix，`媒体流信息.输出声道数`，缺席退源流）格式化：1=单声道、2=立体声、6=5.1、8=7.1、10=5.1.4、12=7.1.4、其它 `Nch`（银色）。

可见性：直通接管 / 双耳可用 / 有音频流任一成立；源流布局放 ToolTip（`输出：… · 源 5.1（点击循环：传统/HRTF/直通）`，动态更新）。

### 吸收的旧功能

- 旧 `5.1` 徽章（`MB_当前声道数显示`）的隐藏行为是 **WASAPI 独占/共享开关**（`Form1.vb` 旧 :1205）——其入口收编进直通状态（进直通=确认切独占、退出=回共享），旧控件与占位隐藏、旧点击处理器删除、旧 `更新WASAPI按钮`（红色独占指示）删除。
- 源声道数信息由信息图层"输入/输出"行继续承担，徽章只在 ToolTip 摘要。

## 六、追加分析：耳机输出下"自动 HRTF"的保障链（用户追加要求，2026-11-12）

只读分析 + 探针重跑，**零代码改动**。结论：**耳机端点（形态 3/5）+ 自动策略 ⇒ HRTF 双耳**由内核单一判定函数保障，徽章三态循环不破坏它。
（**2026-11-12 追加更正**：本节所记"自动=形态 3/5"的规则已被用户裁定废除，自动语义改为**按端点声道数**——2 声道默认激活、多声道回退传统，见 **docs/155**；本节保留为旧规则的历史记录。架构澄清：HRTF 的接缝/策略/回读/徽章是本体功能，渲染实现与授权由模块函数表承载，见 §八。）

1. **规则本体**：`PlayerWasapiRenderer::BinauralWantedFor`（`WasapiRenderer.h:134-140` inline）——auto ⇔ `IsHeadphoneEndpointFormFactor`（**3=Headphones、5=Headset**；1 扬声器 / 9 数字（HDMI/DP/多数 USB DAC）/ SPDIF / 未知 0 一律折叠）。渲染器**每床帧**用它选路由（`SelectBedRoute`，`WasapiRenderer.cpp:482`），`GetAudioBinauralStatus` 回读（`PlayerSession.cpp:2644-2658`）用**同一个函数**——注释明言"the two must agree or the badge would describe a route the audio thread is not taking"。
2. **形态来源**：renderer 打开设备时读端点属性 `PKEY_AudioEndpoint_FormFactor`（`:1191-1195`，0=没读到→按非耳机）；设备一换 renderer 重建、形态随之更新、策略继承（`PlayerSession.cpp:2172`）。
3. **自动 HRTF 实际接管还需**（`SelectBedRoute` 每帧）：非 mono、**插槽已装**（HRTF 模块表）、端点 mix=**2 声道**、床 >2 且 ≤16 声道；**2.0 素材不进接缝**（本来就是双耳目标布局）。
4. **宿主保障链**：内核默认策略=0（自动）、宿主 `设置.双耳策略选项` 默认 0；100ms 心跳 `同步双耳策略` 幂等下发；**强制不跨设备泄漏**——`折算双耳策略` 对强制策略记端点形态，形态不匹配即折回自动 ⇒ 在音箱/数字输出上被强制过的策略，插上耳机（3/5）后自动回到"自动=双耳"。本轮徽章三态走同一持久化路径：耳机+自动 → 徽章 HRTF（可用且期望双耳）；拒绝直通落到"强制立体声(形态=耳机)"，拔耳机换扬声器 → 形态 mismatch → 自动 → 折叠 → 徽章回 立体声/5.1。
5. **实证**：重建 `audio_binaural_probe`（出货头文件 inline 规则直接编进探针 = 测的是出货代码；文档注明这是唯一能在非耳机机器上盖到 headphone 分支的方式）并对当前内核 `EC3B89A550B3BD0E` 重跑：**19/19 PASS、exit 0**——含 "auto: headphones only (3,5)、force-binaural ignores shape、force-stereo overrides headphone、unknown shape = not headphone、kernel formFactor == 独立 MMDevice 查询（本机 9，mix 2ch，live auto wanted=0 属预期）"。
6. **边界（Windows 语义，非缺陷）**：多数 USB DAC 被 Windows 报成 9（DigitalAudioDisplayDevice）而非 3 ⇒ 自动不触发，需用户用输出徽章点一下（强制双耳压过——内核注释即此设计意图）。徽章表达"路由意图（策略×形态）"；2.0 源或模块婉拒时信息图层"双耳"行（真接管 `音频双耳渲染生效`）不出现——徽章与信息图层两层各司其职，与旧双耳徽章口径一致。

## 七、追加调整：徽章真值化——显示真实情况，不是路由意图（用户追加要求，2026-11-12）

§六 指出徽章 HRTF 用的是"策略×形态"的**路由意图**，与真接管（`音频双耳渲染生效`）在三种情况下会分叉：2.0 源（无床）、模块婉拒、接管前过渡帧。用户随后要求"确保徽章显示的是真实情况"⇒ 本节把徽章与点击循环全部改到真值上：

1. **HRTF 态改为真接管**：`刷新音频输出按钮` 的 HRTF 分支从 `可用 && 期望双耳` 改为 **`快照.音频双耳渲染生效`**（内核床渲染接缝真的拥有床）。直通（`音频直通已接管`）与 IAMF（`IAMF已接管`）本就是真接管，未动。2.0 源/模块婉拒时徽章诚实显示传统布局，不再假绿。
2. **传统态布局跟随设备**：输出声道数来自媒体信息探针（内核按**当前** renderer mix 格式回 `outputChannels`）；新增 `播放器界面呈现器.更新音频流信息()` 轻量重探（只换音频流信息+刷新徽章，不动章节/编码徽章），由 `Form1.播放控制器_状态已变化` 调用——设备热切换、WASAPI 模式变化、各类回退（控制器 `会话_设备变化` 等都 raise 状态已变化）后徽章跟着真实端点走。
3. **点击循环也改真值定位**：位置判定 = 直通接管 → 直通态；`生效`（或已请求强制双耳**且**这条轨有床 >2 声道，覆盖接管前过渡帧）→ HRTF 态；否则传统态。传统→HRTF 一跳加**有床闸门**：`界面呈现器.当前音频声道数 > 2` 才设强制双耳，**2.0 源直接跳到直通尝试**——HRTF 对 2.0 永不生效，不让用户"点了个寂寞"；模块婉拒的多声道轨也不会卡死循环（下一拍走到直通）。"双耳：HRTF 空间音频" toast 只在有床路径出现。
4. **ToolTip 2.0 说明**：双耳就绪（可用且期望双耳）但源 2.0 时提示"输出：立体声（耳机双耳已就绪；当前音轨 2.0，无床可渲染）"。
5. **实测（本机）**：300s 5.1 AC3 + 真值徽章构建——点输出芯片 → 直通弹窗 ✓、拒绝 → 跳过 toast ✓、徽章"立体声"=本机真实状态（无模块 ⇒ 生效恒 false）✓、状态已变化重探无副作用 ✓。耳机+模块场景（生效 true 的翻转、2.0 直跳直通）留 U。
6. 产物：`FFF.Player.dll` **1,225,728 B / sha16 `47C8C0A02D824224`**（2026-11-12 05:0x）；构建 0 警告 0 错；零 commit / 零 push。

## 八、架构澄清（用户裁定"你重新思考一下"，2026-11-12）

- **HRTF 的接缝/策略/路由/回读/徽章是本体功能**；**渲染实现与授权在模块**——契约头原文（`FFF.Player.AudioRenderPlug.h:5-11`）："rendering a channel bed to binaural output is an implementation that needs authorization to write, so it does not belong in the body. The body keeps only this neutral seam plus the matrix fold-down... The host loads the external module, authenticates it, and hands the kernel a function table."
- 本机证据：模块文件 `FFF.HDRdp.Test.dll` 不在播放器 bin 目录（"缺席是常态而非错误"）⇒ `plugInstalled=false` ⇒ 床按设计矩阵折叠。§六/§七 中"HRTF 模块""本机 HRTF 插槽未装"的措辞不准确，应为"授权床渲染实现（模块函数表）未在场"。
- 由此修正产品代码一处：可用=False 时 tooltip 不再笼统写"当前端点不支持 HRTF"（端点明明是 2 声道），拆为两种真因——输出声道 >2 ⇒ "多声道输出，HRTF 不适用"；否则 ⇒ "HRTF 渲染器未就绪"（不提模块/授权细节，守"缺席静默"纪律）。
- HRTF 实现路径不唯一（用户指出）：授权模块是一条；IAMF 等公开标准自带 HRTF 相关渲染。徽章按"谁真接管显示谁"设计，天然容纳多路径——当前快照只有接缝路径发布真值；IAMF 声场映射全为扬声器布局、无双耳输出值，其自带双耳落地时应有自己的真值来源。自动默认语义已按用户裁定改为**按端点声道数**（2 声道默认激活、多声道回退传统），内核侧落地见 **docs/155**。
