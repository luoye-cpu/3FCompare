# AVIF 渐进式（分层）与 grid 修复计划（2026-10-20）

> 承接上一轮的只读调研结论：`3fp/docs` 下 99 号静图硬解交接与本轮实测。
> 本文档是**修复台账**：缺陷清单 → 根因 → 方案 → 验证 → 进展。边做边更新。

## 1 缺陷清单与根因（均已实测）

| # | 缺陷 | 根因 | 判据 |
|---|---|---|---|
| **P0** | 渐进式（分层）AVIF **打不开** | FFmpeg `mov_read_iloc` 见 `extent_count > 1` 直接 `avpriv_report_missing_feature` → `AVERROR_PATCHWELCOME`，**打开阶段即失败，到不了解码器** | 样本 `fox-progressive.avif` 在两个独立构建（FFmpeg master 参照构建 + `C:\PLAN\FFmpeg` 全功能构建）上均报 `iloc: extent_count > 1 is not implemented / Not yet implemented in FFmpeg, patches welcome`；3FP 捆绑 `avformat-63.dll` 内含同一拒绝串、`avutil-61.dll` 内含 "patches welcome" 串 |
| **P1** | grid AVIF **只显示第一块 tile** | FFmpeg 7.0+ 把 grid 拆成多条 tile 流（无一条带 `AV_DISPOSITION_DEFAULT`）+ 一个 `AV_STREAM_GROUP_PARAMS_TILE_GRID` 组；3FP `FindDefaultOrFirstStream`（`PlayerSession.cpp:618`）无 default 时取第一条流，且只处理 IAMF 组 | `sofa_grid.avif`：5 条 1024×154 流，合成应为 1024×770；ffmpeg CLI 靠 `xstack` 才合成 |
| **P2** | `.avifs`（动画 AVIF）**不被识别** | 文件关联注册了 `.avifs`（`文件关联管理器.vb:517`），但播放列表的媒体/图片扩展名集合里没有（`Core/播放列表.vb:26-39`） | 源码对照 |

附带（未修，登记）：alpha 辅助通道、irot/imir/clap 未实测；动画 grid 未覆盖。

## 2 方案

### P0：容器层就地补丁（不动 FFmpeg DLL，不自研 demuxer）

分层 AVIF 的 item 数据在 mdat 中被切成多个 extent（基层 + 增强层），libavif 写出的两段**首尾相接**。
把它们合并成单 extent 即可让 mov demuxer 正常解析，而合并后的字节流正是完整 OBU 流——
libdav1d 默认只输出最高层（`alllayers=0`），即渐进 AVIF 期望的最终图（隔离实验 PSNR 32.03 dB 已证）。

**补丁规格（就地，文件其余部分一字节不动）**：
- 命中条件：ISOBMFF；`ftyp` 品牌属 AVIF/HEIF 家族；`meta` 内含 `pitm` 与 `iloc`；
  目标 item（pitm 主项）`extent_count > 1` 且是 iloc 中**最后一个** item；`index_size == 0`；
  `construction_method/offset_type == 0`（文件偏移）；各 extent 按 `(base_offset+extent_offset)` 排序后
  **首尾相接**；合并段在文件范围内。
- 动作：该 item 的 `extent_count` 改 1；第一个 extent 的 `length` 改为合并总长；
  其余 extent 条目**原样保留**成死字节。
- 安全性：`mov_read_iloc` 只读一个 extent pair 后 `return atom.size`；
  `mov_read_default`（mov_master.c:10529-10531）有 `left = a.size - avio_tell(pb) + start_pos; if (left > 0) avio_skip(pb, left)`，
  按**声明 size** 跳到 box 尾，残留字节当 "garbage at atom end" 被跳过。多 extent item 必须是最后一项，正是此因。

样本真值（`fox-progressive.avif`）：iloc @91 size=38，v0，off/len=4，base/idx=0，item_count=1；
item_ID=1 @107，data_reference_index @109（HEIF 的 iloc v0 也有此 2 字节，ffmpeg 无条件读）；
extent_count=2 @111；extent[0] offset=299 len=5491 @113/117；extent[1] offset=5790 len=149110 @121/125；
补丁后 → extent_count=1，extent[0].length=154601。

**接线**：新 `3FP/Core/AvifIlocShim.{h,cpp}`（纯字节解析，不依赖 FFmpeg）+ `SharedFileInput::OpenMemory`；
`PlayerSession::OpenFormat` 先试补丁，命中则走内存 AVIO 打开，未命中/失败**回退原路径**。

### P1：Tile Grid 合成

- DoOpen 里检测 `AV_STREAM_GROUP_PARAMS_TILE_GRID`，记录 group 指针与几何；grid **静图强制软解**（避开 N 个硬件解码器初始化，tile 小、软解快）。
- `DecodeInitialFrame` 对 grid 走合成路径：逐 tile 流软解一帧 → 按 `offsets[i]` 的 `horizontal/vertical` 贴到
  `coded_width × coded_height` canvas（越界裁剪、背景色填充）→ 走与普通静图完全相同的
  `NormalizeVideoFrameTimestamp` + `PresentVideoFrame`。
- `BuildImageInfo` 对 grid 报 canvas 尺寸而非 tile 尺寸。

### P2：补扩展名

`Core/播放列表.vb` 的 `媒体扩展名`(:32) 与 `图片扩展名`(:38) 加 `.avifs`，与文件关联对齐。

## 5 验证结果（均已实测）

**P0 补丁（组件级）**：`AvifIlocShim::RepairInPlace` 对 `fox-progressive.avif` 只改 4 字节——
`extent_count` 0x0002→0x0001、extent0.length 0x00001573→0x00025BE9（154601）；`fox.avif`/`sofa_grid.avif` 判定为单 extent、**一字节不动**。
补丁后：系统 ffmpeg（libdav1d）解出顶层图，PSNR **32.025 dB** 对 `fox.png`；**捆绑 avformat-63.dll** 打开 `open=0`、mov/av1/1598×1753/nb_frames=1/DEFAULT（未补丁则 `Not yet implemented in FFmpeg, patches welcome`）。

**P1 合成（组件级）**：合成 canvas 与 ffmpeg 自己的 xstack 合成 **逐字节一致**（1024×770 yuv420p，1,182,720 字节，`cmp` 无差异）。
（PNG 域比对只有 28.7 dB，是色彩范围解释差异，不是落位问题——已在 YUV 域用 `cmp` 排除。）

**端到端（schtasks 跑进程树外，A/B 同一环境）**：

| 样本 | 发布版 DLL（API 19） | 修复后 DLL（API 20，手工构建） |
|---|---|---|
| `fox-progressive.avif` | ❌ `Could not open local media: Not yet implemented in FFmpeg, patches welcome` | ✅ OpenCompleted、1598×1753、presented=1 |
| `fox.avif` | ✅ | ✅ 1598×1753、presented=1（无回归） |
| `sofa_grid.avif` | （未跑基线） | ✅ **1024×770**（canvas，不再是 1024×154 单块）、presented=1 |

附带修正：grid 静图的快照原来会报 tile 尺寸（宿主看到 1024×154），现报 canvas；媒体信息 JSON 新增 `tileGrid`/`tileGridWidth`/`tileGridHeight`/`tileGridTileCount`。

⚠ **一次性异常**：某轮 e2e 中 `fox.avif` 退出码 `-1073741819`（0xC0000005）一次，同二进制同样本未能复现（后续 A/B 正常），登记待观察。

⚠ **构建说明**：本环境 `dotnet`/`MSBuild` 被安全策略按 LOLBin 拦截，验证用 DLL 由 `cl.exe` 手工编译链接而成（flags 与工程管线不同，**不可直接出货**），落在 `C:\Users\20210\AppData\Local\Temp\avifprobe\kern\FFF.Native.dll`。出货仍须走工程自己的构建管线；出货树的 DLL 未被覆盖。
