## 0. 判词

**管线是健康的，用户面是残缺的。** 时钟、缓冲、精度三件事在 53/54/55 号文档里已经量过且有余量（A/V 漂移 0.0000 s / 60 s，峰值扫描 0.002 ms/秒），本轮没有发现需要修的正确性缺陷。要说的全是**"能力在内核里，用户拿不到"**这一类不对称。

| 档 | 内容 |
|---|---|
| **真通到用户** | 音量+静音、音轨切换、WASAPI 共享/独占、峰值电平条、信息层的音频五连行 |
| **半通** | 外部音轨（能拖进来，不能撤、不能调偏移、不能选流）；IAMF（能解，但渲染布局恒 7.1.4，用户无从配置） |
| **死 API**（有导出、宿主有绑定、**零调用者**） | `SetAudioEndpoint`、`SetAudioDelay`、`ClearExternalAudio`、`SetExternalAudioOffset` |
| **ABI 有槽、恒为 0** | `iamfBinaural`、`audioBinaural`、`audioRejectedFrames`（UI 已经把最后一项渲染成"拒绝 N"，而它永远不会非零） |
| **内核就没有** | 音频设备枚举、AC3/DTS/TrueHD 码流直通、响度归一化/DRC/EQ、变速不变调、gapless/音频截取、频谱/波形、音频导出 |

三句话要点：

1. **用户换不了输出设备。** 原生只有 `SetAudioEndpoint(id)`，全树没有端点枚举——而同一个原生工程里 Recorder 侧就有一份能用的枚举实现（`3FR/Api/NativeApi.cpp:95 AppendEndpoints`）。托管侧的创建配置里那个 `音频端点标识` 字段（`FFF.Player/Core/播放模型.vb:96`）没有任何人赋值，恒空 ⇒ 恒默认设备。
2. **多声道到耳机只有一条路：swr 矩阵折叠。** 双耳渲染器 `3FP/Audio/BedBinauralRenderer.cpp`（439 行）在本地是**编译得进来的**（`third_party/libiamf/` 在位 ⇒ `HaveLibiamf=true`，`FFF.Native.vcxproj:60/156`），但两棵树的 `3FP/` 目录内**零调用点**，且快照的两个双耳字段没有任何写入者 ⇒ 用户既得不到 HRTF，也得不到"HRTF 还是矩阵"的读数。
3. **直通结构上就不可能。** 独占模式协商表里 SubFormat 只有 `KSDATAFORMAT_SUBTYPE_IEEE_FLOAT / _PCM`（`WasapiRenderer.cpp:629`），位深只试 16/24/32 ⇒ AC3/DTS/TrueHD 到功放那一跳必然经历"解码 + 重采样重编码"。

## 1. 管线拓扑与实测参数

只有两个线程：`PlayerSession::Worker`（`Core/PlayerSession.cpp:2346`，创建于 `:703`，demux/decode/排队同一条线程）和 WASAPI 事件线程 `PlayerWasapiRenderer::RenderThread`（`Audio/WasapiRenderer.cpp:560`，创建于 `:145`）。视频另有软件解码工作线程（`PlayerSession.cpp:3483`，函数 `:3495`），**音频没有**。

生产端节流水位：`TargetAudioBuffer100ns = 1'200'000`（`PlayerSession.cpp:53`，判据点 `:850/3156/3175/3177`）——按 100 ns 单位即 **120 ms**，与 54/55 实测的 0.10–0.18 s 相符；`docs/53` 把它写成"1.2 s"是单位口径错（见 §7）。

| 环节 | 实况 | 证据 |
|---|---|---|
| 分流 | 音频包仅在 `stream_index == audioStream_ && externalFormat_ == nullptr` 时进内嵌路 ⇒ 外挂轨一旦加载，内嵌轨静音 | `PlayerSession.cpp:3240` |
| 压缩态队列 | 512 包 / 8 MiB 封顶（视频侧是 64 包 / 16 MiB） | `PlayerSession.cpp:57-58`、判满 `:3185` |
| 解码 | **恒软解**：`OpenDecoder` 的硬件分支写死 `hardwareRequested = video && useConfiguredHardware && decodeMode_ == D3D11` | `PlayerSession.cpp:2491`、音频调用点 `:2781` |
| IAMF | libiamf 参考解码器取代 FFmpeg，渲染目标写死 sound system **F（3+7+0）= 12 声道 = 7.1.4** | `Audio/IamfAudioDecoder.cpp:157` |
| PCM 队列 | 分块 SPSC `queue_`（**无硬上限**）+ 复用池 ≤8 个 / 单个 ≤1 MiB | `WasapiRenderer.h:146-147`、`:22-23`、回收 `:932` |
| 重采样 | 唯一一处 fold-down，目标 = 设备 `GetMixFormat`（共享）或独占协商值 | `WasapiRenderer.cpp:184-237` |
| 共享端点缓冲 | `clamp(默认周期 × 3, 30 ms, 50 ms)`，事件回调 | `WasapiRenderer.cpp:601-604`、`:596` |
| 独占端点缓冲 | `defaultPeriod`，含 `BUFFER_SIZE_NOT_ALIGNED` 重算重试 | `WasapiRenderer.cpp:656`、`:665-675` |

## 2. 输出格式与精度：用户听到的东西在这一层被定死

55 号文档量过采样率换算精度（44.1/48/96/192 kHz 全 0.0000 s），但**从未断言落到哪一种 PCM**——本轮补上：

- **落点**：共享模式跟随设备 `GetMixFormat`，独占只接受 16/24/32 bit 的 PCM 或 IEEE_FLOAT（`WasapiRenderer.cpp:607-644`）。目标样本格式是 `AV_SAMPLE_FMT_FLT / S16 / S32`（`:201-202`）。
- **下混矩阵被钉死在代码里**：`rematrix_maxval = 0.95`、`center/surround_mix_level = 0.707107`、`lfe_mix_level = 0.0`（`WasapiRenderer.cpp:52-55`，写入点 `:223-226`）。**用户没有任何旋钮**可以改折叠电平或保留 LFE。
- **音量是软件增益，且分两种精度**：浮点输出走逐样本乘法（无损）；整型输出在 S16/S32 域做 `std::lround(sample * gain)`（`ApplyGain` 定义 `WasapiRenderer.cpp:346`，整型量化点在 `:375` 与 `:386`）⇒ **音量只要不等于 1.0，就在整型域重新量化**，5 ms 淡入斜坡同样落在整型域（`StartupFadeInMilliseconds = 5`，`:24`、`:353`）。
- **>100% 增益结构上不可能**：`SetVolume` 对入参是**拒绝**而非钳制——`if (!isfinite(volume) || volume < 0 || volume > 1) return InvalidArgument`（`PlayerSession.cpp:1965`）；且全程不使用 `IAudioEndpointVolume`，软件增益是唯一音量级。
- **无滤波图**：`AVFilterGraph` 在音频侧一次都没出现，唯一一处 `avfilter_graph_*`（`:4708-4733`）是视频的 zscale 色域图。⇒ 响度归一化、DRC、EQ、变速不变调在架构上**没有挂载点**，不是"没做界面"。

## 3. 时钟、延迟与事件

- **主时钟音频优先**：`ClockPosition()`（`PlayerSession.cpp:5508`）在 `!audioClockFinished_ && audioRenderer_ && (audioStream_ >= 0 || externalAudioStream_ >= 0)` 时取 `audioRenderer_->Position100ns()`（`:5514`），否则退化为 QPC 墙钟；视频在 `PumpVideoPresentation()`（`:3704`）按 `position <= now + 20'000`（2 ms 容差，`:3713`）对齐。
- **渲染器时钟**：`IAudioClock::GetPosition` 锚定 + QPC 插值，且**不越过已提交帧**（`WasapiRenderer.cpp:729-757`）。
- **延迟补偿**：`QueueAudioFrame`（`PlayerSession.cpp:4337`）按 owner 二选一——外挂轨加 `externalAudioOffset100ns_`（`:4346`），内嵌轨（含 IAMF 渲染出的帧）加 `audioDelay100ns_`；同一条 owner 判断保证**一帧不会被两个旋钮同时位移**。入口 `SetAudioDelay`（`:1389`，±10 分钟超界返回 `InvalidArgument`，落位后无条件 `DoSeek` 重走，因为已入队帧带着旧延迟算出的位置，`:1405`）与 `SetExternalAudioOffset`。**这两条都只有测试在调**（`FFF.Player.Tests/StreamSelectionRegression.vb:181-202`、`:251-266`），界面与快捷键都没有。
- **断点修复**：以 100 ms（`outputSampleRate_/10`）为界，正向缺口插静音、负向重叠丢帧；抖动地板取 `sr/1000`（≈1 ms），这是 54 号文档修掉"100% 误报"后留下的容差（`WasapiRenderer.cpp:263-290`）。
- **事件**：`FFF3FPEvent` 共 7 项，**没有音轨/流变化事件**（`Api/FFF.Player.Api.h:86-93`）。音频唯一会外播的是 `DeviceChanged`，载荷 `{"type":"audio","exclusive":bool}`（`PlayerSession.cpp:1960`）。音轨切换在界面上靠快照轮询差值刷新。

## 5. 界面上真能看到的音频读数

信息层（`UI/播放器信息图层呈现器.vb`）是音频诊断唯一成面的地方，五组行：

- **音频**：`编码 - WASAPI 模式`（`:269-274`）
- **声场**：IAMF 实际布局名（`:278`，取自 `快照.IAMF描述` → `播放模型.vb:305-309` 的 OAR sound system 表）——这一行的存在理由写得很清楚：容器里的编码名（opus/flac）不能说明真实声场
- **输入**：采样率 / 位深 / 声道数 / 实时码率（`:537-544`）
- **输出**：FLOAT PCM 或 PCM / 采样率 / 位深 / 声道数 / **缓冲区 ms** / **欠载次数**（`:546-561`）
- **音频告警**：只在异常时出现——不连续、抖动、补静音、丢重叠、**拒绝**（`:563-582`）

跨线程读数由 `PlayerAudioRuntimeState` 的原子量提供（`WasapiRenderer.h:24-83`），经 `UpdateAudioDiagnostics`（`PlayerSession.cpp:4445`）灌进快照，外部走 `FFF3FP_GetSnapshot` + `FFF3FP_GetAudioPeakLevels` 取。**这套读数在视频侧是对等的**（VSR/HDR/pixel-probe 都有回读口），音频侧只缺"写入者"，不缺管道。

## 6. 缺口清单（按补齐代价排序）

### 6.1 只缺一个调用点（改界面即可）
`SetAudioDelay`、`ClearExternalAudio`、`SetExternalAudioOffset`——内核、P/Invoke、会话封装三层全都是通的，快照还带着 `音频延迟`/`外部音轨偏移`/`正在使用外部音轨`（`播放模型.vb:222-226`），**但没有任何界面渲染它们**。这是本表里唯一"东西已经做好了，就差没人按下按钮"的一档。

### 6.2 缺一个内核导出
- **设备枚举**：`EnumAudioEndpoints` 在 3FP 全树 0 命中，同工程 Recorder 侧有现成参照（`3FR/Api/NativeApi.cpp:95-98`）。补一条"列表导出"即可让 `SetAudioEndpoint` 从死 API 变活。
- **峰值电平 8 声道封顶**：内部 `MaximumChannels = 24`（`WasapiRenderer.h:34`，注释明确写了"8 会把 IAMF 的电平表截成半张"是改内部的原因），而 ABI 结构仍是 `float values[8] / inputValues[8]`（`FFF.Player.Api.h:417-418`）⇒ 内部 widened、契约没 widen，**IAMF 12 声道在用户的峰值条上仍只有前 8 路**。改动要过 ABI 版本/偏移钉，属"动基线"一类。

### 6.3 缺一段实现
- **码流直通（IEC61937）**：交接文档-2026-10-10 第八节 R2 已"设计定案暂缓"；本轮实测确认当前代码里 `passthrough/IEC61937/AC3/DTS/TRUEHD` 在 `3FP/` 下 0 命中（正控 `bitstream` 命中 20+ 处全在 Hdr 目录）。
- **双耳渲染接线**：`BedBinauralRenderer` 编译得进、无人调用；两棵树的 `iamfBinaural`/`audioBinaural` **无任何写入点**（正控：同结构体的 `iamfSoundSystem` 在 `PlayerSession.cpp:3335` 有写入）。成员 `iamfSoundSystem_`（`PlayerSession.h:369`）则从未被读写，调用方也就无从选择声场系统——IAMF 恒走 F/7.1.4。
- **任何音频滤镜**：见 §2，架构上要先挂 filter graph 才谈得上响度归一化/EQ。

### 6.4 一条 lane 的头条是错的（记录以免被复述）
lane 写的是"`SetVolume` 把入参 **clamp** 到 0..1"；实读是**超界直接返回 `InvalidArgument`**（`PlayerSession.cpp:1965`）。两者对用户是不同结果：钳制意味着"设 150% 会静默变 100%"，拒绝意味着"设 150% 会报错、界面得自己知道"。本报告所有条目按实读写。

### 6.5 一个恒为 0 的读数挂着带牙的界面
`audioRejectedFrames` 只在 `Enqueue` 返回 `BufferTooSmall` 时自增（`PlayerSession.cpp:4361`），而 `PlayerWasapiRenderer::Enqueue` 的全部返回路径是 `Success / InvalidArgument / InvalidState / FfmpegFailure / NotSupported / DeviceFailure / NativeFailure`（`WasapiRenderer.cpp` 全文 22 处 `return FFFResult::` 中无 `BufferTooSmall`）⇒ 该计数器恒 0，信息层那行"拒绝 N"永不出现。**不能据此说队列不会溢出**——真正的背压在上游 512 包 / 8 MiB 的压缩态队列，PCM 队列本身无上限（§1）。

## 10. 追加（同日第二轮）：收纳侵权内容的 DLL 里有没有空间音频？剩下的不侵权部分在不在 3FP 内？

### 10.1 判词

1. **那个 DLL 里没有一寸空间音频。** 它是纯计算的色彩载荷件，链的只有 `KERNEL32 + bcrypt + CRYPT32`——没有 `avcodec/avformat/swresample`，也没有 `iamf/oar/obr`。

## 11. 施工记录：把杜比/DTS 床的双耳渲染搬进外部模块（2026-10-18 第三轮）

用户口径：**有侵权风险的实现进 DLL；IAMF 族确认无风险，留本体；未解锁必须回退。** 按 §0 的实测，本体音频侧唯一一处自研受限实现就是 `BedBinauralRenderer`（它的存在理由正是 AC-3/E-AC-3/Atmos/TrueHD/DTS 床与多声道 PCM 的空间化）。AC-4/MPEG-H/DTS:X 在本体零实现，搬不动——那要先造解码器。

### 11.1 形状（一条决定）

过程中三条必须写下来的教训（都是探针自己的错，不是内核的）：

1. `plug.context` 传空 ⇒ 内核的守卫 `plug_.context != nullptr` 让 `supports()` **一次都不问**，床被默认判"未接受"、每帧计一次拒绝。⇒ 顺带暴露一条校验缺口：`SetAudioRenderPlug` 校验了 `size/version/supports/render/reset`，**没校验 `context`**；契约已写明除 `destroy` 外指针都得非空，所以应当在装载点直接 `InvalidArgument` 拒掉，而不是静默永久回退。待补。
2. 窗口不显示、不泵消息 ⇒ 音频首帧门控永不开，全部读数恒为 0，看起来像"接缝死了"。⇒ 判据必须泵消息。
3. `Pause` 会清掉"最后一帧来自 plug"的标志，`snapshot.audioBinaural` 与 `decodedAudioFrames` 由工作线程按节拍发布 ⇒ 暂停后再读，读数落后一整臂。⇒ 必须**在播放中**读。

### 10.10 补：§10.4"两棵树"到底是不是两份库（回源实测）

写 §10.4 时用的是"两棵树的 Release `link.command.1.tlog` 都点名这些库"。这句话的含义取决于**两棵树的库目录是不是同一份物理件**——而本轮 memory 里刚出现一条"`3fp/kernel/third_party` 是指向出货树的 junction"已被作废、改写成"实测是真实目录且为出货树严格子集"。两条读数不可能并存，故回源量。

**实测：它是 junction，且自 09-24 起就是。**

| 读数 | 值 |
|---|---|
| `GetFileAttributesW` | **0x410** = `FILE_ATTRIBUTE_DIRECTORY \| FILE_ATTRIBUTE_REPARSE_POINT` |
| reparse tag | **0xA0000003**（`IO_REPARSE_TAG_MOUNT_POINT`） |
| 目标 | `\??\c:\PLAN\3FCompare\third_party\fff_project\third_party` |
| junction 自身 ctime/mtime | **2026-09-24 04:17:16**（早于本轮所有改动，不存在"今天被换成 junction"） |
| 子目录 inode | 两侧 `ffmpeg`/`libiamf`/`vcpkg_installed` **三个 inode 全同**；目录清单 name→inode 映射逐字相同 |
| 六个库文件 | `iamf.lib` 1,085,456 / `oar.lib` 615,620 / `obr.lib` 15,394,204 / `obr_capi.lib` 160,966 / `pffft.lib` 75,080 / `fdk-aac.lib` 4,174,632——两侧**长度、sha256 前缀、inode 三项全同** |

**那条被作废的读数，数字是真的，配对错了。** 逐字复现：include **13 vs 19**、lib **15 vs 20**、bin **28 vs 38**，缺的正是 `libbluray/udfread/libxml2/iconv/charset` 整簇（`root-only = ∅` ⇒ 确为严格子集）。但这**不是** kernel↔出货树——`3fp/kernel/third_party` 与 `third_party/fff_project/third_party` 同 inode，两侧永远相等。这一对其实是：

- `C:\PLAN\3FCompare\third_party\vcpkg_installed`（**仓根那份**，ino 562949955095879）= 13 / 15 / 28，缺光盘簇；
- `C:\PLAN\3FCompare\third_party\fff_project\third_party\vcpkg_installed`（ino 6192449489304220）= 19 / 20 / 38，簇齐。

`3fp/kernel` 从不指向根那一份：`FFF.Native.vcxproj:59` 的依赖根是 `$(ProjectDir)..\third_party\`，经 junction 落到**齐簇**的那套。差集逐项实测（与 +6/+5/+10 的计数差自洽）：

- `include` 缺 6 项：`iconv.h`、`libbluray/`、`libcharset.h`、`libxml2/`、`localcharset.h`、`udfread/`
- `lib` 缺 5 项：`bluray.lib`、`charset.lib`、`iconv.lib`、`libxml2.lib`、`udfread.lib`
- `bin` 缺 10 项：`bluray-3`、`charset-1`、`iconv-2`、`libxml2`、`udfread-3` 各一对 `.dll`+`.pdb`

**陷阱机理（下轮照这条走）**：对 reparse 点路径**带尾反斜杠**枚举会穿透到目标，属性里的 `0x400` 就看不见，于是"看起来是真实目录"。判 junction 必须直接问该路径本身：`GetFileAttributesW` / `os.lstat(p).st_file_attributes & 0x400`，或 `fsutil reparsepoint query`（本机 `fsutil` 经 MSYS 传参报 123，改 `py` + `DeviceIoControl(FSCTL_GET_REPARSE_POINT=0x000900A8)`；`REPARSE_DATA_BUFFER` 的 tag 在偏移 0，不在 4）。探针已落盘：`tests/output/junction-probe-20261018/junction_probe.py`（只读）。

**对本节结论的影响**：§10.4 的判读**不变且更硬**——两棵树的链接清单是两份独立文件，但它们解析到**同一套物理库** ⇒ "两棵树都要治"等于**一次替换、两处记账**（`docs/94:187` 口径成立）；反过来，"两棵树都干净"**不能**算两次独立证据。仓根那套 vcpkg 缺光盘簇，别当内核依赖根用。
