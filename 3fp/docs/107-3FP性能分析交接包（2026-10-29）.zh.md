## 二、交付形态与启动性能核心数据

**最终交付形态（用户拍板）**：net10 + **JIT 默认（R2R 关，`-ReadyToRun` 余量开关保留）** + IAMF 强制携带 + 单文件框架依赖。发布脚本 `3fp/kernel/tools/发布3FP单文件.ps1` 已含全部开关（commit e010857/1cb205f 链）。

| 形态 | 窗口负载 | T1 出窗中位 | **T2 上屏中位** | 样本 | 判定 |
|---|---|---:|---:|---|---|
| bin 散装 IL（JIT） | ~68-70% | 1748.0 | **1893.0** | 10+10 | 有效（本轮基线） |
| **单文件 IL（JIT，最终形态）** | **91%** | 2770.7 | **2862.5**（2568–3353） | 9/9 | ⚠ 高负载上界参考 |
| 单文件 IL 首跑（含 10.6 MB 解压） | 91% | 5066 | **5190.2**（单轮） | 1 | ⚠ 上界参考 |
| 单文件 R2R（余量开关） | ~70% | 1588.0 | **1717.2** | 5/5 | 有效（较早窗口） |
| net11-rc2 bin（JIT） | 同窗 | 1811.4 | 1963.6 | 10+10 | U=43/100，与 net10 无显著差异 |

**阶段构成**（形态无关部分，docs/103/105 实测）：进程创建→运行时引导 ~16 ms → CLR+CoreLib ~20 ms → WinForms/DWrite ~115 ms → 托管 UI 栈/JIT ~434 ms → D3D/驱动（nvgpucomp ~704 ms）~242 ms → 托管收尾 ~363 ms → FFmpeg+内核接入 ~30 ms → 窗体收尾→T1 ~340-680 ms → **内核开图链 T1→T2 ~86-94 ms**（可归因：上传 2.0 + 软件转换 4.5 + presentWait 4.5；FFmpeg 首映射+解码+设备/交换链 ~75 ms 未细分）→ 上屏。

**一句话**：JIT 形态综合启动 ≈ **1.9 s 档**（bin 实测中位 1893）；**R2R 余量一键 −176 ms**（同窗实测 1717）；首跑另有 10.6 MB 原生件解压一次性成本；**net11-rc2 无收益**（且 R2R 被 crossgen2 CJK 崩溃阻断）。

| 认证 API | `git credential fill` 取令牌（不回显）+ `Invoke-RestMethod -Proxy http://127.0.0.1:10808` | git 通道挂起时的可靠旁路（删除/查询/关 PR 均成功） |

**陷阱速查（本轮全部实测）**：代理缓存 ls-remote 假象 · NETSDK1176 压缩仅自包含 · NETSDK1102 AOT 需 SelfContained · MSBUILD_EXE_PATH 毒化 dotnet 解析器（用 PATH 前置替代）· APPDATA 缺失→NuGet path1 null · DOTNET_ROOT 指向 vendored dotnet→宿主起不来 · `Sleep(1)` 15.6ms 分辨率虚高等待上限 · `$pid` 只读 · PS `-f` 除法需括号 · Mann-Whitney 满载下对 <100ms 效应无判定力 · 跨窗口对比不可归因。
