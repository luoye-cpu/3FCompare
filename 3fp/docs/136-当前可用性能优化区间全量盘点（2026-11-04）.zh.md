### #13 考古结论（2026-11-04，源＝11-02 日志 + PR #51 正文 + PR #49 页面）

- **撤回性质：产品决策，非技术失败。** 导火索是合并版 FailFast（0xC0000602@417ms），但 135 号已定根因＝LakeUI.dll 坏 R2R 产物，与 PR #49 无关；11-02 日志原文：「所以回退是产品决策，不是修 bug」。PR #51 正文与评论区均未给出产品层理由（只写撤了什么）——产品动机当时未留书面记录。
- **被连坐的三件与 VSP 功能面无关的独立改进**（重引入的真正标的）：①跳帧阶梯 `57252bd`+`2efdfd0`（PR 内实测 720p60 软解 8×：NONREF 后解码量 −40%，waste 0.66→0.31，压力回落即停）；②时钟读点原子化＋快照分段外推 `b9538f1`（修真实跨线程读缺陷＋静音段外推瞬态误差）；③`.gitattributes` linguist-generated（工程项，无风险）。
- **重引入路径（PR #51 明示）**：须 revert 本次回退或 cherry-pick 原分支提交，**不能再次合并 `pr/vsp-player-*` 分支**。建议形态＝只 cherry-pick ①②③ 三件性能/工程提交，不带 VSP 功能面（倍速/双字幕/右键菜单/缩放档位等），产品决策留给上游；①②带 PR 内实测数据，重引入后仍需按 136 纪律在当前 main 复测。**待用户批准后才动手**。
