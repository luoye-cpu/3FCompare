# LakeUI 性能分析笔记（只读研究，master@b434f13）

## 结构普查
- 主库 VB.NET（LakeUI.vbproj），108 个 .vb / 约 23,000 行（不含 Designer），net10.0-windows10.0.17763.0，WinForms + PerMonitorV2
- LakeUI.Notifications = C# 独立包（WindowsAppSDK，不依赖本体）；Demo/Tests 辅助
- 控件：DX 控件 30+ 个全部实现 D3D_IGpuRenderable + V5_IGpuPresentationSource
- 依赖：仅 Vortice.Direct2D1/Direct3D11/DirectComposition 3.8.3（含 DirectWrite）
- 无 Svg/ExCSS 引用（那是 3FP 宿主自己的依赖）；无嵌入字体、无字体池
- 10/13 提交 1cea213 才是 UltraDetailListView 大改（+841 行 = 复选框模式功能）；10/22 b434f13 主改 Ultra2DChart（+395）
- 3FP Form1.Designer 使用约 400 个 LakeUI 控件实例（172 ModernMenuItem、73 ModernContextMenu、58 JustEmptyControl、52 ModernButton、37 ModernPanel、28+4 ThisIsYourWindow、4 ExcellentTrackBar、3 HtmlColorLabel）

## 关键发现
1. FFF.Player.vbproj:312-314 引用 LakeUI 用 HintPath 无条件指向 bin\Debug\$(LakeUITfm)\LakeUI.dll（Debug IL 2.4MB，2026/11/02）；bin\Release 有 2.0MB IL（2026/10/28）。R2R 5.4MB 是商业仓发布打包产物，3FP 开发环境实际加载 Debug IL。
2. 每 V5 控件 GPU 资源 = 2×ID2D1DeviceContext（D3D_ControlSurface.vb:224 离屏渲染 + D3D_HwndCompositionPresenter.vb:191 呈现）+ 2 份 w×h×4 表面（离屏 bitmap + IDCompositionSurface）+ Target/Visual。
3. 设备单例两套并存：D3D_DeviceManager（V5 主路径）与 D3D_DeviceGlobals（遗留，仅 D3D_BackdropSurfaceRenderer 引用 3 处），后者若触达会创建第二套 D3D11 设备。
4. 文本路径：DrawText 每次调用 D2D 内部临时 TextLayout；UltraDetailListView 截断文本二分测量（UltraDetailListView.vb:1142-1165，每次 measure 新建 TextLayout D3D_TextInterop.vb:47）；measure 缓存满时全清（UltraDetailListView.vb:1187）。
5. 滚动 = 行步进（_scrollOffset，HandleWheel 3 行/格），无像素平滑；滚轮触发整控件 dirty（请求GPU渲染() 无参版）。
6. 初始化均懒触发：设备 EnsureCreated 首个控件渲染时；Shared Sub New 均轻量；GlobalOptions 全静态默认（SSAA=OFF、ClearType、Brush 256、TextFormat 128）；无主题解析。PrecisionTimer 进程级 timeBeginPeriod 引用计数。
7. 动画 = 共享调度器（CurrentScheduler.Register），非每控件 Timer；hover 动画带脏区 provider。
8. 缓存体系完整：Brush/Geometry/Texture/Image/TextFormat/Measure 多级 LRU；脏区合并 + 外到内批次 + 深度排序 + ContinuationTimer 让输入优先。
9. 3FP 未使用 Ultra2DChart/CpuMonitor/RamMonitor/MarkDownViewer。
