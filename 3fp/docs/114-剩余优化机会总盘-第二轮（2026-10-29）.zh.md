## 三、合成账（三桶，**不可相加**）

- **T0→T1 桶**：O3-A（−70~90，已落地）+ O4（−60~95）+ M2（−20~30）+ O3-B（−30~40）+ A2 R2R（−80~130）⇒ 区间重叠严重，端到端只认安静窗实测。
- **T1→T2 桶**：89 ms → **25–40 ms**（P1 −45~55 + P2 −4 + P3 −2~5；O3-A 的免重映射份额 −15~35 已在此桶内）。
- **首跑桶**：M3 −20~24、解压 ≈602 ms（每版本一次）。

参考锚点：T2 中位基线 1893 ms（bin JIT，68–70% 负载窗）。若 A 组全落 + P1 + M2，粗算 T2 进入 **~1600 ms 档**；再叠 A2 R2R 或全量 R2R 分别再 −80~130 / −176。

## 四、建议落地顺序

1. **O4-A**（确定性最高、顺手 −1.05 MB）——需设计侧一句确认；
2. **P2 + P3 + P4/P5**（内核小刀，低风险，一次改一起验）；
3. **P1**（需像素级验收 + 安静窗基线，收益最大的一笔宿主改动）；
4. **M2 + O3-B**（共用 Startup 后台骨架，一次做两个）；
5. **R2R 决策**（三臂交替 ≥20 轮，安静窗）；
6. **O2** 按稳态项评估（拖拽/动画/滚动），不占启动账。

## 五、测量缺口（下一轮必须先补）

1. **`-TraceDir` 当前不产出任何计时**（`FFFPROF`/`FPT_OPEN_TRACE` 在树内 0 命中，插桩在 docs/17 末尾已移除）——想分段验收必须恢复插桩（宿主 Load 分段 + 内核 open 链分段）。
2. **ETL 只有 `PROC_THREAD+LOADER`，无 JIT 事件**——托管 gap 的 JIT 份额只能推断（首轮/二轮 50× 比 + 负载拉伸旁证）。
3. **安静窗仍未到**（avg5 ~60%）：O3-A、A2/全量 R2R、P1 的收益都还只是区间值。
