**改动前（HEAD `:4010`）**：

`layout == 3` ⇒ 落末尾 `else` ⇒ **`DXGI_FORMAT_R16_FLOAT`（单通道）**。✅ **与 vivid-impl 描述逐字一致。**

// :4021

// :4022

⇒ layout 3 ⇒ `planeCount = 1` ⇒ **plane 0 确实进入循环体**，`format` 确实被使用。✅

**该处是否会被"零 pass"短路？** 复核确认**会**，但**不适用于 JXR**：
- `EnsurePlaneScaleChain` 的纹理只在 `while (width > targetWidth || height > targetHeight)` 循环体内创建；

- **但 JXR 场景有真实缩放**：`CalculateVideoDestination(3840, 2160, 960, 540)` ⇒ `{width:960, height:540}`（`limitToNativeSize` 为假），源 3840×2160 > 目标 960×540 ⇒ **循环体执行，纹理真的以 `format` 创建**。✅

**单通道纹理如何导致"恰好只剩 R"**：缩放着色器返回 `float4`（`return total/max(abs(weightTotal),...)`），写入 `R16_FLOAT` 目标 ⇒ **仅 R 被存储，G/B 丢弃**；随后 `ReadSource`/`ReadSourceLinear` 以 `InputLayout==0||==3` 直接 `SampleVideo(Source,uv).rgb` ⇒ **G/B 读作 0，R 保持正确**。✅ **完整闭合，与实测签名一致。**
