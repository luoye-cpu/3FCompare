## 七、已知坑（接手时别踩）

1. **三个优先级写者**：宿主启动 HIGH、内核基线采样、内核 Boost/Prioritize；"启动即播放"落在 `Shown+1500 ms` 前会让基线记成 HIGH（docs/124 §4.1、docs/148 §三A）。改 HIGH 之前先把这个时序想清楚。
2. **CPU Sets 是进程级软亲和**：内核播放期一设，宿主 UI/计时器/预取线程一起被约束；不要以为"只约束播放线程"。
3. **`FFF_PLACEMENT` 的负控语义**：`off/prefer/spill/boost` 是单向负控臂，`FFF_PLACEMENT_TRACE` 只是加日志；`FFF_STARTUP_PLACEMENT` 只认 `1/on/true`。
4. **预取默认 on**：`FFF3FP_PREFETCH` 默认 true、mode=2；静图侧车解码不设线程上限（docs/144 PF-1），这是"默认 CPU 策略"里最该先修的实际项。
5. **多 group 机型**：启动期放置直接 no-op（日志 `groups=N`），播放期省略；Threadripper 类机型不要当"支持"。
6. **别碰的判死项**：ServerGC/TieredPGO=0/NativeAOT/单文件压缩/硬亲和/启动期大件预取（默认关且有负收益实测）。
7. 改动 API 头后必须重编 34 个探针（`python tools/build_probe.py` 或 `pwsh tools/rebuild_probes.ps1`）。
