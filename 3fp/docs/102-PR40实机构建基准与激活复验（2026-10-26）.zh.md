## 一、从零构建：能过，但要先补三件依赖（都是上游既有缺陷，非 PR40 引入）

`tools/构建3FP.ps1 -Configuration Release -SkipDependencyPreparation` 第一次在干净 worktree 上
**失败两次**，原因都在依赖准备，且 `git log 922e4b7..034507e -- tools/准备FFmpeg.ps1` 为空 ⇒
PR40 没动过这些脚本：

1. `libavutil/avconfig.h` 缺失（C1083×8 文件）。`准备FFmpeg.ps1` 从 git 克隆拷 `*.h`，
   而 `avconfig.h` 是 configure 生成件，git 源里天然没有 ⇒ **该脚本在全新机器上产不出可编译的头文件集**。
2. `ass/ass.h` 缺失：`third_party/vcpkg_installed`（libass）不在 worktree 里，同样没被自动准备。
3. runtime FFmpeg 变体：脚本默认 URL 下载 lgpl-shared，而全项目实测基线是 nonfree-shared
   （脚本自己的警示注释也这么说）。pr38-wt 里已是 lgpl 件（avcodec-63.dll sha1 `6b0d6c1e`）。

修法（环境修复，未改任何代码）：用出货树 `third_party/fff_project` 的
`third_party/ffmpeg/{include,lib}`、`vcpkg_installed`、`libiamf`、`runtime/*.dll` 覆盖两个 worktree，
覆盖后 `avconfig.h` 在位、`avcodec-63.dll` sha1 对齐出货树 `28358cd8`。

此后门禁**全绿**（exit 0）：原生 + 宿主 + 测件 0 错误、图片缩放几何回归通过、
RTX 两行判词 **306/0**。新内核指纹：PR `b3ea7067`（5,619,200 B）。
（此前的"门禁绿"建立在一份现已不存在的 third_party 状态上——本轮是真正从零重建。）

结论（细则见当轮对话）：**VSR 的 GPU 增量随源分辨率走**（+18.3/+23.7/+31.5pp @540/720/1080p，
关臂三档平在 ~39% ⇒ 增量即 VSR 自身成本；网络跑在源帧上），1080p 源是本机（4060 Laptop）
的临界档——九臂里唯一丢帧的臂，峰值摸 99%；**TrueHDR 在 4K 上 GPU 增量 ≈0**（58.5 vs 58.6，
它把缩放链的 2 pass/帧 卸给视频处理器，净零），代价只有 +185MB 显存；
**重建成本与分辨率无关**（0.37–0.66ms 跨 540p→4K，纯驱动对象初始化）；
VSR 开启即占 187–833MB 驱动侧显存（远超 ~11.5MB 可见中间面）。
今晨 4K HDR 臂 44fps 与本轮 60.05 的会话间漂移未解释（rebuilds=1 恒定，非 pass 瓶颈）。
指标边界：`bltSubmitAvgMs` 是 CPU 提交耗时非 GPU 执行；`utilization.gpu` 是粗粒度指标，
A/B 增量有意义、绝对值参考即可；60Hz 面板上限掩盖头顶空间；4K 源的 VSR 本屏不可测
（需 >4K 客户区）。
