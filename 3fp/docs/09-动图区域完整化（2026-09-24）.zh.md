## 1. 需求与现状

### 1.1 设计目标
- **G4**：动画图（GIF/APNG/WebP动/JXL动）默认**停首帧**、可手动播放。
- **STATUS.md:183** 待办：M2 4.2「外壳接 `GetImageInfo`：EXIF 自动旋转、动画图默认停首帧（`loop=0`）」。

### 1.2 实测现状（修复前）
- **A 类（GIF/APNG/WebP动）**：`PumpVideoPresentation` 第 2462 行
  `if (playbackPreroll_ && !primesVisibleVideo) return false;` 会在
  `playbackPreroll_=true` 时挡住首帧呈现；而 `ArmAudioUntilVideoFrame` 又把
  `playbackPreroll_ = videoStream_ >= 0 && !staticImage_` ⇒ 动图打开后**preroll 永远不完成
  ⇒ 一帧都不出**。设计 G4 直接被违反。
- **B 类（`mov` 承载的动画 AVIF/HEIC）**：ffprobe 报 **2 路流**——
  流 0 首帧静图（`nb_frames=1`）+ 流 1 动画轨（`nb_frames=10`）。
  内核 `FindDefaultOrFirstStream` 选了流 0 ⇒ **`nb_frames=1` ⇒ `staticImage_=true`
  ⇒ 整个动画退化成一张静图**，连同 `duration100ns`/`ANIMATED` 标志都错。
- **`GetImageInfo`**：外壳**完全没接**（`STATUS.md:183` 待办）。
- **样张**：原只有 WebP/GIF/APNG 三个，**缺动画 AVIF**。

## 4. 已知折中与遗留

### 4.1 不可避免的「首帧前闪一帧」（用户实际感知）

宿主必须在 `打开媒体` 时调用 `Play`，否则**打开时不呈现任何帧**（静图与动图都会全黑——宿主有自己的 swapchain 时序）。
所以「默认停首帧」的实现路径是**先 Play 让帧呈现，再立即 `暂停+跳转(0)`** ⇒ 用户理论上能感知到"开图瞬间闪一帧"。
实证：从打开到 14 s 的两次抓屏**像素完全相同**（判据：未在播放），且亮像素稳定在 79.4% ⇒ **闪一帧的窗口 < 1 个动画帧**（10 fps 时为 100 ms 不到），但**首帧会停留**。

**进一步收紧**（彻底无闪）需要内核侧配合：当 `animatedImage_` 时让 `Open` 不返回 `Ready`、而是返回 `Paused` 状态；这是 M2 4.3 的待办。

### 4.2 动画 HEIC / 动画 JXL 仍无样张

本机 FFmpeg 构建**无 `heif` muxer**（且所有 `.heic` 实测皆单帧）、**无 `jxl` muxer**（`libjxl_anim` 解码器存在但任何容器都不接受）。代码路径**覆盖**了 B 类（`FindAnimatedImageStream` 对 `mov` 家族通用），但**没有真实素材**可走完整 E2E。Hepburn 状态属"代码就绪、待真实素材"。

### 4.3 仍欠一个动图专项宿主回归测试

`--static-image-open-regression` 是为静图写的，断言里写着"静态图片…用 CPU 解码"。动图该有的 `--animated-image-open-regression`（断言：打开后首帧已呈现、`ANIMATED=1`、未在播放）**未加**——这是把 G4 钉死的最好办法，建议作为本轮工作的最后一步。
