# 单文件 exe 体积：19.8 MB → ~7 MB 交接文档

> 写于 2026-09-26。本会话已定位 19.8 MB 的成因并实测多条路径，余下「如何真正回到 ~7 MB」交由交接 agent 决策并落地。
> 状态：已停止构建/测试，仅做交接整理。

## 0. 目标
宿主 `FFF.Player` 单文件发布包当前 **19.8 MB**，用户要求回到「原发布包 7 MB」。

## 1. 当前 vbproj 改动（FFF.Player.vbproj，均已改、均未提交）
| 改动 | 内容 | 备注 |
|---|---|---|
| R2R 开启 | `<PublishReadyToRun>True</PublishReadyToRun>` | 本轮新增，**贡献 +7.2 MB** |
| SupportedOSPlatformVersion | 恢复为 `10.0.19041.0`（实验残留的 `7.0` 已回退） | |
| 6 个 clang 运行时 | 新增 `DevelopmentRuntime`（libc++/libomp/libunwind/libwinpthread-1/libshaderc_shared/libSPIRV-Tools-shared） | 仅进 OutDir，**不进发布项图** |
| `CopyProductNativeToPublish` | 仅拷 `ProductNative` + `LibassRuntime`；FFmpeg 刻意不随发布 | 用户要单独打包 FFmpeg/.NET |
| `DropUnusedWinRTProjection` + `DropUnusedWinRTProjectionBeforeBundle` | 从发布项剔除 `Microsoft.Windows.SDK.NET.dll`（25.99 MB WinRT 投影，宿主零使用） | **48→19.8 的开关**；⚠ 脆弱：依赖 SDK 内部目标 `_ComputeFilesToBundle`，且必须挂两处（ComputeFilesToPublish 之后该 DLL 会被重新加回） |

`git status`（3fp/kernel，嵌套 git 仓）显示 `FFF.Player.vbproj` 已 `M`，连同其余若干内核/测试文件改动——**全程零 git 写提交，等用户/交接 agent 决定提交口径**。

## 2. 体量归因（实测，散装发布目录逐项）
19.8 MB = 托管 **6.54** + 原生库 **5.94** + R2R 膨胀 **7.20**（IL 12.6 + R2R 7.2）

| 分类 | IL 体积 (MB) |
|---|---|
| LakeUI.dll（右键菜单，841 处引用，**不可去**） | 2.15 |
| FFF.Player.dll + exe | 1.22 |
| Vortice.* + SharpGen（DirectX 绑定，渲染用） | 1.60 |
| Svg.dll + ExCSS.dll（SVG 图标） | 1.00 |
| WinRT.Runtime.dll | 0.57 |
| FFF.Native.dll（播放器核心） | 0.73 |
| libass 全家桶（harfbuzz/freetype/fribidi/libpng16/brotli/bz2/z/ass-9） | 2.71 |
| 光盘库（libxml2/iconv-2/bluray-3/charset-1/udfread-3，来自 DiscRuntime.props） | 2.50 |

原生库合计 5.94 MB，托管合计 6.54 MB。

## 3. 实测体积阶梯（单文件，framework-dependent，`--self-contained false`）
| 配置 | 体积 | 说明 |
|---|---|---|
| R2R 开 + WinRT 在 | **45.8 MB** | 最初基线 |
| R2R 开 + WinRT 剔除 | **19.8 MB** | = 当前落地状态（含 DropUnusedWinRTProjection） |
| R2R 关 + WinRT 剔除 | **12.6 MB** | 全内置下限 |
| R2R 关 + WinRT 剔除 + 原生库不进包 | **6.68 MB** | ⚠ 该版只产出 exe，FFF.Native.dll 等未生成 → 运行缺核心文件，**不可用** |

⇒ 6.68 MB 与「原 7 MB」几乎吻合 ⇒ **原发布包 = 托管-only 单文件**，原生库不在包内。
`发布3FP单文件.ps1` 里的 `-p:IncludeNativeLibrariesForSelfExtract=true` 正是把原生库塞进包的来源（本机库在 `IncludeNativeLibrariesForSelfExtract != 'true'` 时被 SDK 排除出 bundle）。

## 4. 关键未决：如何真正回到 ~7 MB
- **方案 A（全内置，最小 12.6 MB）**：关 R2R → 12.6 MB。代价：启动速度回到 +74~141 ms（抵消本轮优化）。
- **方案 B（回到 ~7 MB，需外置原生库）**：关 R2R + 把 libass/光盘库从单文件包移出，放到 exe 同目录旁（或随包分发）。FFF.Native.dll 是否留包内待定。前提：与用户「不挂任何依赖」诉求冲突，**需用户拍板**。
- **方案 C（约 7.3 MB）**：关 R2R + 只外置 libass+光盘库（−5.21），FFF.Native 留包内。
- ⚠ 不要再试 `EnableCompressionInSingleFile`：NETSDK1176（仅 self-contained 支持）；而 self-contained 会把 .NET 运行时整包塞入（≈30 MB+），得不偿失。

## 6. 环境须知（跨 agent）
- .NET SDK 两个：**10.0.401（稳定）** 与 **11.0.100-rc.1（预览，当前默认）**。26 MB WinRT 投影是否进发布，预览 SDK 行为可能不同——交接 agent 应确认用哪个 SDK 发布，及其对 26 MB 投影的影响（也许切稳定 SDK 后连 `DropUnusedWinRTProjection` 都不需要）。
- `发布3FP单文件.ps1` 断言「输出目录只能有 FFF.Player.exe」，外置任何原生库会被它 `throw`。
- 用户最终口径：**单文件 exe + 不内置/不外挂 .NET + 不含 FFmpeg**，FFmpeg 与 .NET 由用户单独打包。⇒ 其解压位置必须放 exe **同目录顶层**（枚举核心文件用 `SearchOption.TopDirectoryOnly`，不进 `ffmpeg-full/` 子目录），否则弹「播放器核心文件缺失」。
- ⚠ 路径必须用反斜杠；跑 `.ps1` 用 PowerShell 工具，跑 exe 用 Bash。

## 7. 建议交接 agent 的下一步
1. 决定体积目标（12.6 全内置 vs ~7 外置原生库），向用户确认「不挂依赖」是否允许 exe 旁放 9 个原生 DLL。

3. 若外置原生库：在 `发布3FP单文件.ps1` 去掉 `-p:IncludeNativeLibrariesForSelfExtract=true`，并加「把原生库旁置到发布目录」的步骤（注意脚本的「仅 exe」断言要相应放宽）。
4. 用 `run_host_tests.sh` 跑宿主全量回归，确认无新回归；用启动探针确认无「核心文件缺失」窗口。
