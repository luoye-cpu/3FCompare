### 4.1 实际实现的闸（比文档建议的多一步，且第二步是必需的）

文档原建议「只清内存」——**实测无效**。原因：`Form1_Load:79` 的 `设置.启动时加载设置()`
会把 `实例对象` **整体替换**成磁盘上读来的那份（`设置.vb:99 实例对象 = 读取`），
把 `Main` 开头的内存清除**整个丢弃**，随后第 80 行用的是重载后的对象。

落地实现为两步：
1. `Main` 开头调 `引导测试进程的文件关联(参数)`：内存里清一遍 9 个 `关联*`；
2. **把设置文件路径重定向到一份临时全 False 副本**（`设置.vb` 新增 `设置文件路径` 属性 +
   `Friend 重定向设置文件路径`），使任何时点的重新加载读到的都是"全未勾选"，
   从而 `启动后台同步` 在 `有已启用的类别` 处早退。

例外：`--file-association-live-toggle` / `--file-association-live-release` 是刻意的真机开关，放行。

### 4.4 本轮踩到的两个工具级陷阱（都会造出反向假结论）

1. **Git Bash 里 `reg delete … /f` 静默失败**：MSYS 把 `/f` 当路径转换，返回
   `ERROR: Invalid syntax.`；若同时用了 `>/dev/null 2>&1` 就把错误一起吃掉。
   ⇒ 所有"已清空"都是假的、所有"污染"都是那个**从未被删掉**的旧键。
   **清注册表一律走 PowerShell + 回读确认**（本目录新增 `tools/restore_associations_baseline.ps1`）。
2. **`Copy-Item -Force` 会保留源文件的修改时间**：变体文件比上次构建产物更旧 ⇒
   MSBuild 判定"源码未变更"⇒ **跳过编译、复用旧 DLL** ⇒ 两组 A/B 实际跑同一份二进制（假对照）。
   实测两组 dll mtime 完全相同。修法：改「读原版 → 字符串替换 → 重写」，写入时间必然是"现在"；
   并在跑前硬校验 `dll mtime > 源码 mtime`。

## 6. 产品级事实：勾选 ≠ 夺走双击

Windows 双击解析看 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\<ext>\UserChoice`，
它**优先于** `HKCU\Software\Classes\<ext>`，且 UserChoice 带系统哈希、第三方写不进去。本机实测（`tools/userchoice.ps1` + `tools/shell_open_probe.ps1`）：

| 扩展名 | UserChoice | ShellExecute（=双击）结果 |
|---|---|---|
| `.apng` | 无 | **FFF.Player 接手**，窗口标题 `probe_apng.apng` |
| `.png` | `AppXtn09g7patsyascvjgfyyx71s4parg8g3`（已失效商店 AppX） | 系统弹「**选取应用**」（`OpenWith.exe`），没走我们 |

⇒ 本功能的准确定位：**把 3FP 登记成可用的打开方式**（进「打开方式」列表与"默认应用"选择器），
不是静默夺走已有主人的扩展名。若用户要"勾选即夺走双击"，只能引导去系统"默认应用"里点一次——
**这是个产品决策，上游提 PR 前需要定调**（写进 PR 描述或拆成后续议题）。
