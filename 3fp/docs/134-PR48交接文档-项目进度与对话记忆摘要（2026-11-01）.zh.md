## 3. 本轮全部实测结论

### 3.1 已采纳（在 PR 里）

- **第 8 笔**：三台图层泵（字幕/弹幕/歌词）按"有没有内容源"在 16↔200 ms 间切调度间隔。三条设计约束写进了代码注释：①只调频率不改提交条件（不复制签名去重职责）；②间隔只由 tick 线程写（单写者，UI 线程写会让守卫字段与真实 Interval 脱钩、泵永久卡 5 Hz）；③弹幕泵恢复时清累积基准。
- **第 9 笔**：chrome（Attach，440.2 ms）延后到图片上屏之后。Shown 消息队列顺序：`①开图 → ②Attach → ③图层群构造`；空载（无启动文件）Shown 里同步 Attach 不变。`FFF_ATTACH_EARLY=1` 回退。已知代价：窗口先带标准边框，chrome 接管时几何微调一次（客户区 1303×874→1285×887，约 1.4%），验收确认 chrome 完整接管（顶部条带 mean 差 0.1）、接管后帧间 diff=0。

### 3.2 已判死（数据在案，勿重试）

| 尝试 | 批内 Δ | 结论 |
|---|---|---|
| Attach 再延到"媒体已打开"之后（二级延后） | −356.9 vs 一级 −352.5（差 4.4 ms） | 无额外收益：像素上屏由内核渲染线程完成，Attach 占 UI 只堵回调不堵像素 |
| 布局应用延后（PerformLayout+初始尺寸，插桩段 99.5 ms） | +12.3，p=0.646 | 无收益：段值大 ≠ 在关键路径上 |
| R2R Composite（`PublishReadyToRunComposite=true`） | +15.0，p=0.873 | 不如 A2；发布保持 `PublishReadyToRun=true` |
| ServerGC（`DOTNET_gcServer=1`） | +100.4 | 更慢 |
| TieredPGO=0 | −9.8，p=0.817 | 噪声 |
| 文件关联延后 | −21.4，p=0.163 | 不显著；UI 线程同步部分微秒级；早期"43.8 ms 是文件关联"是 JIT 插桩臂伪影 |
| 光盘 1 Hz / 解锁轮询延后 | 消融 Δ +2.7 / +5.2 | 无效应 |
| 预取（第 4 笔半边） | 关掉反而快 96.4，p=0.009 | 已默认关，`FFF_PREFETCH=1` 可开 |
| 移除 SWP_FRAMECHANGED | — | 成本转移到首次显示，固有 |

### 3.3 关键测量口径（读数必读）

- **只信批内配对 Δ**。同臂跨批漂移实测 69–430 ms；"T2 是否 <1000ms"取决于负载窗口（41% 负载时 858.7，56% 时 790–920）。
- 插桩臂（LTTrace，stderr `[LT] 名 毫秒`）用于**结构与占比**，绝对值比像素口径宽（含宿主收尾）。
- quiet_ab 的 `废` 轮 = 进程早退；出现大量废轮先怀疑崩溃而不是测量。
- 图层群延后打破了里程碑戳的时间顺序假设（25 戳打在 Shown 之后），**段差会出现负值**——用绝对时刻表（startup_breakdown.py）读，别用相邻段差。
