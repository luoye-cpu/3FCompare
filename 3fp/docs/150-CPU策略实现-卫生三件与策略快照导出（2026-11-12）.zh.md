## 二、P0-1 启动期 HIGH：默认关，改显式 opt-in

- **改法**（`FFF.Player/ApplicationEvents.vb:76-93`）：`启动期拉高优先级()` 在触碰 `Process` 之前做两道判断——
  - `:79` `FFF_NO_STARTUP_PRIORITY=1` ⇒ 直接返回（保留旧开关的兼容语义，且**优先**）；
  - `:81` `FFF_STARTUP_PRIORITY<>"1"` ⇒ 直接返回（**默认关**）；
  两道都过才走原逻辑（保存原始 class → 写 High → 置 `启动优先级已拉高=True`）。
- `Form1.vb:612-614` 只加注释、逻辑逐字未动：降回线程仍由 `启动优先级已拉高` 守卫，默认 False ⇒ **默认路径不出现该线程**。
- 保留不动：GPU 预热（`ApplicationEvents.vb:41-55`）、启动预取（`:108-146`）、启动 CPU 放置 3 s 兜底（`Form1.vb:631-640`）。
- **去掉的代价不是"少一个旋钮"**：默认不写进程 class 后，内核 `PlacementPolicy` 在首次 `SetState(Playing)` 采样的 `baselinePriorityClass_` 只可能是 NORMAL（或用户 `start /high` 的原始 class）⇒ docs/124 §4.1 的"基线记成 HIGH、Boost 释放后停留 HIGH"缺陷**默认不可能发生**（E2）。
- **A/B 负控**：`FFF_STARTUP_PRIORITY=1` 恢复旧行为（等价旧 exe 默认臂）；`FFF_NO_STARTUP_PRIORITY=1` 仍是 no-op 兼容。

## 三、P0-2 进程优先级写者规则（纪律，不改状态机）

规则正文（同时以注释锚点落在 `FFF.Native/3FP/Core/PlacementPolicy.cpp:666` 与 `:683`，指向本文）：

1. **宿主不在播放链路里写进程 priority class**：P0-1 之后宿主默认零写入；唯一保留的显式路径是 `FFF_STARTUP_PRIORITY=1`，且只用于 A/B 负控/排障，不产品化。
2. **进程 class 只允许内核按测量升级，并按"播放开始时的基线"恢复**：`PlacementPolicy` 是唯一写者（`Boost()`/`Prioritize()`），基线在 `OnPlaybackStart` 采样、`Recover()`/`Release()` 回退；`overlayPriority_` 只由 `Release()` 清除。
3. **线程级优先级是另一层，不混算**：session worker 的 `THREAD_PRIORITY_HIGHEST` 只在 Boost/overlay 期间；LakeUI `PrecisionTimer` 调度线程固定 `AboveNormal` 属于单个计时线程，不等于"进程被拉高"。
4. **用户外部 `start /high` 不受影响**：宿主降回语义只作用于自己拉高的窗口（原始值恢复，不是常量 NORMAL）。

## 六、P3-12 CPU 策略快照（追加导出）

### 6.1 ABI（已冻结）

在**已存在**的 `FFF.Native/3FP/Api/FFF.Player.CpuPlacement.h` 尾部追加（`:52-116`）：`#define FFF3FP_CPUPLACEMENT_SNAPSHOT_VERSION 1u`、`FFF3FP_CPUPLACEMENT_UNKNOWN 0xFFFFFFFFu`、`enum class FFF3FPCpuPlacementDomain/Tier/Flags`；`struct FFF3FPCpuPlacementSnapshot` = **22 × 4 B = 88 B** 纯 POD + `static_assert(sizeof==88)`（`:108`）；导出：

```c
FFF3FP_API FFFResult FFF3FP_GetCpuPlacementSnapshot(FFF3FPHandle player,
    FFF3FPCpuPlacementSnapshot* snapshot) noexcept;   // :116
```

字段（顺序即 ABI）：`size/version` → `domain/tier/flags` → `processPriorityClass/baselinePriorityClass` → `tier0SetCount/tier1SetCount/processDefaultSetCount` → `preferredDomainThreads/processorGroupCount` → `workerThreadId/workerThreadPriority/workerSelectedSetCount` → `presentThreadId/presentSelectedSetCount` → `decoderThreadCount` → `reserved[4]`。

- **零契约动作**：`FFF.Player.Api.h` / 快照结构 / `PlayerApiVersion=20` / `SnapshotVersion=23` 全部未动（`git diff` 对这三个文件为空）。该头**不在**模块仓 contract 闭包内——独立复核：`Refresh-Contract.ps1` 的入口闭包只有 `3FP/Api/FFF.Player.Api.h → 3FR/Api/FFF.Native.Api.h + 3FP/Api/FFF.Player.AudioPassthrough.h`（3 文件），`CpuPlacement.h` 不在其中 ⇒ 不需要 `Refresh-Contract` / `Verify-Contract` 重签。
- 三道门：`player`/`snapshot` 空、`version != 1`、`size < sizeof` ⇒ `InvalidArgument`（`PlayerApi.cpp:663-675`）；成功时 session 端 `memset` 零填充后整体覆盖（含 `size/version`、`reserved`）。

### 6.2 语义

- `domain/tier/flags` 是策略**认为已生效**的状态；`processPriorityClass`/`workerThreadPriority`/`*SelectedSetCount` 是**此刻向 OS 实测**的值。线程已退出/查询失败填 `UNKNOWN`，不猜 0。
- `presentThreadId` = 渲染器 `TimedTextThread` 的线程 id（`VideoRenderer.cpp:5977` 入口发布、`StopTimedTextThread` 清 0）；`presentSelectedSetCount` 回答 **A1「钉的是 worker 不是 presenter」**（presenter 未被 `SetThreadSelectedCpuSets` 选中时应为 0）。
- `tier0SetCount/preferredDomainThreads/processDefaultSetCount` 回答 **「tier0 是否被 `EnsurePreferredCapacity` 扩容」**。
- `decoderThreadCount` 取 `decoderThreads_`（worker-owned，诊断性无锁读取，可能滞后一档；不影响播放）。
- `flags`：`AVAILABLE/DISABLED/FORCED/CLASS_RAISED/OVERLAY_PRIORITY/PRIORITY_SAVED/STARTUP_APPLIED/WORKER_PINNED`。
- **快照是 advisory 的**：不取 session 锁、各字段非同刻采样，仅用于 A/B 自证，不能当控制路径。

### 6.3 内核侧落点

`PlacementPolicy`：`TraceEnabled()`（`:111`）、`FillDiagnosticSnapshot()`（`:862`）、`QueryThreadSelectedCpuSetCount()`（`:845`，`OpenThread(THREAD_QUERY_LIMITED_INFORMATION)`+`GetThreadSelectedCpuSets`）、`processDefaultSetCount_`（在 `SetProcessDefaultCpuSets` 成功/清除处维护）、startup 历史静态量（`:76-83`，Begin 成功=1/拒绝=2，End 不清）。`PlayerSession::GetCpuPlacementSnapshot`（`:3260`）补 `decoderThreadCount`、`presentThreadId`、`presentSelectedSetCount`。

### 6.4 追踪行（仅诊断，默认零行为）

`FFF_PLACEMENT_TRACE` 在策略构造期开启时，`SetState(Playing)` 在 `OnPlaybackStart` 之后发一行（`PlayerSession.cpp:9441-9470`）：

