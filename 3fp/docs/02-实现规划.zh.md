## 0. 一页总览

| 项 | 内容 |
|---|---|
| 目标 | 把 3FP 已有的"能打开图片"升级为"能顺畅看图"：导航、缩放平移、适应窗口、目录浏览、幻灯片 |
| 分期 | M0 准备 → M1 能看图 → M2 看得准 → M3（独立）广色域 |
| 工作量 | 约 8–11 周（1 人）；内核/宿主分两人并行可压到 5–6 周 |
| 内核新增导出 | 3 个（`GetImageInfo` / `OpenWithOptions` / `SetViewRotation`）+ 快照/配置字段扩展 |
| ABI | `PlayerApiVersion 15 → 16`、快照 `8 → 9`，**一次性**递增，内核与外壳同 PR |
| 最关键的一件事 | **K3**：把静态图判定从"猜 demuxer 名"改成"`nb_frames <= 1`" —— 它是图片体验的地基 |

**三个必须记住的前提**

1. 3FP **已经能解码并显示图片**（`staticImage_` 全链路），本规划不重写解码，只补语义与交互。
2. 格式覆盖取决于**用户自己的 FFmpeg DLL**（3FP 允许换核心）⇒ 一切能力必须运行时探测，禁止硬编码格式清单。
3. 广色域 / GainMap **不在本规划范围内**（见可行性报告 §4.6.2 / §4.6.3），M3 只做广色域且须单独提案。

## 1. 目标与非目标

### 1.1 目标（M1 + M2）

| 编号 | 目标 | 验收要点 |
|---|---|---|
| G1 | 打开单张图片即可正常浏览，不报错、不跳 Ended、缩放平移可用 | 见 §6 M1 验收 |
| G2 | 目录内连续浏览（上一张/下一张/首张/末张 + 幻灯片） | 状态栏显示"第 n/N 张" |
| G3 | 适应窗口 / 1:1 / 百分比缩放，滚轮与拖拽符合看图直觉 | 与视频模式行为互不干扰 |
| G4 | 动画图（GIF/APNG/WebP 动/JXL 动）默认停首帧，可手动播放 | — |
| G5 | EXIF 方向正确、旋转可用、多页/多尺寸如实标注 | M2 |
| G6 | HDR 静态图（PQ/HLG AVIF·HEIC·JXL）走 HDR 链路 | M2（依赖 Q5 实测） |
| G7 | 不支持的格式给出**明确错误**而非崩溃或黑屏 | RAW / SVG 等 |
| G8 | 文件关联覆盖主流图片扩展名 | HKCU，无需管理员 |

### 1.2 非目标（明确不做）

- 缩略图网格图库 / 壁纸管理 / 批处理转码 / 编辑标注（属独立产品）
- **Display P3 等广色域（M3，独立提案）**
- **GainMap / Apple Gain Map / Ultra HDR（不建议做）**
- 引入第三方图像库（ImageSharp / Skia / LittleCMS）—— 与 3FP 轻量定位冲突

## 3. 格式支持矩阵（基于 2026-09-23 实测）

实测环境：本机 `runtime/` Shared FFmpeg `N-126168-gb16b5f2a01-20260815`，
298 个视频解码器 / 364 个解复用器（工具：`../../tools/探测FFmpeg能力.ps1`）。

| 格式 | 解码器 | 解复用器 | 当前是否被判为静态图 | 规划处理 |
|---|---|---|---|---|
| PNG | `png` | `image2` / `png_pipe` | ✅ 是 | 基础盘 |
| APNG | `apng` | `apng` | ❌ 否（`IsLoopAwareImageDemuxer` 含 apng） | 按动画处理，默认停首帧（G4） |
| JPEG | `mjpeg` | `image2` / `jpeg_pipe` | ✅ 是 | M2 处理 EXIF（G5） |
| WebP 静 | `webp` | `webp_pipe` | ✅ 是 | — |
| WebP 动 | `webp_anim` | `webp_anim` | ❌ 否 | 动画，默认停首帧 |
| GIF | `gif` | `gif` | ❌ 否 | 动画，默认停首帧 |
| TIFF | `tiff` | `image2` / `tiff_pipe` | ✅ 是 | **多页只解首页**，UI 如实标注 |
| BMP | `bmp` | `image2` / `bmp_pipe` | ✅ 是 | — |
| ICO | `bmp` | `ico`（判定名单含 `ico`） | ✅ 是 | **多尺寸只取首个**，如实标注 |
| JPEG XL 静 | `libjxl` | `jpegxl_pipe` | ✅ 是（`*_pipe`） | — |
| JPEG XL 动 | `libjxl_anim` | `jpegxl_anim` | ❌ 否 | 动画 |
| **AVIF** | `av1` | **`mov`** | ❌ **否**（K3 前） | K3 后归位；HDR 重点格式 |
| **HEIC** | `hevc` | **`mov`** | ❌ **否**（K3 前） | 同上 |
| EXR | `exr` | `image2` / `exr_pipe` | ✅ 是 | float HDR，需 K7 验证 |
| 相机 RAW | — | 无 `dcraw` | — | **明确报错**"当前 FFmpeg 不支持该格式" |
| SVG | —（只有 `svg_pipe`，缺解码器） | — | — | **明确报错** |

### 3.1 静态图判定现状（代码事实）

```322:329:third_party/fff_project/FFF.Native/3FP/Core/PlayerSession.cpp
bool IsStaticImageDemuxer(const AVInputFormat* inputFormat) noexcept {
    // FFmpeg's single-image demuxers are image2 or codec-specific *_pipe
    // demuxers. Animated image demuxers deliberately remain timed video.
    return name == "image2" || name == "image2pipe" || name == "ico" ||
        (name.size() > 5 && name.ends_with("_pipe"));
}
```
动画图由 `IsLoopAwareImageDemuxer()`（`:316-320`，`gif`/`apng`/`webp_anim`/`jpegxl_anim`）刻意排除，
且这类文件 `duration100ns` 被置 0（`PlayerSession.cpp:2081`）。

### 3.2 判定方式必须换（K3）

按名字枚举的问题是**永远追不上 ffmpeg**（AVIF/HEIC 就是活例子）。改为按内容判定：

```cpp
// 目标语义
staticImage_ = videoStream_ >= 0
            && stream->nb_frames <= 1          // 只有一帧 ⇒ 静态图
            && !IsLoopAwareImageDemuxer(iformat)  // 动画图即使 nb_frames=1 也当视频
            && !isTimedSource;                  // 有真实时间轴的仍是视频
```
兜底：`nb_frames == 0`（未知）时保留现有名字判定，避免回归。

**K3 一次解决三件事**：①序列图（`img%03d.png`）回归定时视频；②AVIF/HEIC 正确进入静态图语义；③未来新格式自动生效。

### 3.3 K3 之前的宿主补救判定

M1 交付时若 K3 尚未合并，宿主可用媒体信息做临时判定（**不是长期方案**）：

```
format ∈ {mov,mp4,m4a,3gp,3g2,mj2} 且 streams[].frames <= 1 且 无音频流 ⇒ 视为图片
```
该逻辑集中在 `播放器图片浏览控制器` 一处，K3 合并后删除。

## 4. 内核改动规格

### 4.1 版本与 ABI 策略（硬约束）

内核对版本**严格相等**校验（`PlayerApi.cpp:52-63`）：`version != PlayerApiVersion` 立刻返回 `InvalidArgument`；
快照同理（`PlayerSession.cpp:1703`，当前 8）。因此：

- 配置结构体加字段 ⇒ `PlayerApiVersion 15 → 16`
- 快照加字段 ⇒ 快照 `version 8 → 9`
- **必须一次性把本项目需要的字段加完**，避免反复递增
- 内核与外壳**同一 PR** 合并（PR #9 已有先例：单独合内核会让播放器打不开任何文件）
- 新 API 一律遵循"未实现返回 `NotSupported`"，保证新旧 DLL 混用可安全降级

### 4.2 行为修正（不改 ABI）

| # | 位置 | 改法 | 风险 |
|---|---|---|---|
| K1 | `PlayerSession.cpp:2910-2915` `FlushAtEnd` | `staticImage_` 时不置 `Ended`，置 `Paused`；仅在用户显式 `Play()` 时（图片模式即"播放动画"）才走结束流程 | 低 |
| K2 | `PlayerSession.cpp:2926-2954` `DoSeek` | 开头 `if (staticImage_) { PublishSnapshot(); return Success; }` | 低 |
| K3 | `PlayerSession.cpp:322-329` + `:2035-2036` | 按 §3.2 改为 `nb_frames <= 1` 判定，保留名字兜底 | **中**（影响所有图片类文件的语义，需全格式回归） |
| K4 | `PlayerSession.cpp:4320` 附近 / `VideoRenderer` | Open 后预检宽高，>16384（D3D11 纹理上限）返回明确错误而非渲染失败 | 低 |

### 4.3 新增 API（签名草案）

```c
// ---------- 1) 图像信息 ----------
typedef struct FFF3FPImageInfo {
    uint32_t size;
    uint32_t version;
    int32_t  frameCount;         // 总帧数；<0 = 未知
    int32_t  loopCount;          // 0 = 无限循环，-1 = 不循环，>0 = 次数
    uint32_t flags;              // 位标志，见下
    uint32_t rotationQuarterTurns; // 0/1/2/3（由 EXIF orientation 归一化）；0xFF = 未知
    int32_t  sourcePixelFormat;  // AVPixelFormat 原值
    uint32_t sourceBitDepth;
    uint32_t iccProfileSizeBytes;// 0 = 无
    uint32_t reserved[4];
} FFF3FPImageInfo;

// flags
#define FFF3FP_IMAGE_FLAG_STATIC       0x1  // 静态图（nb_frames<=1 且非动画）
#define FFF3FP_IMAGE_FLAG_ANIMATED     0x2
#define FFF3FP_IMAGE_FLAG_HAS_ALPHA    0x4
#define FFF3FP_IMAGE_FLAG_MULTI_FRAME  0x8  // 多页 TIFF / 多尺寸 ICO
#define FFF3FP_IMAGE_FLAG_HAS_ICC      0x10
#define FFF3FP_IMAGE_FLAG_HAS_ROTATION 0x20

FFFResult FFF3FP_GetImageInfo(FFF3FPPlayer player, FFF3FPImageInfo* info);
// 契约：info->size/version 必须填；未打开 / 无视频流 ⇒ InvalidState；
//       旧内核未实现 ⇒ NotSupported（外壳降级为"不显示图片扩展信息"）

// ---------- 2) 打开选项（动画循环 / 强制 demuxer）----------
FFFResult FFF3FP_OpenWithOptions(FFF3FPPlayer player,
                                 const char* pathUtf8,
                                 const char* optionsUtf8);
// optionsUtf8: "key=value" 以 ';' 分隔，传入 avformat_open_input 的 AVDictionary
//   图片模式典型用法："loop=0"（动画图只播一次，不无限循环）
//   未识别的键忽略；解析失败 ⇒ InvalidArgument
// 注：现有 OpenFormat（:1799-1824）把 protocol_whitelist/blacklist/ignore_loop 写死，
//     本 API 在其基础上叠加调用方选项，不动默认行为。

// ---------- 3) 旋转 ----------
FFFResult FFF3FP_SetViewRotation(FFF3FPPlayer player, uint32_t quarterTurns);
// quarterTurns ∈ {0,1,2,3}；其它 ⇒ InvalidArgument
// 与 SetViewTransform(zoom,panX,panY) 组合生效；旋转后需触发 Redraw
```

**为什么旋转单独开 API 而不是扩展 `SetViewTransform`**：扩展现有函数签名会破坏已有调用点（宿主 `设置360视角`、3FC 的 P/Invoke），
单独新增可让旧 DLL 返回 `NotSupported` 安全降级。

### 5.2 `UI/播放器画面控件.vb` 扩展

现有同构能力：`全景交互已启用`（属性）、`全景视角拖动` / `全景视场角滚轮`（事件，`:52-53`）。
图片模式照抄一套：

| 新增成员 | 说明 |
|---|---|
| `Friend Property 图片交互已启用 As Boolean` | 与 `全景交互已启用` 同构，决定鼠标事件归谁 |
| `Friend Event 图片缩放滚轮 As MouseEventHandler` | 滚轮（可带光标锚点） |
| `Friend Event 图片平移拖动 As …` | 左键拖拽位移量 |

⚠ 关键：现有 `MouseDown` 做"拖动标题栏移动窗口"（WM_NCLBUTTONDOWN + HTCAPTION）、`MouseWheel` 走音量 ——
必须在 `图片交互已启用 = True` 时短路这两条既有分支（这是最容易回归的地方，见 §9 R4）。

### 5.3 交互映射表

| 输入 | 视频模式（现状，保持不变） | **图片模式** |
|---|---|---|
| ← / → | ±5 秒跳转 | **上一张 / 下一张** |
| ↑ / ↓ | ±5 音量 | 保持音量（不改，避免与看图习惯冲突时无处调音量） |
| 滚轮 | 音量 | **缩放**（以光标为锚点） |

## 11. 与 3FCompare（3FC）的关系

3FC 是 3FP 内核的下游 fork。本规划的内核改动对 3FC 同样有价值：

- K1 / K2 直接消除 3FC 打开图片时的 seek 报错与立即 Ended
- K3 让 3FC 的"图片 vs 视频帧对比"成为可能
- 版本 15→16 需要同步更新 3FC 的 `src/3FCompare.Core/Backend/Interop/Fff3FpNative.cs`
  与 `Fff3FpEngine.ConfigVersion`（当前 15）

⚠ 顺序建议：**先在上游/归档分支落地内核改动 → 3FC 按 `PATCHES.md` 重移植并推进基线 SHA**，
不要在 3FC 侧先行 fork 一份不同实现（会造成后续无法合并）。
