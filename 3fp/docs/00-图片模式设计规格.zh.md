# 3FP「图片模式」设计规格

> 本文定义**图片模式**与**视频模式**的关系、隔离边界与实现约束。
> 是 `3fp/` 工作区实施 M1/M2 的直接依据。
>
> 上级文档：[`01-可行性分析`](01-可行性分析.zh.md)（能不能做）、[`02-实现规划`](02-实现规划.zh.md)（按什么顺序做）

---

## 1. 模式模型

3FP 现有形态是**视频模式**（含音频/字幕/弹幕/光盘）。本次新增**图片模式**，两者关系：

```
                 ┌──────────────── 3FP ────────────────┐
                 │                                     │
   输入 ────► 模式判定 ──┬──► 视频模式（现状，零改动）   │
                        │                              │
                        └──► 图片模式（新增）            │
                                │                      │
                                └─ 复用视频管线的：      │
                                   解码 / 渲染 / 色彩   │
                                   / 缩放 / 回读 / 恢复  │
                 └─────────────────────────────────────┘
```

| 维度 | 视频模式 | 图片模式 |
|---|---|---|
| 时间轴 | 有（position / duration / frameIndex） | **无**（单帧或动画序列） |
| 时钟 | avsync + 帧队列 + Present 节律 | 不需要 |
| 音频 | 有 | 无 |
| 字幕/弹幕 | 有 | 无 |
| 导航 | 播放/暂停/进度条 | **上一张/下一张/幻灯片** |
| 缩放平移 | 有（现状绑定在滚轮/360） | **有（重新绑定到看图习惯）** |
| 解码/渲染/色彩/HDR/回读 | 有 | **完全复用** |
| 设备丢失恢复 | 有（重解码） | **有（复用 `stillImageFrame_` 常驻帧）** |

**一句话**：图片模式 = 视频管线的**解码与呈现部分** + 一套**全新的交互与导航语义**。

## 2. 隔离原则：只加不改（铁律 2 的细化）

### 2.1 四条规则

| # | 规则 | 含义 |
|---|---|---|
| R-1 | **新增分支，不修改分支** | 图片逻辑一律以"新增 if 分支 / 新增函数 / 新增类"实现，不改动视频模式现有代码行 |
| R-2 | **门控不可达** | 图片分支必须由模式开关门控；开关关闭时该分支**不可达**（不是"执行了但没效果"） |
| R-3 | **状态显式化** | 模式状态必须是显式变量（`imageMode` / `图片模式已启用`），不允许靠"duration==0"之类隐式推断 |
| R-4 | **单行不共享** | 视频模式与图片模式**不共用**任何被修改过的函数；共享的必须是**未修改**的既有函数（解码、渲染、回读） |

### 2.2 为什么 R-3 很重要

靠 `duration == 0` 或 `frameCount <= 1` 隐式推断"这是图片"会在边界情况失控：
损坏的 MP4、未索引的 TS、时长为 0 的流，都会误判成图片并进入图片交互，
用户会发现"这个视频方向键不能快进了"。

⇒ 模式判定**只在打开完成时进行一次**，结果存进显式状态，后续所有分支读这个状态。

### 2.3 允许修改既有代码的**唯一例外**

内核中确属既有缺陷、且对视频同样有害的修正（K1/K2/K3/K4），
但必须满足：

1. 视频路径行为**不发生变化**（例如 K2 只在 `staticImage_ == true` 时短路，视频不受影响）
2. **单独成提交**，与图片模式新增代码分开，便于上游单独评估与回退

## 3. 模式判定与切换

### 3.1 判定时机

**只在 `媒体已打开`（`OpenCompleted`）时判定一次**，不在轮询中反复判断。

### 3.2 判定依据（优先级从高到低）

```
1. 用户手动指定（菜单"图片模式"可强制切换）          ← 最高优先级
2. 媒体信息 staticImage == true                     ← 内核判定（K3 后含 AVIF/HEIC）
3. 补救判定（K3 合并前）：
   format ∈ {mov,mp4,…} 且 streams[].frames <= 1 且 无音频流 ⇒ 图片
4. 否则 ⇒ 视频模式
```

⚠ 第 3 条是**临时措施**，K3 合并后立即删除（见 `02-实现规划` §3.3）。

### 3.3 切换时的状态重置

进入/退出图片模式都必须重置：

- 视图（zoom / pan / rotation）回到默认
- 幻灯片计时器停止
- 画面控件交互开关复位（`图片交互已启用 = False`）
- 音频状态：进入图片模式时若正在播放，先 `Stop()`（无音频源）

## 4. 复用边界（图片模式基于视频模式执行的部分）

### 4.1 直接复用（**不得修改**）

| 能力 | 内核位置 | 说明 |
|---|---|---|
| 解复用 / 解码 | `PlayerSession::DoOpen` / `DecodePacket` | `avformat_open_input` + avcodec |
| 静态帧解码与常驻 | `DecodeInitialStillImage()`（`:2130`）/ `stillImageFrame_` | 设备恢复靠它 |
| 渲染 | `PlayerVideoRenderer::Render`（`VideoRenderer.cpp:4178`） | D3D11 + 单一 shader |
| 色彩 / HDR | `HdrProcessor` + shader | 三挡色彩模式、mDCV/MaxCLL |
| 缩放 / 平移 | `FFF3FP_SetViewTransform` | 图片模式直接调用 |
| 像素回读 | `ReadVideoPixel` / `ReadVideoPixelRegion` | 探针、截图 |
| 重绘 | `FFF3FP_Redraw` | resize 后恢复画面 |
| 媒体信息 | `FFF3FP_GetMediaInfo` JSON | 含 `staticImage`、流内 `frames`/`pixelFormat`/色彩字段 |

### 4.2 需要新语义（图片模式专用）

| 能力 | 现状 | 图片模式要求 |
|---|---|---|
| Seek / 步进 | 时间轴语义 | **静默成功**（K2），不报错 |
| 播放结束 | `FlushAtEnd` 置 Ended | **不置 Ended**（K1） |
| 播放列表续播 | 靠 `PlaybackEnded` 触发 | **不触发** ⇒ 导航必须显式驱动 |
| 进度条 / 时间码 | 显示 | **隐藏** |
| 字幕 / 弹幕 | 有 | 天然为空，无需处理 |
| 旋转 | 无 | **新增**（K6 / `SetViewRotation`） |
| 帧数 / 动画 / EXIF / ICC | 无 | **新增**（K5 / `GetImageInfo`） |
| 动画循环 | `ignore_loop=0` 写死 | **新增**（`OpenWithOptions`，传 `loop=0`） |

### 4.3 明确不复用

- 音频渲染（WASAPI）：图片模式下不启动
- 定时文字（SRT/ASS/弹幕）：图片模式下不提交图层
- 光盘导航（`DiscNavigate`）：与图片模式互斥

## 5. 内核侧隔离设计

### 5.1 模式开关

`FFF3FPConfiguration` 新增 `imageMode`（version 15→16）：

| 值 | 含义 |
|---|---|
| 0 | 自动（现状行为，按 §3.2 判定） |
| 1 | **强制图片语义**（外壳已判定为图片时置 1） |

置 1 时内核：不启动音频、不启动定时文字、`FlushAtEnd` 不置 Ended、`DoSeek` 静默返回。
**视频模式（0）下所有既有行为不变** —— 这是 R-1/R-2 在内核侧的落点。

### 5.2 行为修正（K1–K4，视频路径行为不变）

| # | 位置 | 改法 |
|---|---|---|
| K1 | `PlayerSession.cpp:2910-2915` | `staticImage_` 时不置 `Ended`，置 `Paused` |
| K2 | `PlayerSession.cpp:2926-2954` | 开头 `if (staticImage_) { PublishSnapshot(); return Success; }` |
| K3 | `:322-329` + `:2035-2036` | 判定改为 `nb_frames <= 1`（保留名字兜底，防回归） |
| K4 | Open 后 | 宽高 > 16384 返回明确错误 |

### 5.3 新增 API

```c
FFFResult FFF3FP_GetImageInfo(FFF3FPPlayer player, FFF3FPImageInfo* info);
FFFResult FFF3FP_OpenWithOptions(FFF3FPPlayer player, const char* pathUtf8, const char* optionsUtf8);
FFFResult FFF3FP_SetViewRotation(FFF3FPPlayer player, uint32_t quarterTurns);
```

契约：**未实现一律返回 `NotSupported`**（`FFFResult` 已有该分支），
保证新外壳 + 旧内核 DLL 的组合能安全降级，而不是崩溃。

完整字段定义见 `02-实现规划.zh.md` §4.3。

## 6. 宿主侧隔离设计

### 6.1 新增控制器（照抄 360 控制器的结构）

`UI/播放器图片浏览控制器.vb`，结构对齐 `UI/播放器360视角控制器.vb`（:3-314）：

| 360 控制器（模板） | 图片控制器（新增） |
|---|---|
| `Implements IDisposable, IMessageFilter` | 同 |
| 构造 `(宿主窗口, 画面控件, 标题栏菜单, 应用视角, 操作提示)` | 构造 `(宿主窗口, 画面控件, 标题栏菜单, 应用视图, 操作提示, 打开媒体)` |
| `模式已启用 = 模式菜单项.Checked` | `图片模式已启用` 同构 |
| `媒体已打开(路径, 信息, 快照)` 内判定 | 同，判定逻辑见 §3.2 |
| `PreFilterMessage` 先判 `光盘交互已启用` | 先判 光盘 → 再判 360 → 再判 图片 |
| `Dispose` 里 `RemoveMessageFilter` + 逐个 `RemoveHandler` + 复位开关 | 同 |

### 6.2 画面控件门控（最易回归处）

`UI/播放器画面控件.vb` 现有：`全景交互已启用`、事件 `全景视角拖动` / `全景视场角滚轮`（:52-53）。
图片模式**新增一套平行成员**：

| 新增成员 | 说明 |
|---|---|
| `图片交互已启用 As Boolean` | 平行开关 |
| `图片缩放滚轮` 事件 | 带光标锚点 |
| `图片平移拖动` 事件 | 位移量 |

⚠ **必须短路的既有分支**（`图片交互已启用 = True` 时不可达）：

- `MouseWheel` → 音量
- `MouseDown` → `WM_NCLBUTTONDOWN + HTCAPTION`（拖标题栏移窗口）

这两条是视频模式的既有行为，**实现方式是"在前置 if 里 return"，而不是改原分支的条件表达式** ——
后者属于"修改分支"，违反 R-1。

### 6.3 输入优先级（门控顺序）

```
光盘交互已启用  ──► 360°模式已启用 ──► 图片模式已启用 ──► 视频默认行为
```

- 360° **静态全景图**是真实场景（`播放器360视角控制器.vb:86/90` 已支持），图片模式**必须让位**
- `Form1.vb:746 处理方向键快捷键` 已有 `Handled` 抢键机制（剪辑区间控制器在用），图片控制器复用它，
  **不改 Form1 键盘主流程**

### 6.4 交互映射（仅图片模式生效）

| 输入 | 视频模式（不变） | 图片模式 |

| ← / → | ±5 秒 | 上一张 / 下一张 |

| Esc | 退出全屏 | 退出图片模式 |
| R / Shift+R | — | 旋转 ∓90°（M2） |

| 元素 | 视频态 | 图片态 |

| 进度条 | 显示 | 隐藏 |

## 8. 验收：如何证明"视频模式零回归"

图片模式最容易出的事故是**改鼠标/键盘分支时误伤视频模式**。验收必须逐条手测：

| # | 用例 | 期望 |
|---|---|---|
| V1 | 视频模式下滚轮 | 仍是**音量**（不是缩放） |
| V2 | 视频模式下左键拖画面 | 仍是**移动窗口**（不是平移） |
| V3 | 视频模式下 ←/→ | 仍是 **±5 秒** |
| V4 | 视频模式双击 | 仍是**全屏** |
| V5 | 视频播完 | 仍按列表模式自动下一集 |
| V6 | 360° 视频 | 仍进 360 模式，拖拽/视场角正常 |
| V7 | 360° **静态全景图** | 进 360 模式，**不**被图片模式抢走 |
| V8 | 光盘 | 光盘交互优先 |
| V9 | 打开图片后再打开视频 | 状态机完整恢复，交互绑定还原 |
| V10 | 打开视频后再打开图片 | 正确进入图片态 |

## 9. 广色域：**保留**，不压缩（需求澄清，2026-09-24）

> ⚠ 本节修正此前的思路。早先考虑过"把 P3 转成 BT.709 再交给 shader"——
> 那是**压缩**：超出 709 的颜色会被裁掉，等于假装广色域不存在。
> 需求是**保留**广色域，让 P3 的颜色完整送到显示器。

### 9.1 为什么"保留"必须走 HDR / scRGB 输出

| 输出路径 | 能表达的色域 |
|---|---|
| SDR（BGRA8 / R10G10B10A2，sRGB 契约） | 仅 sRGB / Rec.709 —— **物理上放不下 P3** |
| HDR（`R16G16B16A16_FLOAT` + scRGB 线性） | **可以**：FP16 允许超出 [0,1] 与负值，scRGB 正是为此设计的中间交换空间 |

⇒ 广色域内容**必须**走 scRGB 输出；在 SDR 管道里无论怎么算都会被裁到 709。
这是 Windows 的现实约束，不是实现偷懒。

### 9.2 实现路径：以 BT.2020 作为无损载体

现有 shader 已经支持 BT.2020（`source2020` 标志），且输出 scRGB 时会做 2020 → 线性 709 primaries 的映射（含超范围值），这正是"保留广色域"的现成机制。

```
P3 源  ──(前置转换, 无损: P3 ⊂ BT.2020)──►  BT.2020 帧
                                              │
                                    标记 source2020 = 1
                                              ▼
                                    主 shader（现有能力）
                                              ▼
                              scRGB FP16 交换链（超范围值保留 2020 色域）
                                              ▼
                                   DWM 映射到显示器实际色域 ✅
```

要点：

- **转换方向是 P3 → BT.2020，不是 → BT.709**。色域只扩不缩，无信息损失
- 前置转换可用 `zscale`（zimg，实测在 avfilter 中可用）或新增一个 GPU pass
- BT.2020 源本来就走 `source2020 = 1`，无需改动
- swscale 目标矩阵写死 ITU709 对本方案**无影响**：图片是 RGB 数据，RGB→RGB 不经过 YUV 矩阵

### 9.3 必须改的一处门禁

`SetColorMode` 现在挡住了这条路：

```cpp
if (requestedMode_ == FFF3FPColorMode::MapToHdr &&
    !hdrProcessor_.IsHdrSource()) {
    actualMode_ = FFF3FPColorMode::MapToSdr;   // SDR 的 P3 图片被强制回 SDR
}
```

`IsHdrSource()` 只看 `color_trc`（PQ/HLG），不涉及 primaries ⇒
**一张 SDR 的 Display P3 照片永远进不了 scRGB 输出，色域必被裁**。

需要新增判定：广色域源（primaries 非 709/sRGB）也允许进入 scRGB 输出路径。

### 9.4 前提与限制（必须如实告知用户）

| 限制 | 说明 |
|---|---|
| 显示器需支持广色域 / HDR | 若显示器只有 sRGB，最终仍会被映射到 sRGB —— 这是硬件限制 |
| HDR 模式下的 SDR 白电平 | SDR 图片在 HDR 输出下依赖 paperWhite / SDR white level，需要正确设置，否则整体偏亮或偏暗 |
| 需要 primaries 检测 | `GetImageInfo` 目前**没有** primaries 字段，必须先补 |

## 10. 反模式（明确禁止）

| ❌ 禁止 | 原因 |
|---|---|
| 用 `duration == 0` / `frameCount <= 1` 隐式推断图片 | 违反 R-3；损坏视频会误判 |
| 改视频模式现有分支的条件表达式 | 违反 R-1 |
| 在 `third_party/fff_project/` 里做图片模式改动 | 违反铁律 1（污染 3FC 构建基线） |
| 扩展 `SetViewTransform` 签名加旋转 | 破坏已有调用点；应新增 `SetViewRotation`（D7） |
| 把补救判定（§3.2 第 3 条）写进长期设计 | K3 合并后必须删除 |
| 硬编码"支持的图片格式清单" | 3FP 允许换 ffmpeg 核心，格式覆盖随 DLL 变化，必须运行时探测 |
| 图片模式与广色域改造捆绑提交 | 广色域动全局管线，属 M3 独立提案（D3） |
