# AI 字幕包一键下载与删除（2026-11-12）

## 一、需求（用户裁定）

- 设置页 AI 字幕页按其它设置页规范重构（行容器 + HtmlColorLabel + 统一配色尺寸）。
- "我们是否可以给模型丢到 Hugging Face 上，给用户提供一个下载按钮？"→ 乙′ 方案全量实现：
  **模型直链官方 HF 仓（不转载）+ 上传载荷备好待传 + 下载/删除按钮全链路**。
- 后续追加："确保徽章显示真实情况"（输出徽章，见 docs/154 §七）与本文件无关。

## 二、现状盘点（实现前）

- 包契约（`Ai字幕包.vb` v3）：目录含 `ai-subtitles.json`（version/name/worker/python/model/runtime/window/step）+ `asr_worker.py` + 模型 + llama 运行时目录。引擎按 `*.gguf` 存在判定；llama 需主权重 + mmproj + `runtime/vulkan/llama-server.exe`。
- 模型：Qwen3-ASR-0.6B GGUF Q8_0（主权重 804,749,248 B + mmproj 214,392,480 B ≈ 973 MB）。
- 宿主**零下载代码**；分发=1.1 GB 手工 zip（dist/）。`asr_worker.py` 不随 exe 部署。
- 验证包在 `dist\AI字幕包-GPU+CPU`（本机在）——作为哈希基准与母仓载荷来源。

## 三、关键事实纠错（实现中实测）

- **cleanup-record 里的 HF 仓路径 `Qwen/Qwen3-ASR-0.6B-GGUF` 不存在**（HF 对不存在仓回 401）。
  官方 GGUF 实际在 **`ggml-org/Qwen3-ASR-0.6B-GGUF`**（llama.cpp 官方转换仓，公开不门禁），
  文件名/字节数与验证包逐字节一致（HEAD 实测 804,749,248 / 214,392,480）。
- dist 包内含**包内 Python**（`runtime/python/` 2,232 文件 / 92.9 MB，embeddable+numpy）——
  清单 `python` 指向它 ⇒ 全新用户连 PATH python 都不用装。下载器据此把"包内 Python"作为
  母仓载荷的一部分。
- llama.cpp 已转 nightly 发布制：`v0.9.0` release 无二进制，**b12110** nightly 才有
  `llama-b12110-bin-win-vulkan-x64.zip`（37,661,146 B，GitHub 提供 digest sha256 实核）。

## 四、实现（宿主 5 文件 + vbproj）

### 4.1 `AI字幕\Ai字幕包下载器.vb`（新，~260 行）

- **内置清单**（常量钉死 字节+SHA256，全部实测）：
  | 项 | 路径 | 字节 | SHA256 | 源（顺序回退） |
  |---|---|---|---|---|
  | 主权重 | model/Qwen3-ASR-0.6B-Q8_0.gguf | 804,749,248 | bca25981…1971 | hf.co/ggml-org → hf-mirror |
  | 投影 | model/mmproj-Qwen3-ASR-0.6B-Q8_0.gguf | 214,392,480 | 41a342b5…6603d | 同上 |
  | 运行时 | runtime.zip → 解压 runtime/vulkan | 37,661,146 | 9732a5e4…6874f | 母仓（配置后）→ llama.cpp b12110 |
  | 包内 Python | python.zip → 解压 runtime/python | 31,868,218 | 39d36922…e913 | 母仓（未配置则跳过） |
- **母仓地址**：`Public Const 母仓地址`（默认空）。上传 `dist\hf-upload\` 的两个 zip 后填
  `https://huggingface.co/<组织>/<仓库>/resolve/main` 即切换到验证版运行时+包内 Python；
  留空=运行时回落 llama.cpp b12110、Python 缺席（清单 `python` 留空 → 管道回落 PATH python）。
- **流程**：磁盘空间预检（需量+10%）→ 逐项：已合格（字节+哈希）跳过 → `.part` Range 断点续传
  （HF/GitHub 均支持）→ 字节核对 → SHA256 流式校验 → 落位 → zip 解压（overwrite）→
  复制随 exe 部署的 `ai-subtitles\asr_worker.py` 进包 → 手写 v3 清单（python 字段按
  包内 Python 是否就位决定）。
- 失败语义：单源失败试下一源；全源失败保留 `.part` 报"可续传"；上游字节数不符报
  "上游可能已更新，请更新清单"；哈希不符删临时文件报错。取消（CancellationToken）原样抛出，
  页面按取消显示。

### 4.3 构建链修复（本机环境特有，见 §六）

  `ICO.ico` 随 exe 部署（图标运行时加载）。

### 4.4 状态区富文本

- `刷新状态` 从 Label+ForeColor 改为 `HCL_状态` HtmlColorLabel + `<font>/<br>` 内联富文本；
  编码用轻量转义（`& < >`），**不用 WebUtility.HtmlEncode**——它把 `·` 编成 `&#183;` 而
  HtmlColorLabel 不解码实体，包名会显示成乱码（实测发现并修复）。

## 六、MSB3821 构建链插曲（本机环境，已绕过）

实现期间主构建被 `MSB3821`（resx Mark-of-the-Web）卡住：MSBuild 18.9+ 的 GenerateResource
对带 typed/mimetype 条目的 resx 做 MOTW 信任检查，而本机 IE 安全组件（CLSID
79eac9ee… InternetSecurityManager）被精简未注册，`MapUrlToZone` 对**本地路径**也回
受限区（zone≥3），第一方 resx 全被误判。逐层排查记录：
- 官方 opt-out 均不生效：注册表 `AllowProcessOfUntrustedResourceFiles`（VS 18.11 dll 内
  有该字符串、SDK 18.12 dll 无——两分支行为不同）与 `MSBUILDDISABLEFEATURESFROMVERSION`
  （对 zone 分支无效，只影响 typed 条目的 18.9 内容分支）。
- 解决：**tools\strip_resx_binary.ps1** 移除全部 15 个第一方 resx 的二进制/typed 条目
  （盘点确认仅 Form1 `$this.Icon` 被使用 → 运行时从 ICO.ico 加载；其余为模板死条目；
  TrayLocation/TrayHeight metadata 为设计器托盘记录，移除零运行时影响）。resx 只剩
  字符串与布局，不再进 MOTW 检查分支。中途尝试的旧版 ResGen 预编译方案废弃
  （NETFX 4.8 ResGen 用 BinaryFormatter 序列化 Icon，.NET 10 运行时禁用 → 启动崩溃）。
