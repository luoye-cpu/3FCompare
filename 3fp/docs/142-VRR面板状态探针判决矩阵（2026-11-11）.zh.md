## 1. E 段判据链：⓪统计自洽前置门 + 五重守门

判决链顺序：**⓪ 统计自洽 → ① 跌落 → ② 调用率 → ③ LFC 相关 → ④ 轮内稳定 → ⑤ 节奏**
（`vrr_state_probe.cpp:895-938`）。V1/T 两相取**并集**（任一相全过即算过）；
任一环不过只记 ambiguous，交 W/N 段裁决。

| # | 判据 | 阈值（代码为准） | 不过时的语义 |
|---|---|---|---|
| ⓪ | 统计自洽 | 块聚合率与中位率背离 ≤ **max(20%, 5Hz)**（`:903-905`，对 C1 与每个可用慢相各判一次） | 帧统计本身不可信（驱动模拟/采样毛刺，v3.1 内屏轮 623626Hz 教训），任何跌落都不归因面板 |
| ① | 原始跌落 | 慢相聚合率相对 C1 基线 **>25% 且 >10Hz**（`:911-912`） | 无跌落则 E 段无事可判（fixed 的必要面） |
| ② | 调用率守门 | 慢相聚合率 **> 1.15× Present() 调用率**（`:914-919`）；调用率不可得（≤0）时退回纯跌落判据 | 计数推进只跟 present = 驱动在模拟帧统计（DISPLAY5@60Hz 实测 19.2Hz≈调用率而 LFC 底应 48Hz） |
| ③ | LFC 相关 | 中位率须 **>0.9×基线以下**（贴基线不算跌）；中位率/内容率 = k，**k ∈ [1,8] 且 \|r−k\| ≤ 0.15**（`:920-927`） | 面板率不是内容率的近似整数倍 → 跌落不是 LFC 整倍跟随 |
| ④ | 轮内稳定 | C1↔C2、V1↔V2 中位漂移各 ≤ **max(5%, 2Hz)**（`:929-932`）；重复相**无数据即不过**（v3：无数据 ≠ 漂移） | 轮内切换（合成↔独立翻转/模式漂移）会现形 |
| ⑤ | 节奏自检 | 慢相 Present() 调用率与内容率偏差 ≤ **±30%**（`:933-934`）；调用率不可得时视为过（无参照可判） | 节奏走样说明慢相本身没按 24fps 打，跌落读数无意义 |

汇总（`:937-938`）：

```
empiricalVrr      = guardAny && lfc && cStable && vStable && pacingOk && calibSane && slowSane
empiricalAmbiguous = !empiricalVrr && (rawV || rawT)   // 有跌落但守门链未全过
```

E 段整体失能（C1 无样本或 V1/T 均无样本，样本<2）：不做任何跌落判断，
`VRR-NOTE: 聚合率不可算（… 样本<2）`，交 W/N 段裁决（`:964-971`）。

## 2. 判决矩阵（VRR-VERDICT 行，四态）

实现于 `vrr_state_probe.cpp:1025-1034`，**按顺序命中**（前面的态优先）：

| 判决 | 条件 | 语义 |
|---|---|---|
| `vrr-active` | E 段五重守门全过（跌落+调用率+LFC 相关+轮内稳定+节奏，⓪自洽前置门也过） | 面板**此刻真的在变刷新**，决定性 |
| `fixed` | E 有数据（C1 与 V1/T 至少一相可用）且**无跌落**（非 ambiguous）、非 vrr-active，且 NVAPI 窗口屏三位（possible/enabled/requested）全 0、W1 无声明 | 有 E 读数且零面板级证据 → 固定刷新屏 |
| `vrr-idle` | 任一面板级证据：NVAPI 窗口屏 possible/enabled/requested **任一**，或 W1 EDID 声明了 VRR（FreeSync / HDMI Forum VSDB） | 能力在、行为未实测确证。**声明本身就是能力证据，无需请求态陪伴**（v3 定稿）；请求态与系统开关只进 VRR-NOTE 行增强解释，不参与判决分支 |
| `inconclusive` | 零面板级证据：E 段没给出决定性读数（判别力受限/样本不足）且 W/N 均无声明可依 | 无从判决（exit 3） |

### 2.1 与基础设施失败的边界（2026-11-11 头注勘误）

**建窗 / D3D 设备 / 建链 / RTV / 目标模式获取失败走不到判决矩阵**：
`vrr_state_probe.cpp:762/777/844/848/853` 直接 `return 2`，不打印任何 VRR-VERDICT 行。
"链建不起来"不是 inconclusive 的一种——两者退出码不同（2=基础设施失败，3=不可判），
对账时不能把 exit 2 的轮次计入判决矩阵分母。

## 3. 退出码

| 码 | 含义 |
|---|---|
| 0 | 已判（`vrr-active` / `vrr-idle` / `fixed` 都算判，绿红都算判） |
| 2 | 基础设施失败（目标监视器模式获取失败、建窗失败、D3D11CreateDevice 失败、建链失败、RTV 失败）——**无判决行** |
| 3 | `inconclusive`（不可判） |

## 4. 机器行格式

- `VRR-VERDICT: <四态之一>`——判决本体，每轮恰好一行（能走到汇总的话）
- `VRR-DECLARED: <设备名> amdFreeSync=… hdmiForum=… baseRange=…-… windowsToggle=…`——W1 声明面取证
- `VRR-NOTE: …`——增强解释（E 失能原因、判别力受限、开关与驱动层独立等），不参与判决分支
