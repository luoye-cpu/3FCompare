## 3. 关键实证（实现期新发现，已回写常量表）

### 3.1 TrueHD 的四处关键规则（扩展检索 FFmpeg 源码后确认）

| # | 事实 | 来源 |
|---|---|---|
| 1 | **AU 长度 = 4 字节头的 12 位字段 × 2**，与 major sync 间距无关 | `libavcodec/mlp_parser.c`：`bytes_left = (hdr & 0xFFF) * 2` |
| 2 | AU 槽位固定在 **i×2560**（`TRUEHD_NOMINAL_AU_SPACING`），槽 0 从偏移 20 开始（紧随 20 字节 start code） | 实测 1200 AU 全匹配 |
| 3 | MAT 码位置 0 / 30708 / 61408，**码会覆盖槽位数据**，写游标须跨过码区 | `spdifenc.c` mat_codes[] |
| 4 | **末帧保留不刷**：1200 AU ÷ 24 = 50 帧，golden 只有 49 个 burst | 实测（FFmpeg 环形缓冲不排空） |

另：`accumulator_` 必须按 **61424 字节**（MAT 帧）而非 24576（E-AC-3）分配，否则 TrueHD 写入越界——这是本轮实际踩到的 bug。

### 3.2 其余三处（前一轮已记录）

1. **burst 头不参与字交换**：preamble 即 `72 F8 1F 4E`，只有 payload 区需要 16 位交换。
2. **DTS 帧长字段位置**：`sync(32)→normal_frame(1)→deficit(5)→crc(1)→npcmblocks(7)→frame_size(14)`；`npcmblocks=16` → 512 样本 → type 0x0B。
3. **DTS burst 周期**取 `blocks<<2`（512→2048B），帧短于周期时补零。

### 3.3 JOC/Atmos 检测

`ProbeEac3Joc()`：读 E-AC-3 帧尾 `addbsi` 块，取首字节 LSB = `flag_ec3_extension_type_a`（`ac3_parser.c` 语义）。实测非 Atmos 样本 313 帧 **0 误报**。命中时 `describe()` 优先给 `0000010a`（DDP_ATMOS），端点拒绝再退 `0000000a`。

### 3.4 DTS 的 `blocks` 语义（本轮从上游源码确认，此前理解有误）

拉取 `spdifenc.c:spdif_header_dts()` 后确认：

```
blocks = ((RB16(data+4) >> 2) & 0x7F) + 1     // PCM 块数：8/16/32/64
samples      = blocks << 5                     // 256/512/1024/2048
非 HD: type 由 samples(512/1024/2048) 决定；pkt_offset = blocks << 7
HD   : period = dtshd_rate * (blocks << 5) / sample_rate
```

**此前我把 `blocks` 当成样本数**，导致周期算错。实测样本 `npcmblocks=16` → `blocks=16` → `samples=512` → `pkt_offset=2048`（与 golden 完全吻合）。

### 3.5 DTS-HD 完整规则（FFmpeg + Kodi 双源一致，已用真实素材验证）

| 项 | 值 | 来源 |
|---|---|---|
| 数据头 | `01 00 00 00 00 00 00 00 FE FE` + u16 size | 两源一致 |
| subtype | period {512,1024,2048,4096,8192,16384} → {0..5} | 两源一致 |
| Pd | `FFALIGN(out_bytes + 8, 16) - 8` → `(Pd & 0xF) == 8` | FFmpeg `FFALIGN` / Kodi `((size+0x17)&~0x0f)-0x08` |
| burst | `period * 4` | 两源一致 |
| core 剥离 | `10 + 2 + frameSize + 8 > burst` 时只发 core | FFmpeg `dtshd_skip` |
| dtshd_rate | 768000（MA）/ 192000（HRA）；44.1 族 705600 | FFmpeg `ctx->dtshd_rate` |

**实测补充的两条关键规则**（源码没写死，靠真实样本才确定）：

1. **帧边界 = 本帧 core sync → 下一帧 core sync**，扩展子流（syncword `64 58 20 25`）包含在其中间。子流自身的长度字段跨 profile 不可靠，不能用来定界。流末帧无后继，取到缓冲区末尾。
2. **样本率 `sr_code` 跨 32 位字边界**：位于 4 字节后的第 34..38 位，必须用 64 位窗口读取；只读 32 位会得到错误值（实测错读成 12000 Hz，正确是 48000 Hz）。

另：`Pd` 必须**向上**对齐到 16 字节边界（`(x+8+15) & ~15`），写成向下对齐会差 16。
