## 3. 发现清单（Lead 复核后定级）

### P0-1（宿主/兼容性）四个新原生导出裸 DllImport，换旧内核必炸——违背仓库"可选导出动态解析/能力探测"既有惯例
- 位置：Interop/播放器原生接口.vb:1189-1200（静态 DllImport ×4：SetPlaybackRate/SetAudioEffects/SetScalingMode/Redraw）；Core/播放器会话.vb:553-564（封装无 try/catch，EntryPointNotFoundException 在 P/Invoke 层直接抛，`检查结果` 管不到）。
- 触发链（旧内核 DLL 下）：**每次打开媒体**都走 媒体已打开 处理器（VspFeatures.vb:114-122）→ 无条件 `设置均衡器`、`当前倍速<>1` 时 `设置播放倍速`、`应用视频缩放设置()`→`设置缩放算法`：
  - 直接打开路径：被外层 Catch → 每次开片弹"无法播放媒体"；
  - 原位重开路径：异常后 Return，**跳过自动加载字幕/弹幕/歌词**；
  - 会话事件路径：`会话_打开完成` 只 Catch `播放器异常`，异常逃逸进 UI SynchronizationContext.Post → 无 ThreadException 处理器 → 崩溃对话框；
  - 设置页改"视频缩放质量"下拉直调 `应用视频缩放设置()` → 未处理 UI 异常。
- 机理：本项目卖点是"用户自己换核心"。版本门是 `FFF3FP_GetApiVersion()==20`（播放器会话.vb:56-61），本次 additive 导出**不升版本号** → 旧内核能过启动门禁，功能触发才炸。仓库既有防护惯例全部被绕开：GetProcAddress 动态解析（播放器原生接口.vb:594-620）、能力探测（:856）、调用点 `Catch EntryPointNotFoundException`（播放器会话.vb:691-697）、catch-all 降级（画面菜单控制器 `尝试读取离屏帧`）。
- 修法（二选一，按既有模式）：(a) GetProcAddress 动态解析为委托，缺席→四封装静默降级（缩放回退旧两档、均衡器/倍速/Redraw 静默）；(b) 封装处 `Catch ex As EntryPointNotFoundException` 降级。并暴露"支持缩放算法选择"类能力开关供 UI 提示。

### P1-1（内核）TempoAudio 建图失败后遗留半成品 `tempoGraph_`，任何错误路径都不清理 → 音频渲染永久失败、整条音轨被禁用【Lead 已复核】
- 位置：PlayerSession.cpp:2261-2302。`tempoGraph_ = avfilter_graph_alloc()`（2264）先赋成员；错误 return 在 2265/2274/2283/2293/2299/2302，均不 free/不 ResetTempo。`ResetTempo` 全部调用点 = 定义 2254 + SetAudioEffects 重建 2348 + DoSeek 6614 + DoClose 6804；`DisableFailedInternalAudio`（6118-6130）只释放解码器/置 audioStream_=-1，不调 ResetTempo。
- 机理：一旦建图中途失败（不止 OOM：`av_channel_layout_describe` 返回值未检查（2269，layout[128] 溢出时 abuffer 参数是垃圾）、流格式中途变化等），下次调用 `if (!tempoGraph_)`（2261）不成立 → 跳过重建 → 每帧对未配置的图 `av_buffersrc_add_frame_flags`（2321）必败 → QueueAudioFrame 置 internalAudioFailurePending_（6067）→ DisableFailedInternalAudio **释放解码器、丢弃整条音轨**。同轨内 seek 之前音频彻底消失。
- 修法：建图全程用局部 `AVFilterGraph*`，全部成功后才提交给成员；或每个错误 return 前调 `ResetTempo(tempoOrigin_)`。顺带检查 av_channel_layout_copy/describe 返回值。

### P1-2（宿主）「字幕样式设置…(SRT)」跳到 HDR 页而非字幕页【Lead 已复核】
- 位置：Form设置.vb:49-52 `SelectedIndex = 6`。
- 证据（Lead 复核）：Designer 页注册 0=FFF.Player、1=个性化、2=支持者、**3=ModernTabPage4（IsSeparator）**、4=界面与尺寸、5=设备与性能、**6=HDR**、7=字幕、8=弹幕…；LakeUI ModernTabListControl.SelectedIndex 按含分隔符的原始列表索引；Form设置.vb:31 自己也用 `Where(Not x.IsSeparator)`，证明分隔符占索引位。
- 机理：右键→字幕设置→「字幕样式设置…(SRT)」（SubtitleMenu.vb:91-94）实际打开 HDR 页，入口不可用。
- 修法：`SelectedIndex = 7`；更稳妥用页面对象引用（`SelectedTabPage`）或按名称定位，避免再加页错位。

### P2-K1（内核）外部音频 EOF 不冲刷 tempo 图 → 倍速/音效下外部音轨结尾丢音频
- `DrainInternalAudio` 有 `TempoAudio(nullptr,0)` 冲刷（1130）但函数第一行 `externalFormat_ != nullptr` 挡住外部音频；`PumpExternalAudio`（6256-6263）EOF 分支只 `Finish()` 不送 EOF 进图 → 图内缓冲（atempo/eq 延迟量）最后一段样本出不来。修法：EOF 分支 Finish 前补冲刷。

### P2-K2（内核）前导静音段 ×rate 时钟错位，报告位置可跌破 seek 目标（可为负）
- 建图时 `tempoOrigin_=max(origin,position)`（2263）+ 输出按计数器标注（2328）+ 时钟映射（7301）交互：音频流实际起点 F > seek 目标 T（start_time/AAC priming 常见）时，渲染器在 [T,F) 插静音期间报告位置 = F+(Pos−F)·rate；rate=2、F−T=0.2s → 开局报 −0.2s；rate=16 → −3s；视频前段被压播。修法：输出标注并入帧内容时间偏移，或对静音段做恒等映射。

### P2-K3（内核）scalingMode=1（Jinc）静默废掉 NVIDIA VSR + 死代码门【Lead 已复核】
- bypass `views[i]=sourceViews_[i]`（VideoRenderer.cpp:5547-5549）丢掉 `effectiveSourceViews_`（VSR 上采样面）；`ApplySuperResolution`（4432 起）无 mode 门控 → VSR 每帧 AI blit 照跑、结果被丢弃、快照仍报 D3D11VideoProcessor（8640-8644）。
- PR 给 `CanUseDirectVideoProcessor` 加的 `scalingMode_ != 0` 守卫（4200）落在**全树无调用点的死函数**上（grep 仅定义 4199/注释 4215/声明 619）——该门实际不生效，作者可能误以为挡住了 VP 路径。
- 修法：`ApplySuperResolution` 开头加 mode 门控（或 bypass 改用 effectiveSourceViews_）；删除/标注死函数上的伪门控。

### P2-K4（内核）Jinc EWA 缩小时 tap 爆炸（性能悬崖）
- SampleSelected（841-857）support=2、scale 不封底：4K→1080p 约 81 tap/像素/平面；8K→480p 37×37=1369 tap，含 chroma 约 8 亿次纹理 Load/帧、每 tap 12 项 Jinc 级数 → 60fps 需 ~500 亿 load/s，绝大多数 GPU 幻灯片。mode 2/3 无此问题（缩放由 scale pass 分级 halving 承担）。修法：mode 1 缩小时复用 scale pass 分级或对 scale<0.25 退回 scale pass。

### P2-K5（内核）SetScalingMode 无条件强设 `scalingQuality_=HighQuality`，与 SetScalingQuality 双向静默覆盖
- 2821-2828 强写 quality；mode≠0 期间 SelectScaleFilter（5427-5428）完全无视 quality；mode 回 0 后宿主先前选择已被篡改；快照不回报生效组合。修法：SetScalingMode 不动 quality_（mode≠0 本就不用它），或文档明示+快照回报。

### P2-H1（宿主）每次右键在 UI 线程同步扫盘 + 两次全量媒体信息原生往返
- SubtitleMenu.vb:24-25 `扫描同名字幕` 同步 IO（网络路径卡 UI）；:52 `安全读取媒体信息()` 在 `For Each 槽 In {0,1}` 循环内部，每次右键调两次（每次都走 FFF3FP_GetMediaInfo 编组+JSON 反序列化，会话层无缓存，会话.vb:935-941）。修法：提出循环外；缓存或异步构建。

### P2-H2（宿主）次字幕内嵌轨加载缺会话消失防护
