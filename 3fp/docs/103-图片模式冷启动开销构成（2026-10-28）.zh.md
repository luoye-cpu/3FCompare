### ⚠ 构建环境坑（本轮新踩，接手者必读）

1. **本机 exec 会话缺 `APPDATA`/`LOCALAPPDATA`** ⇒ NuGet `GetRestoreSettings` 拼路径得 null：`Value cannot be null. (Parameter 'path1')`。构建前显式 `$env:APPDATA="$env:USERPROFILE\AppData\Roaming"`。
2. **`DOTNET_ROOT` 指向 vendored dotnet 8（无 SDK）** ⇒ 系统参数下宿主 apphost 报「必须安装 .NET 10」/SDK 解析 `MSB4236`。构建与**任何 spawn 宿主的会话**都要设 `$env:DOTNET_ROOT='C:\Program Files\dotnet'`（X64 同）。
3. **不要给宿主构建会话注入 `MSBUILD_EXE_PATH`**（VS MSBuild 路径）——它会破坏 dotnet 的 SDK resolver（`找不到 .NET SDK`）。内核 vcxproj 单独用 VS MSBuild 编，宿主 vbproj 只交给系统 dotnet。
4. `global.json` 在 3FCompare 根（钉 `11.0.100-preview.7`），`3fp/kernel` 无自己的 global.json ⇒ 向上继承；系统 dotnet 装有 `11.0.100-rc.2` + `10.0.403`，rollForward latestFeature 可解析。

## 五、全套开销构成（从 0 到一张图上屏，中位数口径）

| # | 阶段 | 区间 | 成本 | 归因与证据 |
|---|---|---|---:|---|
| 1 | 进程创建 → 运行时引导 | 0 → ~16 ms | ~16 ms | CreateProcess + hostfxr/hostpolicy/coreclr（ETW） |
| 2 | CLR 启动与首批 BCL JIT | ~16 → ~36 ms | ~20 ms | System.Private.CoreLib 装载 + WinForms 到位（ETW） |
| 3 | WinForms/文本栈 | ~36 → ~151 ms | ~115 ms | WinForms 初始化、DWrite（ETW） |
| 4 | 托管 UI 栈初始化 | ~151 → ~585 ms | ~434 ms | LakeUI/Vortice/Svg 等托管程序集与 JIT（gap；docs/17 首触 JIT 为主项） |
| 5 | D3D/驱动初始化 | ~585 → ~827 ms | ~242 ms | Vortice.DXGI→d2d1/dxgi/d3d11→**nvgpucomp64→nvwgf2umx**（LakeUI 的 D3D 初始化拉起 NVIDIA 着色器编译器，ETW） |
| 6 | 继续托管初始化 | ~827 → ~1190 ms | ~363 ms | gap：剩余控件树/JIT（ETW） |
| 7 | 内核与 FFmpeg 接入 | ~1190 → ~1220 ms | ~30 ms | FFF.Native.dll + FFmpeg 六件套（avcodec 76.6 MB ≈11 ms，OS 缓存温热）+ libshaderc（ETW；与 docs/17 的 30.8 ms 探测一致） |
| 8 | 窗体构建收尾 → 窗口出现（T1） | ~1220 → 1560–1905 ms | ~340–680 ms | 首触 JIT + LakeUI 控件树（gap；T1 由 e2e/驱动双侧测得 1560–1905） |
| 9 | 图片打开全链（T1→T2） | — | **~86–94 ms** | 内核 Open：FFmpeg 首映射 + demux/解码 + 设备/交换链/首渲染 ~75 ms（计数器不覆盖段）；可归因：上传 2.0 + 软件转换 4.5 + presentWait 4.5 ≈ 11 ms（探针+快照计数） |
| 10 | **总账 T0→T2** | — | **中位 1802.8 ms**（有效 1641.5–1883.8） | e2e 正式轮 |

**主次分明**：T0→T2 的 ~1.8 s 里，**图片解码/上传/呈现本身只占 ~90 ms（5%）**；~1.7 s（95%）是「进程 + .NET + WinForms + LakeUI/D3D/驱动 + 首触 JIT」的宿主冷启动固有成本。与 docs/57 结论一致并更进一步：**慢在宿主，不在图片路径**——其中 nvgpucomp64/NVIDIA 驱动栈一段 ~240 ms 与首触 JIT 两大段（#4+#6+#8 合计 >1.1 s）是最大的可优化面（R2R 上游仍未启用）。

**开机首次 vs 进程冷启动**：本次开机后的第一次运行显著更贵——宿主首轮 T1 1933/T2 2036 ms（后续中位 1709/1803，+约 200 ms）；内核探针首轮到 OpenCompleted 493.9 ms（后续 ~86 ms，**+约 400 ms** 为开机首次 D3D 设备/交换链/驱动管线建立）。日常「从 0」口径 = 进程冷启动（OS/驱动缓存温热）；冷开机首张图还要再加约 0.2–0.6 s。

## 六、陷阱记录（本轮实测踩到，接手者别再踩）

1. **xperf/wpr 尺寸失控**：`wpr -start CPU -filemode` 在重负载机器上 40 s 录出 5.5 GB etl，tracerpt 转出 5.9 GB CSV（还伴随命令树退出超时）。只测进程/模块就 `xperf -on PROC_THREAD+LOADER`（3 轮仅 33 MB）。
2. **tracerpt 丢文件名**：对 xperf etl 的 CSV dump 里 ImageLoad 行**没有路径列**（PID 还是十六进制、模块路径整列缺失）⇒ 用 `xperf -i etl -o txt -a dumper` 的 `I-Start` 行（第二字段是**微秒**，不是毫秒）。
3. 内联 P/Invoke **必须用真实导出名**（`GetWindowThreadProcessId`/`GetWindowTextW`）：短名 `GWP` 会「找不到入口点」且在 2 ms 轮询循环里刷几十万行异常。
4. 构建环境四坑见 §二（APPDATA 缺失、DOTNET_ROOT 指向 vendored、MSBUILD_EXE_PATH 污染 dotnet SDK 解析、global.json 继承）。
5. PowerShell：`$pid` 是只读自动变量（循环里改名）；`"{0:P0}" -f $x/100` 会把除法当格式化参数（要加括号）。
6. e2e 工具的 T2 判据在负载尖峰会出离群轮（本轮 1 轮 5576 ms）：中位数扛住了，但**绝对值比较必须同时记录机器负载**。
