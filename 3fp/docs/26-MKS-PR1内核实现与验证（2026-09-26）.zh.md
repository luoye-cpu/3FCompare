## 1. 改动清单（内核，全部在 `3fp/kernel/`）

### 1.1 新文件 `3FP/Subtitle/SubtitleProbe.{h,cpp}`

- 头文件声明 `FFFResult ProbeSubtitleStreams(const char*, char*, uint32_t, uint32_t*) noexcept`（全局命名空间，`PlayerApi.cpp` 转发导出为 `FFF3FP_ProbeSubtitleStreams`）。
- 实现：`SharedFileInput::Open` + `avformat_open_input` + `avformat_find_stream_info`（**不看扩展名**）→ 只收 `AVMEDIA_TYPE_SUBTITLE` 流。
- 输出 JSON 顶层：`{"format":…, "formatLongName":…, "startTimeSeconds":<6 位小数>, "streams":[…]}`；
  流级字段与 `FFF3FP_GetMediaInfo.streams` **同构**（index/type/streamId/codec/codecLongName/codecTag/
  timeBase/bitRate/streamSize/lossless/startTime100ns/duration100ns/frames/extradataSize/default/forced/metadata/profile），
  宿主可直接用现成的 `媒体流信息` 反序列化并白拿 `metadata.language`/`metadata.title`。
- 失败语义（按 `docs/24` §1.1）：文件打不开 → `FfmpegFailure(-5)`；无字幕流 → `Success` + 空数组；
  两段式调用（先传 null 拿 required，再按 required 分配）走 `BufferTooSmall(-3)`。
- 辅助函数（`EscapeJson`/`AppendDictionaryJson`/`CodecTagName`/`MediaTypeName`/`CopyUtf8`）在本文件内独立实现
  —— 它们在 `PlayerSession.cpp` 的匿名命名空间里，不抽共享（保持 PR diff 最小、不碰会话层）。

### 1.2 `AssSubtitleRenderer.cpp`：容器字体附件注册

- 匿名命名空间新增 `IsFontAttachment(mimetype, filename)`：
  mimetype 非空时**包含 "font" 即认**（覆盖 `application/x-truetype-font`、`font/ttf`、`application/vnd.ms-opentype`…）；
  否则按文件名扩展名 `.ttf/.otf/.ttc` 兜底（部分 muxer 对字体附件写 `application/octet-stream`）。
- `ReadContainerTrack` 内、**`ass_new_track` 之前**（流校验之后）遍历全部流：
  `AVMEDIA_TYPE_ATTACHMENT` 且 `extradata` 非空 → `av_dict_get("mimetype"/"filename")` → `ass_add_font(library_, filename, extradata, size)`。
- 注册必须发生在 track 解析前（libass 渲染时查字体，但内存字体必须先入库）；`library_` 在 `Open()` 已初始化，直接可用。
- 该修复对**内嵌 ASS 字幕同样受益**（不只是外挂 MKS），独立价值。
- 补 `#include <cctype>`（`std::tolower`）。

### 1.3 API 头与导出

- `FFF.Player.Api.h`：`FFF3FP_GetMediaInfo` 声明旁新增 `FFF3FP_ProbeSubtitleStreams`（带注释）。
- `PlayerApi.cpp`：include `SubtitleProbe.h` + 一行转发（同 `GetLastError` 的形状）。
- **`PlayerApiVersion` 保持 15**：未改任何结构体，未动 rc 的 VER_API（D9 纪律：纯新增函数，旧宿主/旧 DLL 双向兼容）。

### 1.4 工程文件

- `FFF.Native.vcxproj` + `.filters`：注册 `SubtitleProbe.h/.cpp`（上游构建系统必需）。

### 1.5 工具改动（外层 `3fp/tools/`、`3fp/build/`）

- **`build_kernel_manual.py` 新增 `EXTRA_SOURCES` 机制**：tlog 是上次 MSBuild 的快照，
  **tlog 里没有的源文件无法被复放编译**。给内核新增 .cpp 时在脚本头部登记
  `(新源文件, 模板源文件)`（同目录 ⇒ 编译选项一致），脚本克隆模板 cl 命令块并替换文件主干名，
  再把新 obj 追加进 link 块 line0 的 `|` 分隔输入清单。
  🔴 **踩坑**：追加的 obj 路径必须写 `obj\x64\Release`（不带 STAMP）——`run()` 会对整条命令再做一次
  `redirect()`，路径已含 `Release_anim` 会被二次替换成 `Release_anim_ANIM`（实测 LNK1181）；
  写原始路径由 `redirect()` 统一转换即可。
- **`mks_subtitle_probe.cpp` 新增 `--probe-streams`**：调 `FFF3FP_ProbeSubtitleStreams` 打印 JSON，
  含 BufferTooSmall → 按 required 重试的两段式用法示范。

### 7.5 实现时的三个坑（记入检查清单）

1. **C# 语法混入 VB**：`FirstOrDefault(...) ?? 轨(0)` → VB 用 `If(首选, 轨(0))`；
