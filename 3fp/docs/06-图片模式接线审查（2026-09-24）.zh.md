## 二、Windows「默认打开方式」入口：**命令行走通，但"双击"不通**

**结论一句话**：路径作为**命令行参数**传入时，能正确进入图片模式（接收 / 单实例转发 / 与图片模式衔接三处都通）；
但 **3FP 目前没有注册图片扩展名的文件关联** ⇒ Windows 不会把 3FP 列进"打开方式"候选，用户也无法把它设为图片的默认应用。

### 2.1 命令行接收 ✅

| 环节 | 位置 | 结论 |
|---|---|---|
| 单实例开关 | `My Project/Application.myapp:5` `<SingleInstance>true</SingleInstance>`；`My Project/Application.Designer.vb:23` `Me.IsSingleInstance = True` | ✅ 已开启 |
| 首实例取命令行 | `ApplicationEvents.vb:32` `记录初次启动命令行(e.CommandLine)` → 存入 `待处理启动文件` | ✅ |

> 注：`ConsoleApplicationBase.CommandLineArgs` 会丢弃 0 号元素（可执行文件自身路径），故 `e.CommandLine` 不含 exe。

### 2.3 文件关联 ❌ **未注册图片扩展名**

- `文件关联管理器.vb` **存在**，但 `创建文件类型()`（`:399-443`，共 **43** 个 `New 文件类型定义` 条目）里只有
  **video / audio**（首条即 `常见视频, ".mp4"`），**图片扩展名命中数 = 0**。

⇒ **双击 `.png` 时 Windows 不会把 3FP 列入候选**（没有 `OpenWithProgids` / `SupportedTypes` 项），

## 三、发现的问题

### 🔴 P1 · 360° 静态全景图：两个模式会**同时启用**，且优先级与设计相反

**这是本次审查最重要的发现。**

- 360 控制器对 360° 静态全景图会启用自己：
  `UI/播放器360视角控制器.vb:86-91` —— `自动识别 = 有视频流 AndAlso 是360视频(...)`，注释还特意写"静态图片也可以是 360°全景图"。
- ⚠⚠ **而 `是360视频` 的第三条判据是纯启发式**（`UI/播放器360视角控制器.vb:103-104`）：

  ```vb
  Return 视频流.宽度 > 0 AndAlso 视频流.高度 > 0 AndAlso
      CLng(视频流.宽度) = CLng(视频流.高度) * 2L
  ```

  即**宽 == 高×2 就算 360**，不需要任何元数据 ⇒ **任何 2:1 的普通图片**
  （1920×960、3840×1920、2000×1000…）都会被自动判为 360° ⇒ **冲突面远比"全景图"大**。
- 图片控制器对**同一张图**也会启用自己：`UI/播放器图片浏览控制器.vb:70` —— 判定只看 `信息.是静态图片`，**没有排除 360°**。
- 360 控制器**完全不知道图片模式存在**（全文件搜 `图片模式` / `图片交互` 零命中）。
- 而 `UI/播放器画面控件.vb` 里的分流顺序是「光盘 → **图片** → 360」⇒ **图片模式抢走了滚轮与左键拖**。

⇒ 结果是一个**混合态**：滚轮/拖拽走图片语义（缩放/平移），而设计 `docs/00` §6.3 与 D8 要求
**整块让位给 360°**（"360° 静态全景图是真实场景，图片模式必须让位"）。
**触发条件是"打开任何 2:1 的图片"**，不是罕见的全景素材。

**实证**（用内核实机探针，2026-09-24）：造一张 1920×960 的**普通** PNG（`testsrc2`，无任何 360 元数据），
改动内核报 `staticImage=true`（⇒ 图片控制器会 `设置模式(True)`），
而 `1920 = 960 × 2` 满足上面那条启发式（⇒ 360 控制器也会 `设置模式(True)`）。
⇒ **两个模式确实会同时启用**，不是纸面推演。

**方向键更糟（是"静默失效"，不是双动作）**：
`UI/播放器360视角控制器.vb:164-201` 的 `PreFilterMessage` 在自身启用时对方向键**返回 `True`**（吃掉消息），
`IMessageFilter` 返回 True 后消息不再下发 ⇒ `Form1` 的 `KeyDown` 不触发 ⇒
`Form1.vb:839` 的 `RaiseEvent 方向键快捷键已请求` **不会发生** ⇒ 图片控制器的 ←/→ 处理器根本不被调用。
用户看到的是"滚轮能缩放，但方向键没反应"。

**最小修法（未实施）**：在 `播放器图片浏览控制器.媒体已打开` 里加一条前置判定 ——
若 `视角360控制器.是360视频(信息, 快照)` 为真（该函数已是 `Friend Shared`，可直接调用），
则**不进入图片模式**（`设置模式(False, False)`）。这样两模式天然互斥，且不改 360 与画面控件。

### 🟡 P2 · 图片模式与剪辑区间模式同时启用时，←/→ 会**双动作**

- 两个处理器挂在同一个事件 `Form1.方向键快捷键已请求`：图片在 `Form1.vb:167`（**先注册**）、剪辑区间在 `Form1.vb:203`（后注册）。
- .NET 事件按注册顺序调用，且**置 `e.Handled = True` 不会中止后续处理器**。
- 剪辑区间控制器 `UI/播放器剪辑区间控制器.vb:143-155` **不检查 `e.Handled`**，只看自己的 `当前模式已启用`。
- 而剪辑区间模式在打开图片时**不会被关闭**：`UI/播放器剪辑区间控制器.vb:114-117` 只在"光盘路径"时自动关闭。

⇒ 用户若先开剪辑区间模式、再打开图片，按一次 ←/→ 会**既切图又逐帧/跳转**。
**最小修法（未实施）**：剪辑区间处理器的开头加 `If e.Handled Then Return`（一处即可，且语义正确：抢键机制本就该尊重 `Handled`）。

### 🟢 P3 · 缩放分支冗余（代码异味，不影响功能）

`UI/播放器图片浏览控制器.vb:112`：

```vb
调整缩放(If(刻度 > 0, 缩放步进 ^ 刻度, 缩放步进 ^ 刻度))
```

两个分支**完全相同**。数学上仍正确（`刻度` 为负时 `1.25 ^ 负数` 即缩小），
但条件表达式毫无意义 ⇒ 疑为重构残留，应简化为 `调整缩放(缩放步进 ^ 刻度)`。

### 🟢 P4 · 与设计规格的两处偏离（非缺陷，但需记录）

| 设计原文（`docs/00`） | 实现 | 说明 |
|---|---|---|
| §6.5「播放/暂停按钮 → **换成**上一张/下一张」 | `UI/播放器界面呈现器.vb:221-228` 只**隐藏**该按钮 | 简化实现。功能上不缺失（←/→ 可切图），但按钮位少了可见入口 |
| §6.4「双击 → 适应窗口 ↔ 1:1」 | **未实现** | 且视频模式**本就没有**双击全屏（全仓仅播放列表项有 `ItemDoubleClick`）⇒ 该行是规格的**超前描述**，非回归 |

### 🟡 P5 · 文件关联未注册图片扩展名（"双击图片"不可用）

`文件关联管理器.vb:399-443` 的 `创建文件类型()` 共 43 条，**全部是 video/audio，图片扩展名 0 条**；
`Form设置_文件关联.Designer.vb` 只有 6 个复选框，无图片项。⇒ Windows 不会把 3FP 列为图片的"打开方式"候选。
这正是 `STATUS.md` M2 待办 **4.5**，本 PR 未做（**不属于本 PR 范围**：本 PR 交付的是内核图片模式 + 宿主图片模式，
文件关联是独立的用户可见行为，宜单独提交）。

### 🟢 P6 · UNC 与重解析点被内核拒绝（其中重解析点是副作用）

- `\\server\share\x.png` 被拒（`:3761`）——**设计如此**（禁用网络路径），非回归。
- 但 **OneDrive 按需占位文件 / 符号链接 / junction** 因 `FILE_ATTRIBUTE_REPARSE_POINT`（`:3766`）被拒，
  且错误以**英文原文**弹出。OneDrive 占位是常见场景，用户会看到不友好的英文报错。

## 四、审查结论

| 问题 | 结论 |
|---|---|
| ① 图片模式是否被正确调用？ | **是。** 从内核 `staticImage` 到界面隐藏的**每一跳都已核对**；输入门控符合"只加不改"；视频模式的滚轮/左键拖分支未被修改。数据源走的是 K3 修复后的 `staticImage`，不是宿主侧的隐式推断（符合 R-3）。 |
| ② Windows「默认打开方式」？ | **命令行走通，双击不通。** 路径作为命令行参数（含单实例转发）能正确进入图片模式，且三条入口汇到**同一判定点**；但**未注册图片扩展名关联** ⇒ 双击 `.png` 时 Windows 不会把 3FP 列为候选（属 M2 待办 4.5，不在本 PR 范围）。 |
| **必须修** | **P1（2:1 图片 ⇒ 360 与图片两模式同时启用，滚轮/拖拽被图片抢走、方向键静默失效）** —— 已实证，且触发条件是常见的 2:1 比例 |
