
## 3. 字体附件四格对照（决定性）

### 3.1 设计

只比较"同一文件 ± 外部字体目录"是不够的（无法排除"两边都回退"），因此做四格：

| 组 | 文件 | 外部字体目录 |
|---|---|---|
| **A** | 原始（含 9 附件） | 无 |
| **A'** | `boruto_nofonts.mks`（剥离附件，ASS 数据**逐字节一致**） | 无 |
| **B** | 原始（含 9 附件） | `fonts_extracted/`（从容器导出的同样 9 个字体） |
| **B'** | 剥离版 | `fonts_extracted/` |

判读规则：
- **A ≡ A'** ⇒ 附件等于没带（**缺陷成立**）；A ≠ A' 且 A ≈ B ⇒ 附件生效了。
- **B' 与 A' 不同** ⇒ 外部字体目录这条路径确实有效（反向验证判据本身有牙齿）。

### 3.2 第一次跑出的"意外"——不是缺陷，是时间轴偏移

原始版在 t=0/12/40 全部返回 `Clear`，剥离版却画出了字。一度像是"附件流的存在改变了内核行为"。

**真相**：两文件 ASS 数据逐字节相同、包数相同（1246）、时长相同，但**原始版的容器时间戳整体偏移 +141.81 s**：

```
原始   首包 pts_time = 141.810000   末包 = 5714.060000   start_time = 141.810000
剥离   首包 pts_time =   0.000000                        start_time = 0.000000
```

用 `-copyts` 重封装（禁止 ffmpeg 挪动时间戳）后仍是 `141.810000` ⇒ **偏移是文件固有属性，不是重封装引入的**。

⇒ 用 `--times 142,153,181`（= 剥离版 0/12/40 + 141.81）对齐到**同一条事件**后重测。

### 3.3 对齐后的结果

画布 640×360，同一时刻（原始 t=142/153/181 ≡ 剥离 t=0/12/40）：

| 事件 | A 含9附件·无外部字体 | A' 0附件·无外部字体 | B +外部字体 | B' 0附件·+外部字体 |
|---|---|---|---|---|
| 1 | 196x40 @(226,318) **2826** | 196x40 @(226,318) **2826** | 174x37 @(238,321) **2281** | 174x37 @(238,321) **2281** |
| 2 | 267x40 @(191,318) **4022** | 267x40 @(191,318) **4022** | 230x40 @(210,320) **3194** | 230x40 @(210,320) **3194** |
| 3 | 319x41 @(166,317) **4849** | 319x41 @(166,317) **4849** | 286x40 @(183,320) **4040** | 286x40 @(183,320) **4040** |

**A ≡ A'（三组全部逐位相同）**，**B ≡ B'（三组全部逐位相同）**，而 A 与 B 明显不同（宽度窄 10~14%：196→174、267→230、319→286）。

### 3.4 最终干净对照（真实文件 + 时间轴归零 + 含全部 9 附件）

为排除时间轴变量，另做 `boruto_normalized_withfonts.mks`（`-output_ts_offset -141.81 -t 130`，10 流全保留）。**唯一变量是字体目录**：

| 时刻 | 无外部字体 | +外部字体目录 |
|---|---|---|
| t=0 | 196x40 @(226,318) **2826** | 174x37 @(238,321) **2281** |
| t=12 | 267x40 @(191,318) **4022** | 230x40 @(210,320) **3194** |
| t=40 | 319x41 @(166,317) **4849** | 286x40 @(183,320) **4040** |

三方互证：`A@142/153/181` ≡ `A'@0/12/40` ≡ `boruto_normalized@0/12/40`（196x40/2826、267x40/4022、319x41/4849）。

> ### ✅ 定案
> **"带 9 个字体附件"与"一个字体都没有"在内核里完全等价** —— 容器内字体附件 100% 未被加载。
> 这正是 **Jellyfin #15222（外挂 MKS 的 ASS 字体错误，至今 open）** 的同一根因。
> 修法（`docs/24` 内核改动 2）：`AssSubtitleRenderer::ReadContainerTrack` 内、**track 解析之前**，
> 遍历 `AVMEDIA_TYPE_ATTACHMENT` 流 → 判 `IsFontMime` → `ass_add_font`。

## 4. 时间轴偏移：真实世界的新变量

```
原始 MKS            start_time = 141.810000   首包 141.810   末包 5714.060
官方样本参照          multiple_sub_sample.mkv  start_time = 0.000000
                     supsample.mkv            start_time = 0.000000
自制 .mks            multi_with_fonts.mks      start_time = 1.000000
                     pgs_official.mks          start_time = 1.001000
```

⇒ **正常字幕的 `start_time` 落在 0~1 s**；本样本的 141.81 s 是异常的（很可能来自 mkvmerge 提取时保留了源时间轴）。

**更要命的是**：ASS 文本里第一条事件写的是 `0:00:00.00`，容器却说它在 141.81 s。Matroska 的 ASS **以容器块时间戳为准**（ASS 文本时间被忽略），内核实测行为与之一致（t≤120 全部 `Clear`，t=142 才出字）。

### 对实现的意义

外挂 MKS **没有参考的视频/音频流**，所以对不齐就没人能纠正。宿主必须在两条路里选一条：

| 方案 | 行为 | 评价 |
|---|---|---|
| (a) 用容器绝对时间戳 | 本样本前 141 s 无字幕 | 与内嵌字幕 / 其他播放器一致，但"看起来坏了" |
| (b) 归一化（减去轨道 `start_time`） | 字幕从 0 对齐 | 更符合"外挂字幕"直觉；但与内嵌行为不一致 |

**建议**：内核按 (a) 不变（与内嵌一致、零歧义），但 **`FFF3FP_ProbeSubtitleStreams` 必须在顶层返回 `startTimeSeconds`**，让宿主能显示/用现有"字幕延迟"功能修正。这也是 `docs/24` 里"是否支持字幕延迟/偏移"那个待决项的实测依据 —— **现在看是需要的**。

## 5. 播放器行为复核（真实文件）

```
Create: 0
Open -> 0
    event=Error {"result":-7,"message":"The file contains no playable video or audio stream.","operation":"open"}
OpenCompleted=no  Error=yes
GetMediaInfo -> 0 (required=1)
mediaInfo:                      ← 空
```

- 字幕流 0：`FFF3FP_OpenAssSubtitle(…, streamIndex=0)` → **Success**，渲染出字。
- 位图路径：`FFF3FP_OpenBitmapSubtitle` → `-7 NotSupported`（正确，它是文本轨）。

⇒ **`docs/24` 的唯一硬缺口（探测）在真实文件上原样成立**，方案无需修改。

## 7. 可复现命令

```bash
P="3fp/samples/media/mks/community"

# ① 下载 + 解包（走本机代理）
curl -sL --max-time 180 -x http://127.0.0.1:10808 -o "$P/boruto.mks.tar.gz" \
  "https://github.com/user-attachments/files/23148523/Boruto.Naruto.the.Movie.2015.tmdbid-347201.-.1080p.mks.tar.gz"
tar -xzf "$P/boruto.mks.tar.gz" -C "$P"

# ② 剥离附件（注意：FFmpeg 的 muxer 不认 .mks 扩展名，必须显式 -f matroska）
ffmpeg -v error -y -i "$P/Boruto*.mks" -map 0:s:0 -c copy -f matroska "$P/boruto_nofonts.mks"

# ③ 导出附件字体
ffmpeg -v error -y -dump_attachment:1 AurulentSans-Bold.otf … \
  -i "$P/Boruto*.mks" -map 0:s:0 -c copy -f null -

# ④ 时间轴归零 + 裁 130s（含/不含附件各一份）
ffmpeg -v error -y -i "$P/Boruto*.mks" -map 0    -c copy -output_ts_offset -141.81 -t 130 -f matroska "$P/boruto_normalized_withfonts.mks"
ffmpeg -v error -y -i "$P/Boruto*.mks" -map 0:s:0 -c copy -output_ts_offset -141.81 -t 130 -f matroska "$P/boruto_normalized.mks"

# ⑤ 探针（Windows 路径在 Git Bash 里必须单引号）
cd 3fp/build
./mks_subtitle_probe.exe --stream 0 --times 0,12,40 \
  'C:\PLAN\3FCompare\3fp\samples\media\mks\community\boruto_normalized_withfonts.mks'
./mks_subtitle_probe.exe --stream 0 --times 0,12,40 \
  --fontdir 'C:\PLAN\3FCompare\3fp\samples\media\mks\community\fonts_extracted' \
  'C:\PLAN\3FCompare\3fp\samples\media\mks\community\boruto_normalized_withfonts.mks'
```
