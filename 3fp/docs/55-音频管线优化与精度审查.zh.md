## 1. 看似热点、实测可忽略：逐样本峰值扫描

### 1.1 为什么怀疑它

`QueueAudioFrame` → `UpdateInputAudioPeakLevels`（L3680）：

```cpp
for (channel...) {
    for (sample = 0; sample < frame->nb_samples; ++sample) {
        switch (packedFormat) { ... }        // 每样本一次分支
        if (std::isfinite(value))            // 每样本一次 isfinite
            peaks[channel] = (std::max)(peaks[channel], std::abs(value));
    }
}
```

**疑点**：① 每样本三次运算；② **无条件执行**（即使 UI 不显示电平表）；
③ 对外只暴露 **8** 个声道（`inputValues[8]`），而 IAMF 7.1.4 是 **12** 声道
⇒ **4 个声道扫描后被丢弃**。

### 1.2 实测

`audio_peak_cost_probe`（复现同样循环）：

| 配置 | 成本 |
|---|---|
| 2 ch / 1024 帧 | 0.002 ms/秒 |
| **12 ch / 4096 帧** | **0.002 ms/秒** |
| 12 ch / 1024 帧 | 0.002 ms/秒 |

⇒ **约 0.0002% 单核**。12 声道 57 万样本/秒在现代 CPU 上不足 2 微秒/秒。

**判定：不值得优化。** 即使无条件执行、即使丢弃 4 个声道，成本仍在噪声级。
（若真要改，`if (需要的声道数 < 实际声道数)` 提前截断是唯一有意义的点，但收益为 0。）

## 2. 排查过、确认无问题的项

### 2.1 双重重采样？**不存在**

`streamFlags` 含 `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`（L542），初看像是"OS 又重采样一次"。

但 `activeFormat = format.get()`（`GetMixFormat()`）**就是设备混音格式**，
`outputSampleRate_ = activeFormat->nSamplesPerSec` 即设备采样率，
`swr` 正是以它为输出目标。

⇒ **`AUTOCONVERTPCM` 是兜底**（混合格式与实际端点不一致时由引擎处理），
不是常态路径 ⇒ **不存在双重重采样**。

### 2.2 重采样器尾部丢弃？**不会**

```cpp
while (resampler_ != nullptr) {
    const auto capacity = swr_get_out_samples(resampler_, 0);
    if (capacity == 0) break;
    ... swr_convert(resampler_, output, capacity, nullptr, 0);   // 冲刷
}
```

⇒ `Finish()` **循环取尽** swr 内部残余样本，不会丢尾部。

### 2.3 每帧堆分配？**已复用**

```cpp
converted.resize(capacity * outputBlockAlign_);   // 从复用池取
...
converted.resize(frames * outputBlockAlign_);     // 收缩到**实际**帧数
```

- `reusableBuffers_`（≤8 个，单个 ≤1MB）复用；
- 64 个平面指针走**栈数组**（注释明确说为避免每帧堆分配）；
- `resize` 到 `capacity`（上界）后立刻缩到 `frames`（实际）✓ 不会写入垃圾数据。

### 2.4 时钟换算精度？**足够**

```cpp
playedFrames * 10'000'000 / outputSampleRate_     // 整数除法
```

- `playedFrames` 是**绝对值**而非增量 ⇒ **误差不累计**，单次误差 <1 个 100ns 单位（0.1 µs）；
- `clockFrequency` 换算用 **`long double`** ✓（避免 64 位精度损失）；
- `Position100ns()` 用 QPC 外推并 **clamp 到 `clockLimitPosition100ns_`** ⇒ 不会跑到已提交样本之外。

### 2.5 seek 过滤边界？**正确**

```cpp
if (position + 帧时长 < seekTarget100ns_) return;
```

⇒ 保留**跨过** seek 点的帧（用 `+帧时长` 而非裸 `position`），不会漏掉目标所在帧。

## 3. 精度实测

### 3.1 A/V 同步（60 秒，12 声道 IAMF / 5 分钟素材）

| 墙钟 | 播放位置 | 音频位置 | **差** | 缓冲 |
|---|---|---|---|---|
| 10 s | 9.982 | 9.982 | **0.0000** | 0.174 |
| 30 s | 29.995 | 29.995 | **0.0000** | 0.132 |
| 50 s | 49.994 | 49.994 | **0.0000** | 0.101 |
| 60 s | 59.988 | 59.988 | **0.0000** | 0.180 |

- **最大 |差| = 0.0000 秒**；
- 时钟**单调无回退**；
- `欠载 / 抖动 / 不连续 = 0 / 0 / 0`；
- 缓冲在 0.10 ~ 0.18 秒间正常波动（生产/消费周期）。

### 3.2 采样率换算（设备 48 kHz，源非 48 kHz ⇒ 必经重采样）

| 源采样率 | 最大 |差| | 单调性 | 欠载增量 |
|---|---|---|---|
| 44100 Hz | **0.0000 s** | 单调 ✓ | 0 |
| 48000 Hz | **0.0000 s** | 单调 ✓ | 0 |
| 96000 Hz | **0.0000 s** | 单调 ✓ | 0 |
| 192000 Hz | **0.0000 s** | 单调 ✓ | 0 |

⇒ **换算精度在全部常用采样率下都无可见误差**。

**可感知阈值参考**：ITU-R BT.1359 建议音频超前画面 **≤45 ms**、
音频滞后画面 **≤125 ms** 为可接受。当前 **<0.1 ms（测量分辨率下限）**，
**余量超过两个数量级**。

## 4. 若要继续提升，唯一有意义的方向

**不是精度，而是"可观测性"**。本轮发现的两个真实缺陷（见 docs/53、54）都属于这一类：

| 已修 | 性质 |
|---|---|
| IAMF 时间戳 208 倍误差 → 207 秒静音队列 | 真实播放缺陷，但**任何指标都没报警** |
| 抖动计数 100% 误报 | 诊断字段失效，**掩盖**而非暴露问题 |

⇒ **管线的正确性不缺，缺的是"出问题时能被发现"**。

**建议**（未实施，因需产品决策）：
- 把 `audioUnderruns` / `audioDiscontinuities` / `insertedSilenceFrames` 接入 UI 信息图层
  （字段已在快照里，与 docs/52 的 IAMF 声场显示同一路径）；
- 当前这些值**只有写过探针的人能看到**。
