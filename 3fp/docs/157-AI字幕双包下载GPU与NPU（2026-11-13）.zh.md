## 一、需求（用户裁定）

- 用户："我记得 NPU 版和 GPU 版不一样？"→ 确认两者是**不同引擎、不同运行时**的独立包。
- 用户选定方向：**下载支持两种包**（GPU+CPU / NPU），NPU 也走一键下载，设备下拉随包引擎联动。

## 二、两种包的本质差异（调查实证）

| | GPU+CPU 包 | NPU 包 |
|---|---|---|
| 引擎 | `llama`（GGUF Q8_0） | `onnx`（int8 三件套） |
| 加速 | Vulkan 整份权重进显存，NV/AMD/Intel 通吃 | OpenVINO NPU，**只吃 fp32 的 conv 前端**（约占 1%），int8 两段仍留 CPU |
| 模型 | 主权重 804 MB + mmproj 214 MB | conv 44 MB + encoder.int8 182 MB + decoder.int8 756 MB + tokenizer |
| 运行时 | llama-server（Vulkan，37 MB zip） | 含 OpenVINO 的包内 Python（420 MB，压缩 147 MB） |
| 额外件 | 无 | `qwen3_ort.py`（三段 OpenVINO 推理实现，**须与 worker 同级**） |
| 清单 runtime 字段 | `runtime/vulkan` | **无**（推理在包内 Python 里跑，非子进程） |
| 公共下载源 | 有（ggml-org 官方仓 + llama.cpp 回退） | **无**（sherpa 导出件 + 定制 OpenVINO Python，只能母仓） |
| 体积 | ~1 GB | ~1.4 GB |

worker 对 NPU 的硬依赖（`asr_worker.py` 实证）：`Path(__file__).with_name("qwen3_ort.py")` 存在 +
`import openvino` 成功（即包内 Python 必须带 OpenVINO，**不能用 GGUF 那个精简 Python**）。
引擎判定唯一依据是模型目录里的容器（`*.gguf` → llama，否则 onnx），清单 engine 字段只是备注。

### 3.2 下载器（`Ai字幕包下载器.vb`）

- 新增 `包类型` 枚举（GpuCpu / Npu）；`组清单(类型)` 分流为 `组Gpu清单` / `组Npu清单`。
- NPU 清单三项全来自母仓：npu-model.zip→model/、npu-python.zip→runtime/python/、
  qwen3_ort.py→包根（与 worker 同级）。**母仓未配置时返回空清单**。
- `下载包Async(目录, 类型, 进度, 取消)`：NPU 且母仓空 → 前置人话错误（不静默降级）：
  "NPU 包需要自建母仓…请先上传 npu-model.zip / npu-python.zip / qwen3_ort.py…GPU+CPU 不受此限制"。
- 清单生成按类型分流：NPU → engine=onnx、python=runtime/python/python.exe、**无 runtime 字段**；
  GGUF → 原 llama 清单不变。worker 仍用随 exe 部署的新版（559347B8…，支持 NPU）。
- 全部 NPU 载荷字节 + SHA256 钉死（上表），复用既有 .part 续传 / 逐源回退 / 磁盘预检 / 进度回调。

### 3.3 UI（`Form设置_AI字幕`）

- 新增 PanelAI12「包类型」行（包目录行与下载按钮行之间）：MCB_包类型 下拉 250 宽 +
  HCL_包类型 说明标签。两项：`GPU+CPU 包（GGUF · Vulkan）` / `NPU 包（ONNX · OpenVINO）`，
  项提示写明硬件前提与获取限制。
- 选 NPU 且母仓未配置 → 说明标签橙色"需自建母仓，无公共下载源"。
- **切包类型时目录框重置为该类型默认目录**（`3FP-AI-Subtitles` / `3FP-AI-Subtitles-NPU`）——
  两种包引擎不同，留着旧引擎目录会让下载误判"已是有效包"（实测发现并修复）。
- 下载中禁用包类型下拉（防中途切换）；下载目标目录按类型取默认子目录（用户已填路径则尊重）。
- 设备下拉随引擎联动是**既有能力**（`刷新状态`→`重建设备提示`/`重建后端下拉` 按包引擎过滤）：
  NPU 包（onnx）下 NPU 项真实可用，GGUF 包（llama）下 NPU 项标注"需独立包"。无需新增逻辑。

### 6.2 组装可行性实测（先验证再实现）

在 `_3fc_tmp\npu_pub_stage` 用纯公共源件组装：embed zip 解压 → 五 wheel 解压进
`Lib\site-packages`（wheel 本质 zip；五件顶层都只有包目录+dist-info，无 scripts 特殊件）
→ 写 `python312._pth`（`python312.zip / . / Lib\site-packages / import site`）。结果：

- import 四件套全过，版本与验证包一致；OpenVINO `Core().available_devices` = CPU/GPU.0/GPU.1 ✓
- **金样本真推理**：qwen3_ort.Engine(ov-cpu) + selftest.wav（5s 粤语）→
  "今次寻寻觅觅，终于揾到My Princess，肯借个场俾我哋玩。你知啦，喺香。"
  与 selftest.txt 一致（语言自报 Cantonese ✓；ov-cpu 全段 26.5s 属预期——NPU 包的设计
  就是 conv 上 NPU、int8 留 CPU，本机无 NPU 只能全 CPU 跑通验证）

### 6.3 实现改动

- **下载器**：`组Npu清单` 重写为 12 项公共源清单（6 模型件×双源 + embed + 5 wheel），
  全部字节+SHA256 钉死；`包文件项` 加 `覆盖前缀`——母仓配置时 npu-model.zip /
  npu-python.zip 排前作可选加速，命中即跳过被覆盖散件，失败自动回落公共源（不致命）。
  NPU 母仓守卫**删除**（不再需要）。组装阶段：qwen3_ort.py 从 exe 部署副本复制进包根 +
  写 `python312._pth`。总字节按实际会走的链算（母仓 zip 命中时散件不计入）。
- **vbproj**：qwen3_ort.py 随 exe 部署（ai-subtitles\qwen3_ort.py，PreserveNewest）。
- **UI**：包类型说明改"模型直链 sherpa 官方仓，约 1.1 GB"（不再提母仓/橙色警示）。
- GGUF 链零改动（回归清单=3 项验证过）。
