# 48 · 3FP 上采样/下采样模式分析与优化空间

> 问题：「分析一下目前 3FP 采用的上采样和下采样模式是什么？列举主流的上下采样模式，
> 有没有可优化部分」
> 方法：**读实现 + 实测**（不靠命名推断，3FP 的 "Bicubic" 实际不是标准 Bicubic）
> 日期：2026-10-06

---

## 0. 结论速览

3FP 有**两条**独立缩放路径，质量与自适应性差别很大：

| 路径 | 用途 | 滤波器 | 倍率自适应 | 评价 |
|---|---|---|---|---|
| **① `ScalePixelShader`** | 下采样到窗口尺寸 | Catmull-Rom / Lanczos3 / Box | ✅ `support = radius/scale` | 架构正确 |
| **② `SampleLanczos3`** | 最终绘制到 backbuffer | Lanczos3 固定 6×6 | ❌ 固定半径 | 正常流程不触发 |

**主要可优化点**（按收益排序）：

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 严重下采样（<0.25×）用 **Box 等权** | 非整数倍比例下抗混叠弱于 area/lanczos | 改用自适应 Lanczos 或真正的面积平均 |
| 2 | `Filter=0` 命名 "Bicubic" 实为 **Catmull-Rom** | 命名误导；该核偏锐、下采样非最优 | 按方向分别选核 |
| 3 | **上/下采样用同一套滤波** | 上采样要锐、下采样要平滑，需求相反 | 按方向分别选核 |
| 4 | 路径②固定 6×6 | 极端缩放下会混叠 | 低优先（正常流程不触发） |

## 1. 3FP 实际用的是什么

### 1.1 路径①：`ScalePixelShader`（主下采样路径）

**可分离两遍（separable），逐次二分**（`EnsurePlaneScaleChain`）：

```cpp
while (width > targetWidth || height > targetHeight) {
    nextWidth  = width  > targetWidth  ? max(targetWidth,  (width+1)/2)  : width;
    nextHeight = height > targetHeight ? max(targetHeight, (height+1)/2) : height;
    // 按"面积代价更小"决定先水平还是先垂直
}
```

每 pass 只做**单轴**一维卷积（`Axis` 常量），这是**正确的做法**：
- 可分离滤波把 O(r²) 降到 O(2r)；
- 逐次二分避免大倍率下单 pass 采样跨度过大。

**滤波器选择**（C++ 侧按**总体**比例，shader 内按**每 pass**比例算支撑）：

```cpp
const float scaleX = targetWidth  / planeWidth;
const float scaleY = targetHeight / planeHeight;
const std::uint32_t filter = std::min(scaleX, scaleY) < 0.25f ? 2u :   // Box
    (scalingQuality_ == HighQuality ? 1u : 0u);                        // Lanczos3 / Cubic
```

**shader 内的三个核**：

| Filter | 核 | 半径 | 公式 |
|---|---|---|---|
| 0 | **Catmull-Rom 三次**（代码里叫 "Bicubic"） | 1.0 | `(2v-3)v²+1` |
| 1 | **Lanczos-3** | 3.0 | `sinc(v)·sinc(v/3)` |
| 2 | **Box**（方窗） | 0.5 | `v<0.5 ? 1 : 0` |

**自适应支撑（正确）**：

```hlsl
const float scale  = min(destinationExtent/sourceExtent, 1.0);
const float radius = Filter==2?0.5:(Filter==0?1.0:3.0);
const float support = radius/max(scale, 0.000001);   // ← 关键：下采样时自动加宽
```

⇒ **路径①是 scale-aware 的**，这一点做得对。

### 1.2 路径②：`SampleLanczos3`（最终绘制）

```hlsl
float4 SampleVideo(Texture2D<float4> src, float2 uv) {
    if (near(OutputWidth,width) && near(OutputHeight,height))
        return src.SampleLevel(PointSampler, uv, 0);   // 1:1 => 点采样
    return SampleLanczos3(src, uv, dimensions);        // 否则固定 6x6
}
```

固定 **−2..3 的 6×6** 采样，**半径不随缩放比变化**，外加把负瓣 clamp 到双线性包络（抑制振铃）。

**但正常流程中它不缩放**：路径①已把画面缩到窗口尺寸 ⇒ 这里通常 1:1 ⇒ 走点采样。

会真正缩放的情况：全景投影、VSR 放大后、`limitToNativeSize`、路径①未执行的少数路径。

## 2. 主流上下采样模式对照

| 算法 | 核 / 半径 | 上采样锐度 | 下采样抗混叠 | 成本 | 备注 |
|---|---|---|---|---|---|
| **Nearest** | 方窗 | 极差（块状） | 无 | 最低 | 仅像素艺术 |
| **Bilinear** | 三角，r=1 | 软 | **差** | 低 | 3FP 未用作缩放核 |
| **Bicubic (Catmull-Rom)** | 三次 B=0,C=0.5，r=1 | **锐** | **较差** | 中 | **3FP 的 Filter=0** |
| **Bicubic (Mitchell)** | 三次 B=C=1/3，r=1 | 略软 | 较好 | 中 | 更均衡 |
| **Lanczos-2/3/4** | sinc·sinc(v/a)，r=a | **最锐** | **好**（a 越大越好） | 中高 | **3FP 的 Filter=1**（a=3） |
| **Area / Box（正确加权）** | 覆盖面积加权 | 不适用 | **最好** | 中 | 下采样黄金标准 |
| **Box（等权，3FP Filter=2）** | 等权平均 | 不适用 | 好（整数倍时=area） | **低** | 非整数倍有偏差 |
| **Gaussian** | 高斯 | 很软 | 很好 | 中 | 过度模糊 |
| **Spline (B-Spline)** | 三次 B=1,C=0 | 很软 | 好 | 中 | 极少单独用 |
| **FSR 1.0 (EASU/RCAS)** | 边缘自适应 | 很锐 | 不适用（上采样专用） | 中 | 需锐化后处理 |
| **NIS (NVIDIA Image Scaling)** | 方向自适应 + 锐化 | 锐 | 不适用 | 低 | 驱动内置 |
| **DLSS / XeSS / FSR2/3** | 神经网络 + 时序 | 最佳 | 不适用 | 极高 | **需运动矢量**，视频播放不适用 |
| **madVR NGU / Jinc** | Jinc·sinc 窗 | 最佳（离线） | 最佳 | 极高 | 播放器领域标杆 |
| **mpv `ewa_lanczos`** | 椭圆加权 Lanczos | 锐且少振铃 | 好 | 高 | 2D 非可分离 |
| **mpv `lanczos`/`spline36`/`mitchell`** | 可分离 | 均衡 | 好 | 中 | 含 SSIM 优化下采样 |
| **RTX VSR** | 驱动 AI 超分 | 最佳 | 不适用 | 低（张量核） | **3FP 已支持**（见 docs/28） |

> **视频播放的关键约束**：DLSS/FSR2 一类需要**运动矢量 + 时序累积**，
> 视频播放没有这些数据，**不适用**。视频领域实际可用的是
> 可分离/EWA 滤波、NGU、以及 RTX VSR 这类**单帧**超分。

## 3. 实测：质量与成本的权衡

### 3.1 下采样质量（8K→720p，对 area 参考的 PSNR）

| 核 | PSNR |
|---|---|
| bicubic | **43.16** |
| lanczos | 42.25 |
| bilinear | 39.92 |
| neighbor | 29.20 |

### 3.2 抗混叠能力（细条纹扫描，`YMAX` 越低越好）

| 条纹周期 | area | bilinear | lanczos |
|---|---|---|---|
| 2 px | **189** | 200 | 195 |
| 4 px | **174** | 181 | 176 |
| 8 px | **159** | 171 | 165 |
| 16 px | **159** | 169 | 163 |

⇒ **`area`（面积平均）抗混叠最好**，`bilinear` 最差。

### 3.3 成本（8K→720p 单帧）

| 核 | 耗时 | 相对 |
|---|---|---|
| area | 394 ms | 1.00× |
| bilinear | 396 ms | 1.01× |
| bicubic | 421 ms | 1.07× |
| **lanczos** | **454 ms** | **1.15×** |

**上采样（720p→1440p）**：bilinear 102 / bicubic 104 / **lanczos 118 ms（1.16×）**

⇒ **Lanczos 只比 bilinear 慢 15%**，而质量明显更好。
**3FP 在严重下采样时改用 Box 省下的这点性能，代价不划算。**

## 4. 可优化点（按优先级）

### ★ P1：严重下采样（<0.25×）用 Box 等权，质量低于 Lanczos

**现状**：`min(scaleX,scaleY) < 0.25` ⇒ Box（`v<0.5 ? 1 : 0`，等权平均）。

**⚠️ 先修正一个我自己的过度断言**：等权平均在**整数倍**下采样时**等于**面积平均，
而典型视频比例恰好是整数：

| 场景 | 比例 | 整数倍？ |
|---|---|---|
| 8K→720p | 6.000 × 6.000 | ✅ |
| 8K→1080p | 4.000 × 4.000 | ✅ |
| 4K→720p | 3.000 × 3.000 | ✅ |

⇒ 在**整数倍**场景下 Box 等权**没有问题**。

**但真实使用中窗口尺寸是任意的**（用户拖拽/最大化），比例通常非整数。
实测非整数比例（1851×1041，比例 4.149）的抗混叠：

| 核 | YMAX（越低越好） |
|---|---|
| **area** | **175** |
| bilinear | 185 |
| **bicubic（Catmull-Rom）** | **182** |
| **lanczos** | **181** |

⇒ 非整数倍时 `area` 明显优于其它；而 3FP 的 Box 是**等权简化版**，
在非整数倍下**不等价于面积平均**。

**建议**：严重下采样改用 **Lanczos（现有 Filter=1，已 scale-aware）**，
或实现**真正的面积平均**（权重按覆盖面积而非等权）。
成本仅增加 ~15%（见 §3.3）。

**收益**：消除非整数倍缩放下的莫尔纹/闪烁（拖拽窗口时最易观察到）。


### ★ P2：`Filter=0` 命名误导，且下采样表现不佳

**现状**：代码注释与命名是 "Bicubic"，实际公式 `(2v-3)v²+1` 是 **Catmull-Rom**（锐利核）。

**问题**：Catmull-Rom 上采样锐利（好），但**下采样抗混叠较弱**（实测 PSNR 虽高，
但那是"锐度"得分，混叠扫描里它并未测；其负瓣会造成振铃）。

**建议**：
- 保留 Catmull-Rom 用于**上采样**（锐度优势）；
- 下采样改用 **Mitchell (B=C=1/3)** 或 Lanczos；
- 至少把注释/命名改对，避免误导。

### ★ P3：上/下采样应分别选核

**现状**：`scalingQuality_` 只分 HighQuality / 其他，**不区分方向**。

**原理**：上采样要**锐**（Catmull-Rom/Lanczos），下采样要**平滑抗混叠**（Area/Mitchell）。
用一个核兼顾两者是妥协。

**建议**：按 `scale > 1` / `scale < 1` 分别选核。改动小，收益明确。

### P4：路径②的固定 6×6（低优先）

正常流程不触发（路径①已归一到 1:1）。但在全景/极端缩放下会混叠。

**建议**：加 scale-aware 支撑；或确保路径①总是先归一到目标尺寸。

### P5：可考虑的更高级方案（视频适用）

| 方案 | 说明 | 风险 |
|---|---|---|
| **EWA Lanczos（`ewa_lanczos`）** | 2D 椭圆加权，比可分离更少振铃 | 成本高，需重写 shader |
| **SSIM 优化下采样** | mpv 的 `--scale-down` 默认思路 | 需调参 |
| **RTX VSR** | 3FP **已支持**（docs/28），张量核超分 | 仅 N 卡、仅 360p–1440p 输入 |
| **FSR 1.0 EASU + RCAS** | 跨平台、单帧、无需运动矢量 | 需新 shader；锐化可能过冲 |
