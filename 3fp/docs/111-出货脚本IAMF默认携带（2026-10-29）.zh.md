# 出货脚本 IAMF 默认携带（2026-10-29）

- 用户指令：「更新一下出货脚本，给默认携带上 IAMF」。
- 结论：三条出货路径中，**单文件早已默认携带（`e010857`）**；本轮补齐**散装发布**与**3FC 出货构建**两处缺口，两臂端到端验证通过。

## 一、改动清单

| 脚本 | 原状 | 改后 | commit |
|---|---|---|---|
| `3fp/kernel/tools/发布3FP单文件.ps1` | 已默认携带（`e010857`：前置校验 + `FFF_FORCE_LIBIAMF` + `-SkipIamf`） | **未改** | — |
| `3fp/kernel/tools/发布3FP.ps1`（散装） | 裸 MSBuild，零 IAMF 强制 | 新增 `-SkipIamf`；默认前置校验 `libiamf/{include/IAMF_decoder.h, lib/x64/iamf.lib}`（缺料即抛错）；内核构建传 `/p:FFF_FORCE_LIBIAMF=true` | kernel `99e1bb8` |
| `tools/构建全部.ps1`（3FC 出货 [3/4] 步） | 裸 MSBuild，零 IAMF 强制 | 同上 + **构建后按导出串实测 `IAMF_decoder_open`**（缺则红标「能力被摘除」） | 根仓 `b63beb9` |
| `3fp/kernel/tools/发布3FR单文件.ps1`（Recorder） | 无 IAMF 逻辑 | **有意不动**：录制器不播音频，强制携带 = 净增 ~4.35 MB 无用解码器，与上游发布形态一致 | — |

三处统一的设计口径：**缺料即报错，不让 `HaveLibiamf` 的自动探测静默降级成无 IAMF 内核**；放弃需显式 `-SkipIamf`（此时显式传 `HaveLibiamf=false`，不留"以为带了其实没带"的模糊态）。

`构建全部.ps1` 多一道「实测」的理由：`FFF_FORCE_LIBIAMF` 只保证*构建必须带*，不证明*产物里真有*——而 `发布门禁.ps1` [2/11] 记录的历史事故形状恰恰是「某配置缺 `FFF_WITH_LIBIAMF` ⇒ 出货版完全没有 IAMF，而验证全跑在另一配置上所以全绿」。

## 二、验证（实跑，非推演）

1. **语法**：两脚本 `[Parser]::ParseFile` 均 OK。
2. **门禁正/负控制**：`IAMF_decoder_open` 串判据在带 IAMF 内核（5,623,296 B）命中、在 SkipIamf 臂内核（1,057,792 B）不命中 ⇒ 门禁有牙齿。
3. **前置校验两臂**：`third_party/libiamf/include/IAMF_decoder.h` 与 `lib/x64/iamf.lib` 均实报 `True`。
4. **端到端两臂**（`发布3FP.ps1`，Release，输出到 `3fp/build/imgperf/`）：

| 臂 | 退出码 | 文件数/体积 | 产物内核 | `IAMF_decoder_open` |
|---|---:|---|---|---|
| 默认（携带 IAMF） | **0** | 39 件 / 116.8 MB | 5,623,296 B | **True** |
| `-SkipIamf`（退出口） | **0** | 39 件 / 112.4 MB | 1,058,816 B | False |
| 差 | — | 4.4 MB | 4,564,480 B | — |

5. 两臂 API 版本四重校验均绿（内核=20 / 宿主发送=20 / 宿主校验=20 / 工程声明=20），配置字段 22=22，许可文本 15/15 入包。

## 三、过程中发现的既有问题（与本次改动无关）

1. **本机 FFmpeg 是 nonfree 变体**：`发布3FP.ps1` 的既有变体门禁首轮判红（`swresample-7.dll` / `swscale-10.dll` 命中 `--enable-nonfree`，`--prefix=/home/dominic/ffmpeg-ly`）。首次跑默认臂**就是挂在这里**（`PUBLISH_EXIT=1`），与 IAMF 改动无关；本轮验证用 `FFF_ALLOW_NONFREE=1` 显式放行。要发到 public 通道，得换 lgpl-shared 构建或把清单 §1 的 GPL 文本/源码要约补齐。
2. **kernel 仓库被其他会话改动**：先前出现的 `f4a0e61`（外部色彩变换 kind=3 注入回归）已不在任何分支头上；本轮改动已即时提交为 `99e1bb8` 保护起来。另：根仓 `tools/构建全部.ps1` 的 CRLF 在 commit 时会被 git 转成 LF（`warning: in the working copy ... CRLF will be replaced by LF`），属仓库既有换行策略，未做额外处理。
3. **试验构建子任务无痕**：`rel_tfmnorm` 空、无报告、`trial/tfm-normalize` 分支不存在 —— 该子任务早段即失败（回执未到），与本次改动无关，待重派。
