# 88 · RTX VSR「自动模式」现状分析与交接（2026-10-11）

> 对象：3fp 内核工作树（HEAD `782736e`，`feature/vsr-and-rotation` 分支，`a44cbda` merge upstream/master 后）。
> 性质：**只读核查**，未改动任何文件。
> 背景：用户问「3FP 目前的自动 RTX VSR 是否正常」。
> 方法：逐行实读内核 `VideoRenderer.cpp` / `PlayerSession.cpp` / `Api.h`，并交叉核对 `docs/28-33`、`docs/51`、`_3fp-fix/allreview/lane5` / `lane7`、`patches/kernel-followup-pr-2026-10-09.md`。

## 0. 一句话结论

**「自动 RTX VSR」在成品链路上从未被开启——不是坏了，是休眠。** 内核侧门控自洽、探针实测曾通过；但有一批已登记未修的 P1/P2 缺陷，且本机 NVIDIA App 的 VSR 当前是关闭的，真实生效从未被验证。

---

## 1. 核心发现（决定性问题）

| # | 发现 | 证据 |
|---|---|---|
| **F1** | `requestedVideoSuperResolution_` 默认 **Off**，枚举仅 `Off/Auto` 两档 | `VideoRenderer.h:610-611`；`FFF.Player.Api.h:533-537` |
| **F2** | **没有任何宿主请求 VSR**：3FCompare(C#)、FFF.Player(VB)、LakeUI 都未绑定 `FFF3FP_SetVideoSuperResolution`。全仓调用者只有 `PlayerApi.cpp` 导出 + `3fp/tools/` 三个探针 | 全仓 grep `FFF3FP_SetVideoSuperResolution`（排除 dumps/quarantine） |
| **F3** | 托管侧（`Fff3FpEngine.cs` / `Fff3FpNative.cs`）绑定清单中无 VSR 入口，无 UI/设置项 | `src/3FCompare.Core/Backend/Interop/Fff3FpNative.cs` 的 `FFF3FP_Set*` 列表 |

⇒ F1+F2+F3 ⇒ 3FCompare 实际播放时 VSR 永远走 `Off` 路径；只有跑 `vsr_probe.exe` 等探针才激活。**“自动 VSR”处于休眠而非故障。**

---

## 2. 内核侧实现：自洽且有历史实测背书

- 门控链完整：`Off → 非N卡 → 源格式 → 非放大 → 源高度∉[360,1440] → 驱动曾拒绝`；每条提前返回经 `skip()` 清 `active`（`VideoRenderer.cpp:3250-3269`），防状态粘连。
- 对比模式互斥正确：`SetComparisonMode(true)` 强制关 VSR，`Auto` 在对比模式下被拒 `InvalidState`（`PlayerSession.cpp:2009, 2017-2033`）。
- 历史实测（docs/31-33、51，需配合硬解+放大窗口）：
  - SDR/HDR10/scRGB(16bit) 三路 `active=1` + 像素级差异证实 AI 超分真实工作；
  - 非放大/4K源/软解 正确拒绝；VSR 输出作为源再走着色器 HDR 管线，色彩/曝光无系统性偏移。
- ABI 未破坏：同期 `PlayerApiVersion` 仍为 16（docs/32、33 验收项）。

## 3. 已登记、当前源码仍存在的缺陷（需交接）

基于 lane5/lane7 复核（上游 `4878da0`），本次对照现网 HEAD 逐条核实，**以下全部仍成立**：

| 级别 | 问题 | 证据（现网行号） | 影响 |
|---|---|---|---|
| **P1** | VSR **不感知视图旋转**：`destination` 是交换轴+zoom 后的目的盒（`5893-5896`→`5956`），VP 输入几何却用未旋转的 `sourceWidth_/Height_`（`3326-3327`） | `3217-3393` 通篇无 `viewRotation_` | 旋转 90/270 视图下画面被 `(h/w)²` 量级拉伸 |
| P2 | `active=1` 仅代表 `VideoProcessorBlt` 成功，**无能力确认查询**；NVIDIA App 关 VSR 时 blit 仍成功 → 状态块可能谎报 | `3386-3392`；`NvidiaVideoExtensions.h` 声明 Set/Get 却只 Set | UI/断言不可信 |
| P2 | `ShouldEnableNvidiaSuperResolution`（3160-3175）**零调用者**，与 `ApplySuperResolution` 内联门（3256-3269）构成两套已漂移判定 | 全仓仅声明+定义 | 死代码 / 双门不同步 |
| P2 | 每次 `Set(Auto)` 清闩锁（`6610-6611`），与 reject 注释 "latch off permanently"（`3219-3221`）矛盾 | — | 失效帧可无限重试 |
| P2 | 每帧重建 `VideoProcessorEnumerator`/`Processor`/输入输出视图（3317-3379），仅中间面缓存 | — | AI 上采样路径隐性开销 |
| P2 | 奇数目的盒取偶表面后注释称“多出行列不显示”不成立：`PrepareScaledVideo` 按奇数 `outputWidth/Height` 采样整面（4031-4032） | `3274-3275` vs `4031-4032` | `(w+1)/w` 轻微拉伸 |
| P2 | 自适应降采样（默认关）启用时 `sourceWidth_/Height_` 被折成上传/目的盒尺寸（`5180-5191, 5268-5278`→`3116`）→ VSR 放大判定与 360-1440 区间判的是**窗口**而非内容；降采样纹理无 `BIND_DECODER` → 静默拒绝且 `skip()` 无日志 | `CanUseVideoProcessorForUpscale:3137-3158` | 降采样模式下 VSR 实质失效 |
| P2 | `skip()` 只写状态不写日志；`nvidiaAdapter_`/`videoSuperResolutionRejected_`/`*Width_Height_` 为普通成员，呈现线程写、API 线程无锁读 | `1962-1967`(Session)、`6629-6642`(Fill) | 数据竞争 / 静默失效 |
| P2 | `ShouldEnableNvidiaSuperResolution` 注释宣称“遵循官方 360p..1440p”，但判据用 `sourceHeight_`（3266），而该值会被自适应降采样改写为窗口高度（见上） | `3160-3174` | 区间判定语义失真 |

## 5. 交接清单（给后续接手者）

### 5.1 若目标是「让 3FCompare 自动用上 VSR」
1. **补托管侧接线**（阻塞项，F2/F3）：`Fff3FpNative.cs` 加 `FFF3FP_SetVideoSuperResolution` P/Invoke → `Fff3FpEngine.cs` 加方法 → UI 设置项（默认仍 Off，对比/剪辑模式强制互斥）。UI 措辞用「已请求 / VP 通路中」，不要写「已生效 ✓」（业界共识：已请求≠已生效，MPC-HC #3684）。
2. **先修 P1 旋转几何**再默认开启，否则旋转看片必错比例。
3. 可选清理：删 `ShouldEnableNvidiaSuperResolution` 或让 `ApplySuperResolution` 改调它，消双门。

### 5.2 若目标只是确认现状
- 现状即「休眠且安全」：`Off` 时渲染路径逐字节不变（docs/33 §5 回归验证通过），对比模式双保险互斥，无需动作。

### 5.3 验证复现命令（来自 docs/33 §8、51 §附）
```powershell
cd C:\PLAN\3FCompare\3fp
& 'C:\Users\20210\AppData\Local\Programs\Python\Python312\python.exe' tools/build_kernel_manual.py
cd build
.\vsr_probe.exe <素材> --auto --sr-window 2560x1440 --seconds 8          # 状态
.\vsr_pixel_probe.exe <素材> --sr-window 2560x1440                        # SDR 像素差异
.\vsr_scrgb_probe.exe <HDR素材> --sr-window 2560x1440                     # scRGB 像素差异（需系统 HDR 开）
```
⚠ 必须 `--sr-window` 大于源分辨率才会触发；`--auto` 经 `Set(Auto)`。
