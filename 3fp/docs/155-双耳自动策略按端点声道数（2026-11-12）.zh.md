# 双耳自动策略改为按端点声道数：2 声道默认激活 HRTF、多声道回退传统（2026-11-12）

## 一、需求（用户裁定，同日两次纠正后落定）

1. **HRTF 实现路径不唯一**：授权模块的床渲染是一条；IAMF 等公开标准自带 HRTF 相关渲染（无需授权）。徽章/策略不应把"HRTF"绑死在授权模块上。
2. **默认语义**：HRTF 在**输出为 2 声道**时默认激活；**多声道输出回退传统多声道**。旧规则按端点形态（3=Headphones/5=Headset）判定 ⇒ 本机/用户的 USB DAC 被 Windows 报成 9（DigitalAudioDisplayDevice，mix 实为 2 声道），自动永远不激活——这正是用户截图里"端点形态 9 需要手动强制"的根因。

## 二、内核改动（3 文件，零 ABI/零导出变化）

| 文件 | 改动 |
|---|---|
| `Audio\WasapiRenderer.h` | 删 `IsHeadphoneEndpointFormFactor`；`BinauralWantedFor(policy, formFactor)` → **`BinauralWantedFor(policy, endpointChannels)`**：auto ⇔ `endpointChannels == 2`，强制双耳/强制立体声照旧压过；头注释写明产品裁定日期与理由（形态 9 的 USB DAC mix 实为立体声，声道数才是渲染器真正打开的格式） |
| `Audio\WasapiRenderer.cpp` | `BinauralWanted()` 传 `outputChannels_`（= 打开设备时的 mix 声道数，与 `runtimeState_.endpointChannels` 同源）；`SelectBedRoute` 注释改写（多声道先返回 Native 的闸门保留——强制双耳在多声道端点依旧不接管） |
| `Core\PlayerSession.cpp` | `GetAudioBinauralStatus` 的 `wanted` 改用 `endpointChannels`；`formFactor` 照旧回读（宿主 `折算双耳策略` 的强制持久化仍按形态记录，不受影响） |

语义表（auto）：

| 端点 mix | 旧行为（形态 3/5） | 新行为（声道数=2） |
|---|---|---|
| 2 声道（耳机/耳麦/USB DAC/立体声设备） | 仅形态 3/5 激活 | **默认激活 HRTF**（有授权渲染器时床走接缝；渲染器不在场则如实折叠） |
| 多声道（5.1/7.1/HDMI） | 不激活 | 不激活（传统多声道折叠）——回退语义不变 |

## 三、验证

- **内核构建**：0 警告 0 错误；新 DLL **6,528,000 B / sha16 `74DF07F5CC62AA66`**（`3fp/build` + 宿主 bin 已同步）；`check_kernel_exports` **结论 OK**（REQUIRED 38、API 20、无重名）——零导出/零快照/零版本变化。
- **探针重建重跑**（`audio_binaural_probe`，出货头文件 inline 规则编进探针）：**21/21 PASS、exit 0**。关键读数：
  - `auto: stereo endpoint on, multichannel off` / `force-binaural ignores the channel count` / `force-stereo overrides even a stereo endpoint` / `unknown channel count => fold-down`；
  - **live：`opened: policy=auto(0) formFactor=9 wanted=1 available=0`**——本机（形态 9、mix 2 声道）自动档首次 `wanted=1`；`available=0` 如实反映授权渲染器不在场（床仍折叠，徽章显示立体声=真值）；
  - `kernel formFactor == 独立 MMDevice 查询`（9=9）与 `auto policy derives from the channel count (wanted=1 expected=1, mix 2)` 双锚点一致。
- **GUI 冒烟**：新内核 + 宿主启动 300s 5.1 素材，徽章"立体声"、播放正常、无崩溃。

## 四、边界与澄清（对 docs/154 §六 的更正）

- HRTF 的**接缝、策略、路由、回读、徽章**是本体功能；**渲染实现与授权在模块**（`FFF.HDRdp.Test.dll` 经 `FFF_GetAudioRenderApi` 函数表交内核，头文件契约原文"needs authorization to write, so it does not belong in the body"）。§六 中"HRTF 模块"的说法不准确，应为"授权床渲染实现（模块函数表）"。
- "多实现路径"：徽章按**谁真接管显示谁**设计（`音频双耳渲染生效`=接缝路径真值）。当前快照里只有接缝路径发布真值；IAMF 声场映射（`原生IAMF声场系统`）全是扬声器布局、libiamf 无双耳输出值 ⇒ IAMF 自带双耳属未来路径，落地时应有自己的真值来源，不在本轮伪造。
- 本机 `FFF.HDRdp.Test.dll` **不在场**（bin 目录无此文件，"缺席是常态而非错误"）⇒ 双耳真接管仍无法实测；新规则让"模块在场+2 声道端点"的机器**默认激活**，无需手动强制。
