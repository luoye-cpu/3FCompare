## 二、缺陷总表

### P0 详述

**P0-2 门禁测的不是发货形态**（`发布门禁.ps1:52,292`）
实测门禁构建并自测的是 `bin\Release\net11.0-windows\3FCompare.exe`（74KB apphost + 58 文件 + `deps.json`/`runtimeconfig.json` ⇒ IL/JIT），而发货物由 `pack.ps1:431-441` 产出为 AOT 单文件 33MB。AOT 特有的裁剪掉反射依赖、`Marshal` 封送差异等问题，门禁**一个也看不见**。唯一覆盖 AOT 的是 `pack.ps1:356-377` 的包内自测，但它可被 `-SkipPackageSelfTest` 跳过，且仅 `-WithPack` 触发。

**P0-3 [6/10] 恒绿**（`发布门禁.ps1:337-345`）
```

if ($firstReal) { $firstReal.FullName } else { $SmokeProject }   # ← 缺素材时传 csproj
```

**P0-4 HDR 回读转换未接线**
`src/3FCompare.Core/Imaging/ColorNormalizer.cs` 实现了 scRGB→线性光域的完整转换（含 8/10/16 位、PQ、paper-white），单测覆盖充分（`ColorNormalizerTests.cs` 170+ 行）。但全仓 grep 显示**生产侧零调用** —— 消费点仍是 `v*255` 截断（`ProbePanel.cs:123`、`MagnifierOverlay.cs:325`）。这是「测试全绿、功能没接」的典型形态。

**P0-5 探针断言无牙**（`MainWindow.SelfTest.cs:1083,1096-1101,1107`）
以 `media.VideoWidth*0.25` 比 `MapFallback`，容差 ±2px；无表面/媒体即"跳过"、letterbox 即"跳过"，**跳过不判红**。⇒ 门禁必须与 4K 素材绑定，任何换素材的行为都会翻转结论。

### P0-5 根因校正

题述的 ±2px 假红其实在**第二处**判据（原 `:1149-1167`），不在 `:1096-1101`。`+0.5` 出自 `PixelReadback.cs:42` 的 `(srcX+0.5)*DestWidth/videoWidth`，折合缓冲像素幅度 = `0.5×DestWidth/videoWidth`，随放大倍率线性增长：320×180 放到 1920 宽 = 3px > 2 ⇒ 必红；4K 缩到 1920 = 0.25px ⇒ 稳过。而 `:1096-1101` 的期望值 `(int)(vw*0.25)` 与实现是同一表达式（0.25 是 2 的幂，IEEE 精确），偏差恒 0、±2px 永远用不满，且单点取样挡不住"退化成常量"。

新判据：① 兜底映射取 1/4、3/4 **两点**（零容差 + 跨度 ≤1 源像素）；② 主路径探针点改取 dest 矩形中心，期望值用同一套像素中心约定，阈值 `<1.0` 缓冲像素（floor 量化上界）。跳过分支：无表面/媒体 ⇒ 判红；演示模式无该接口 ⇒ 走 `RecordSelfTestSkip` + 收尾打印"未验证 ≠ 通过"。
