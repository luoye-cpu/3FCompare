## 一、必须修（P0：会让构建错误地成功 / 在本机直接跑不起来）

### 1. `tools/构建全部.ps1:250` 在本机必然失败
```powershell
dotnet build .\src\3FCompare.slnx -c $Configuration --nologo
```
缺 `--no-restore`，且**全脚本没有 APPDATA 兜底**。而本机 `dotnet restore` 全域失败
（沙箱 `APPDATA` 为空 → NuGet `Path.Combine(null)`），restore 必挂。
讽刺的是这恰恰是「构建全部」脚本——本次修复的核心产物之一自己跑不通。

**修**：照抄 `发布门禁.ps1:30-33` 的 APPDATA 兜底；所有 dotnet 调用加 `--no-restore`。

### 2. `tools/构建全部.ps1:246` `-SkipTests` 会连主程序一起跳过，却仍报成功
```powershell
if (-not $SkipTests) {
    ... dotnet build .\src\3FCompare.slnx ...   # ← 主程序构建被塞在这里
    ...
}
Write-Host "✔ 全部完成"
```
`-SkipTests` 时 3FCompare.exe 根本没生成，脚本照样打印成功。**修**：拆成独立步骤，或改名 `-SkipManaged`。

### 3. `pack.ps1` 缺 UTF-8 BOM
首字节 `23 20 33`（无 BOM），而 `tools/` 下三个脚本都是 `efbbbf`。
PowerShell 5.1 无 BOM 按 ANSI(GBK) 解码 → 中文全乱码。本文件里有
`$ReadmePath = "$OutputDir\使用说明.txt"` 和整段中文说明文本，会写出乱码文件名 + 损坏内容。
（注：HEAD 版本同样无 BOM，属历史遗留；但本次改动了它，顺手补上。）
**修**：以 UTF-8 BOM 重新保存。

## 二、应该修（P1：静默用错东西 / 自检被绕过）

### 4. `KernelConfiguration` 与 `-Configuration` 不匹配
- `3FCompare.csproj:44` 默认 `KernelConfiguration = Release`
- `构建全部.ps1:231` 内核产物落在 `x64\$Configuration`
- 脚本从不传 `-p:KernelConfiguration`

→ `构建全部.ps1 -Configuration Debug` 必然被 `CheckKernelDll` 拦下（找 `x64\Release`）。
**修**：脚本透传 `-p:KernelConfiguration=$Configuration`。

### 5. `pack.ps1:231` `-NoCompress` 提前 `return` 绕过全部自检
`return` 在第 231 行，`Assert-Package` 在第 258 行——exe / 版本号 / FFmpeg 校验整段被跳过。
**修**：把 `Assert-Package` 提到 `return` 之前。

### 6. `构建全部.ps1:148` HEAD == 基线时无条件跳过补丁，无校验
仅凭注释假定「扩展已内置」。若基线提交实际不含扩展（分支被重置 / 克隆到同名 SHA），
就静默产出缺能力的包——与本次要根治的「可能用错内核却显示成功」是同一类风险，只是方向相反。
**修**：跳过前对每个 patch 跑一次 `git apply -R --check`，「未应用」则报警而非静默跳过。

### 7. `-AllowKernelDrift` 与「内核工作区脏」只 `Write-Warning` 后继续
DLL 照常部署到 `bin\Release`，下游 `pack.ps1` / 门禁都不再校验内核 SHA → 脏内核可直接进发布包。
**修**：drift 时把实际 SHA 写入 `.3fc_kernel_sha`，`发布门禁.ps1` 增加第 7 项检查「内核 SHA == 基线」。

### 8. `构建全部.ps1:41` `Invoke-Git` 用裸 `git`
若 git 不在 PowerShell PATH，`$LASTEXITCODE` 会沿用上一次原生命令的**旧值**，可能拿到 0 → 误判成功。
**修**：照 `发布门禁.ps1:36` 的 `Resolve-Tool` 解析绝对路径，缺失即 `throw`。

## 三、代码层（C#）

### 9. `SyncController.ForEachSlot` 丢掉了路号（诊断能力回退）
原：`ReportRuntimeError($"播放第 {i} 路", ex)`；现：`ReportRuntimeError($"{actionName}会话", ex)`。
统一执行器是好事，但把索引丢了——多路对比下某一路挂掉时无法定位是哪一路。
**修**：`ForEachSlot` 改用带索引的 `for` 循环。

### 10. `LanguageManager.SubscribeWeak` 只让回调失效，不移除订阅
目标被回收后，delegate 与其闭包**永久留在静态事件的调用列表里**。
窗口反复开关会缓慢累积（单个对象很小，但与注释宣称的「自动失效」有落差）。
**修**：invoke 时顺带剪除已死条目（维护 `List<WeakReference>` + 定期 prune）。

### 11. 启动期会多写一次用户配置
ctor 中 `SetCollapsed(恢复值)` 触发 `CollapsedChanged` → `OnSidebarCollapsedChanged` → `SettingsStore.Save`。
每次启动白白落盘一次。**修**：加 `_restoringSidebar` 标志位跳过。

### 12. `AutoCollapseSidebar` 可能在布局前误触发
`BoundsProperty` 变更时若 `Bounds.Width == 0`（布局未完成）会判定为 narrow 并折叠，随后再展开 → 可见抖动。
**修**：`if (Bounds.Width <= 0) return;`
