## 2. 已定位并修复：退出期 CLR 反向 P/Invoke 断言

### 现象

自测明明打印 `全部通过 ✓`，进程却以 **127** 退出，并报：

```
CLR: Assert failure: !"Attempt to execute managed code after the .NET runtime
     thread state has been destroyed."
    File: ...\coreclr\vm\ceemain.cpp:1750
```

### 根因

托管侧把两个委托交给了原生层：内核**事件回调**（`Fff3FpSession._callback`，函数指针经
`Fff3FPConfiguration.EventCallback` 传入）与**日志回调**（`KernelLogBridge`）。
内核工作线程的生命周期长于托管侧，`Environment.Exit` 后 CLR 进入停机，这些线程仍会
反向 P/Invoke 回调托管委托 → 撞上已销毁的运行时。

自测路径本来还**绕过了 `OnClosing`**（直接 `Environment.Exit`），会话与子 HWND 都没销毁。

### 修复

1. `MainWindow.DestroyAllSessions()`：Dispose 全部会话 + `_coordinator.Close()` + `_sync.Clear()`，
   并接入 `OnClosing`（此前 `OnClosing` 只置标志，不销毁会话）。
2. `KernelLogBridge.Uninstall()`：退出前注销内核日志 sink。
   P/Invoke 形参由委托类型改为 `nint`，以便传空函数指针（委托类型传 `null` 会抛）。
3. `AppDomain.CurrentDomain.ProcessExit` 兜底钩子：`Uninstall` + `AppLog.Shutdown`。
4. 自测统一退出口 `MainWindow.ExitSelfTest(code)`：清理链 → 关闭窗口并 `RunJobs()` 让
   Avalonia 真正销毁子 HWND → 静默期 → 显式 flush → **`TerminateProcess`** 终止。

### 为什么用 `TerminateProcess` 而不是 `Environment.Exit` / `ExitProcess`

- `Environment.Exit` 走完整托管停机，原生线程有机会回调已销毁的 CLR —— 断言依旧（实测 4/6 复现）。
- `ExitProcess` 会依次执行所有 DLL 的 `DLL_PROCESS_DETACH`，**实测在 FFF.Native / D3D11 上死锁挂住**
  （进程 10 分钟不退出）。
- `TerminateProcess` 不跑 DLL detach、不跑托管停机，且可指定退出码。
  日志与控制台已在终止前显式 flush，无数据丢失。

### 验证

真实 4K 素材（`real_4k_h264_60m.mp4`）单路 selftest 连续 4 轮：`exit=0`，无断言，退出码可信。
`_selfTestMode` 守卫使自测不再把测试窗口几何写进 `settings.json`。

## 3. 未修复（既有缺陷）：多路播放真实 4K 高概率崩溃（SIGSEGV / SIGILL）

- 现象：`--multitest <真实 4K> 4 10` 在"静置播放"阶段 SIGSEGV / SIGILL，进程直接死。
  Windows 下退出码为 **`0xC0000005`**（ACCESS_VIOLATION）与 **`0xC000001D`**（ILLEGAL_INSTRUCTION）；
  Git Bash 下显示为 139 / 132。
- **与硬件解码无关**：`HardwareDecode` 设 `true` 与 `false` 均崩溃（软解下甚至出现 SIGILL）。
- 与素材规格强相关：合成素材下"偶发"，换真实 4K 素材后**崩溃率大幅上升**。
  此前基于合成素材得出的"与硬件解码相关"结论是误判。
- 单路 selftest 在同样素材上稳定通过 → 问题出在**多路并发**的解码/呈现路径。
- 属 FFF.Native 原生层缺陷，需带符号转储（dump）在原生侧继续定位。

> **2026-09-16 复测量化**（2 路 4K，`--multitest`）：
> 20 s 预算 3 次 = **1 通过 / 2 崩溃**；25 s 预算 2 次 = **0 通过 / 2 崩溃**。
> 出现 `0xC000001D`（SIGILL）—— **托管 C# 不可能产生非法指令**，必在原生内核/D3D 路径。
> ⇒ 标题由"必现"改为**高概率**：并非每次都崩，但短预算（20 s）内也会崩，
> **与接近片尾无关**，是播放时长累积的概率性崩溃，别指望靠缩短时长绕过。
> 根因已归因到 `dxgi.dll`（详见 `docs/upstream/issue-多路播放崩溃-*`）。
