# 32 · 系统蓝屏归因分析（2026-09-19）

> 结论先行：**本次系统崩溃与 3FCompare 项目无关**，是本机内核驱动层面的稳定性问题。
> 当天共 3 次蓝屏，涉及**两个互不相干**的第三方内核驱动，其中 2 次发生在 3FCompare 完全没有运行时。

---

## 一、事件事实（全部来自实测，非推断）

| 时间 | 事件 | 证据 |
|---|---|---|
| 06:40 / 06:47 | 蓝屏 `0x3B` | Event 41 + 6008 + WER 1001，转储 `Minidump/091926-20187-01.dmp` |
| 06:55 | 蓝屏 `0x3B` | 转储 `091926-17125-01.dmp` |
| 18:38:21 | 蓝屏 `0x3B` | Kernel-Power 41；WER 1001：`0x0000003b (0xc0000005, 0xfffff8026f9dc1e3, 0xffffdc00c2bf59c0, 0)`；转储 `091926-18984-01.dmp` |
| 18:40:25 | 重启完成 | 系统启动期服务事件 |

`0x3B` = `SYSTEM_SERVICE_EXCEPTION`，参数 1 = `0xc0000005`（访问违例）。

## 二、归因：WER 桶直接点名故障驱动

Windows 错误报告对三次蓝屏各自给出了 `Response.BucketId`：

| 时间 | WER 桶 | 含义 |
|---|---|---|
| 06:47 | `AV_eaanticheat!DriverEntry` | **EA 反作弊内核驱动**在 DriverEntry 阶段访问违例 |
| 06:55 | `AV_eaanticheat!DriverEntry` | 同上 |
| 18:38 | `AV_nvlddmkm!_mapInsertFixup` | **NVIDIA 显卡内核驱动**内部访问违例 |

`eaanticheat.sys` 是 EA 游戏反作弊组件，其 `DriverEntry` 崩溃发生在驱动加载期，**与任何用户态应用无关**。

NVIDIA 驱动版本：**32.0.16.1692（2026/9/4）**，设备 `RTX 5080` + `RTX 4060 Laptop GPU`。OS `10.0.26200.9457`。

## 三、为什么排除「当前任务」是根因

1. **早晨两次蓝屏时 3FCompare 根本没运行。**
   `logs/app-2026-09-19.log` 当天第一条会话记录是 `10:15:31`，06:40 / 06:47 / 06:55 三个时点均无任何进程记录。

2. **18:38 那次，应用处于空载启动态。**
   最后一次会话 `18:36:28` 启动，`args=[]`（未加载任何媒体），日志显示仅创建 2 个 `PlayerSurface` 后即**无"会话结束"记录**——是被蓝屏打断的。
   即：没有多路解码、没有 4K 播放、没有放大、没有 WGC 抓屏，只有两个空白渲染表面。

3. **本项目的崩溃是"进程级"，与蓝屏是"系统级"，层级不同。**
   3FCompare 的历史崩溃是**用户态** `dxgi.dll` 访问违例（WER `AppCrash_3FCompare.exe`），表现为**单个进程退出**，不会拖垮内核。当天 16:01–18:24 确有多次此类进程崩溃（既有问题，见 `docs/26`），但它们与 18:38 的系统重启没有因果链。

4. **工作区完好**：`git fsck --no-progress` 输出为空（健康）；源码最后编辑 18:23，18:35/18:36 三次启动均正常退出；崩溃后重建 `0 错误`、Core 427 / Platform 248 全通过。

## 四、诚实的不确定性

- **不能完全排除"我们的 GPU 负载曾触发 nvlddmkm 的既有缺陷"**。3FCompare 会做 4 路 4K 渲染、最大 100 Mpx 放大等高负载操作，这类负载是显卡驱动 bug 的常见触发面。但 18:38 这次发生在空载状态，因此**至少本次不是**该情形。
- **18:38 的 nvlddmkm 崩溃与早晨的 eaanticheat 崩溃是不同驱动**，说明这台机器存在**多个**不稳定的内核组件，属系统性问题而非单一诱因。
- RTSS / Afterburner（RTSSHooks64.dll）与 NVIDIA ShadowPlay（nvspcap64.dll）仍注入进程，它们与多路 Present 的交互此前也未能排除（`docs/26 §16.4`）。

## 五、建议（用户侧，非本项目代码改动）

1. **优先处理 EA 反作弊驱动**：早晨连续两次在同一驱动的 `DriverEntry` 崩溃，这是最容易造成"开机即蓝"的组件；若不玩相关游戏，建议卸载其内核组件或更新 EA 相关软件。
2. **显卡驱动回退/更新**：`32.0.16.1692` 出现 `nvlddmkm` 内核态访问违例，建议回退到上一个稳定版本观察（或升级到更新的分支）。
3. 若需进一步定性，可在关闭 RTSS / Afterburner 后复测多路播放。
4. 排查期间建议**减少高负载 GPU 测试**（4 路 4K、大倍率放大），既降低触发概率，也避免崩溃掩盖真正的回归信号。

## 六、本次取证方法（可复用）

无 WinDbg 环境下定位蓝屏故障驱动的三步法：

1. `Get-WinEvent -FilterHashtable @{LogName='System'; Id=41,6008,1001}` —— 拿到 bugcheck 码与四个参数。
2. 读 `C:\ProgramData\Microsoft\Windows\WER\ReportArchive\Kernel_<code>_*\Report.wer`，取 **`Response.BucketId`** —— WER 已完成在线分析，直接给出 `模块!函数`。这是最快路径。
3. 转储文件是 `PAGEDU64`（内核转储，非 minidump），无调试器时可用 Python 解析；但本例第 2 步已足够，未再深挖。
