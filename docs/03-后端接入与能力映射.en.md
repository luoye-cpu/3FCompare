## 1. Integration Form Decision

3FP has two interface layers:

- **Native C API**: the `FFF3FP_*` series (`FFF.Native/3FP/Api/FFF.Player.Api.h`, current version 10),
  for C/C++/P/Invoke callers.
- **Managed kernel**: the `FFF.Player` assembly (`player session`, `player controller`, etc., .NET 11, VB.NET),
  which internally wraps the Native calls and provides event sync, cancellation, and exception-based error handling.

**This project's integration approach (decided): develop directly on the `FFF.Native` source (MIT license confirmed).**

Core reasons:

1. `LICENSE.txt` is MIT (author confirmed valid) — freely modifiable / redistributable / commercial use;
2. We need capabilities the upstream doesn't currently expose: **VRR swap chain / viewport sub-region / full-frame readback** — only by modifying the kernel can we get them;
3. Rather than treating the `FFF.Player` managed assembly as a black box (constrained by its API and event semantics), we ship a very thin interop layer and fully control the ABI and extension APIs.

> The managed `FFF.Player` can serve as a reference implementation: its event model, error handling, and the `player session` threading discipline are worth borrowing, but we don't depend on its assembly.**

## 3. Core API Quick Reference (shapes exposed by the managed controller)

> Below is organized from `FFF.Player.Api.h`/interop layer into the semantics this project needs; **final signatures take the referenced assembly as authoritative.**

### 3.1 Session Lifecycle

| Needed capability | 3FP counterpart | Notes |
| --- | --- | --- |
| Create session | `player config` (output window, decoder, color mode, SDR/HDR peak, audio endpoint, event sync context) + `player session` | each stream's `output window` = that stream's PlayerSurface.HWND |
| Open/close | `OpenAsync(path)` (cancelable) / `Dispose` | use async to avoid UI stalls |
| State | `current snapshot.state` (Idle/Opening/Ready/Playing/Paused/Ended/Failed/Closed) | |
| Error | `last error message` / `player exception` | uniformly surfaced to UI as notices |

### 3.2 Playback Control

| Operation | 3FP |
| --- | --- |
| Play/pause/stop | `play()`/`pause()`/`stop()` |
| Mute/volume | `SetVolume(volume, muted)` |
| Seek (time) | `Seek(position100ns)` |
| Seek keyframe | `SeekKeyframe(position100ns)` |
| Seek by frame | `SeekFrame(frameIndex)` |
| Step | `StepFrame(direction±1)` / `StepKeyframe(direction)` |
| Stream selection | `SelectVideoStream(index)` / `SelectAudioStream(index)` |

### 3.3 Diagnostics/Reads (safe for high-frequency polling)

| Data | 3FP snapshot fields (key points) | Used by |
| --- | --- | --- |
| playback position/duration | `position100ns` / `duration100ns` | timeline |
| current frame number | `frameIndex` | frame number display / bookmarks |
| raw PTS | `originalFramePTS` + `frameTimebaseNum/Den` | PTS alignment (04) |
| presented/dropped frames | `presentedVideoFrames` etc. | performance diagnostics (optional) |

| audio diagnostics | `audioBuffer100ns`, `audioUnderruns` | optional |
| pixels | `ReadVideoPixel` → `native video pixel probe`(X, Y, RGBA, video scale mode, output bit depth, color mode) | probe |
| subtitle/danmaku status | `GetTimedTextStatus` etc. | (optional) |
| media metadata | `GetMediaInfo` JSON (streams, codec, pixel format, bitrate, etc.) | media panel |

### 3.4 Events

| Event | Purpose |
| --- | --- |
| `StateChanged` | refresh UI state machine |
| `OpenCompleted` | after successful open, fetch media info and build timeline |
| `OperationCompleted` | after step/Seek completes, refresh snapshot display |

| `Error` | show error and mark session Failed |
| `ColorModeChanged` | multi-stream color consistency notice |

## 4. Interop & Data-Flow Notes

1. **UTF-8 pointers/bitmap pinned addresses are only valid during the synchronous call** (the managed interop layer handles pinning);
   any P/Invoke additions we make must follow this contract.
2. **High-frequency `current snapshot` reads are safe**; never access WASAPI objects on the playback thread (we won't).
3. **Player commands are state-sensitive**: inapplicable commands throw `player exception`; orchestration must query snapshot state before issuing commands.
4. **SDR/HDR switching**: current media SDR→HDR requires reconfiguring the swap chain (3FP handles internally);
   when some streams are HDR and the rest SDR, `compare tools` (probe, difference) read from the "pre-color-management buffer",
   so comparison is only semantically consistent under the same `color mode` (e.g. all mapped to SDR BT.709 code values).
5. **Independent HWND per stream**: flip-model swap chains can't coexist on one window; PlayerSurface must not nest.
6. **ACM/wide-gamut**: probe readback (`ReadVideoPixel`) and screenshot paths both use the "pre-color-management" buffer,
   so **consistent video code values can be obtained regardless of whether the display has ACM enabled**; display-side presentation is done by DWM.
7. **VRR**: this software doesn't create "layered windows overlaying other apps" (RTSS-style overlay),
   so VRR only relates to **swap-chain parameters + window Present cadence**; whether it fully takes effect depends on 3FP (see A8/A9).
