# 01 需求分析

## 1. 背景与目标

NVIDIA ICAT（Image Comparison & Analysis Tool）是一款用于画质对比的图形工具：
一次最多加载 4 个视频/图像，支持对齐、帧步进、循环、A-B 滑块、平移缩放等重点区域对比，
被广大编码评测（VCB 等）与游戏画质测试人群使用。

**3FCompare 目标**：做一款同样的视频盯帧软件，但解码/播放内核换用 FFF_Project 的 3FP。
后端能力（帧级步进、按帧 Seek、100ns 级快照、像素探针、多流信息）与 ICAT 的“逐帧对比”工作流天然契合。

**说明**：ICAT 本身由 NVIDIA 开发，不开放源码、无公开插件 API；无法直接复用其代码，
本规划按“对标用户体验 + 独立实现”思路制定。

---

## 2. 用户画像与场景

| 角色 | 诉求 |
| --- | --- |
| 视频编码评测人员（VCB/压制组） | 对比源/各版本压缩差异、定位劣化帧、查看色度/振铃/块效应 |
| 游戏画质 / 光追对比 | 同一画面不同设置下的差异 |
| 视频处理研究者 | 帧级截取、算法参数对比 |

**核心使用场景**：
1. 打开 2~4 个视频，自动对齐时间轴 / 手动设置偏移；
2. 同步逐帧步进（前进/后退）或按帧号跳转；
3. 切换 并排 / 单屏 / A-B 滑动 三种对比视图；
4. 放大镜 / 高缩放平移观察细节；
5. 像素探针（取色读数），记录帧号与时间；
6. 整理出报告（截图、记录）。

## 3. 功能需求总览

### 3.1 视频加载与媒体管理（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F1 | 多路加载 | **1~9 路可变**（最低 1 路，最高 9 路，3x3 网格上限，同时支持 1x1/2x1/2x2/3x2/3x3 等布局）；支持拖拽与文件选择器 |
| F2 | 图像加载 | 静态图片按单帧媒体处理（3FP 已支持静态图按单帧播放） |
| F3 | 媒体信息展示 | 分辨率、帧率、编码、HDR 信息、码率等（来自 3FP `媒体信息` JSON） |
| F4 | 时间轴 | 显示每路/整体时间轴，可拖动 Seek（100ns 精度） |
| F5 | 帧号显示 | 显示当前帧号（快照.帧序号 与 原始帧PTS/时间基）与时间戳 |

### 3.2 同步与播放控制（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F6 | 同步播放/暂停 | 主时钟驱动所有会话（详见 04 同步模型） |
| F7 | 同步帧步进 | 按 PTS 基准对齐步进；无精确 PTS 时回退帧索引基准（设计取舍见 04） |
| F8 | 逐帧 Seek | 精确帧跳转（3FP `SeekFrame`） |
| F9 | 偏移校准 | 每路手动设置 ±时间/±帧偏移，用于源视频与成片压缩的错位对齐 |
| F10 | 播放速度 | 0.25x/0.5x/1x/2x/4x 等（3FP 原生为速度面向高频快照取帧的“伪变速”，见风险） |
| F11 | 循环 | 区间（A/B）循环播放，用于反复盯某一段 |
| F12 | **双步进按钮** | **两组前进/后退按钮**：① 按帧步进（默认 ±1 帧，可在设置中调 ±N 帧）；② 按秒步进（默认 ±1s，可在设置中调 ±N 秒） |

### 3.3 对比视图（P1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F13 | 分屏网格 | **1x1 ~ 3x3 自适应**（1/2/3/4/6/9 路），可点击选中某一路 |
| F14 | 单屏查看 | 只看某一路，放大细节 |
| F15 | A-B 滑动 | 两条时间线并行内容之间用滑块滑动（ICAT 同款交互） |
| F16 | 同步缩放/平移 | 各视图共享同一视口（同 region 同 zoom），或支持独立视口模式 |
| F17 | 放大镜 | 跟随鼠标读取某路局部像素 |
| F18 | **全屏/窗口模式** | **全屏模式**（含播放器表面全屏、隐藏 UI 帧）+ **窗口模式**（正常窗口、可调整大小/最大化） |

### 3.4 像素级工具（P1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F19 | 像素探针 | 取当前帧任意坐标 RGB(A) 值（3FP `ReadVideoPixel`），显示 BGRA8/RGB10A2 原值 |
| F20 | 差异叠加 | （可选）两路逐像素差异热力图——注意受不同缩放/色管理影响，需在相同量化路径下对比，见风险 |
| F21 | 截图 | 当前帧 PNG 输出（需与 3FP 快照缓冲协调，见 03 能力映射） |

### 3.5 记录与设置（P2）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F22 | 书签/标记 | 记录帧号+时间+备注，导出 CSV/JSON |
| F23 | 会话保存/恢复 | 保存各路文件的加载列表、偏移、布局、当前帧，下次一键恢复 |
| F24 | 快捷键方案 | 参照 ICAT/PotPlayer 风格，支持自定义 |
| F25 | **二级设置窗口** | 主窗口菜单/工具栏打开独立**设置对话框**，集中管理：硬件加速、显卡选择、步进参数、窗口/全屏行为、解码/色彩/音轨、布局等（详见下表） |
| F26 | **硬件编解码开关** | 设置中可全局/每路切换 **硬件解码** 与 **硬件渲染** 开关；GPU 解码可逐会话指定（多显卡场景） |

**二级设置窗口（F25）内容清单**：

| 分组 | 可配置项 |
| --- | --- |
| 硬件加速 | 硬件解码开关（全局）；指定解码 GPU（多显卡：可选 `此会话用第 N 块 GPU` 或 `系统默认`）；硬件渲染/合成开关 |
| 步进 | **按帧步进步长（默认 1 帧）**；**按秒步进步长（默认 1 秒）**；步进键位 |
| 窗口 | 默认启动模式（窗口/全屏）；窗口尺寸/记忆；全屏时是否隐藏时间轴/工具栏 |
| 解码/色彩 | 解码模式（CPU/GPU）；色彩模式（SDR 映射/HDR/ACM 相关项）；音轨选择 |
| 布局 | 网格行列默认值；每路是否独立解码配置 |
| 其他 | 快捷键方案、探针面板偏好、VRR 呈现选项（若支持） |

### 3.6 Windows 广色域 / ACM（P1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F28 | 原生广色域 + ACM 支持 | 遵循 Windows Advanced Color 机制：交换链支持 **RGB10A2/BGRA8 软播 HDR**、显式色彩空间（BT.2020/PQ / BT.709）；SDR 窗口遵循桌面 SDR 契约由 DWM/ACM 做显示侧映射 |
| F29 | 广色域覆盖层色 | 渲染/合成路径在 **Rec.709 ↔ Rec.2020** 的广色域色彩转换，覆盖**绘制、探针回读、截屏**全部环节，保证评测看到的颜色语义一致 |
| F30 | HDR/ACM 显示能力探测与降级提示 | 启动/换显示器时检测 Advanced Color（HDR 可用性、位深、色域），HDR 请求失败自动降级 SDR 并提示（3FP 通过 `色彩模式变化`事件 + 快照.实际色彩模式 报告） |

> 关键依赖：3FP 已按「Microsoft Advanced Color 交换链契约」实现：SDR 使用 BGRA8/RGB10A2（桌面合同），真实 HDR 使用 R10G10B10A2 + 显式 PQ/BT.2020；**ICC、HDR 校准和 SDR 亮度映射由 DWM 在窗口合成时应用一次**，3FP 不做显示侧补偿。核心问题是 ACM 是否随 3FP 走（已知），以及**跨会话读取在颜色管理前的原生缓冲**不会互相污染（已知支持）。

### 3.7 VRR（G-SYNC / FreeSync）（P1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F31 | VRR 支持 | 全屏/无边框窗口下输出匹配显示器刷新率范围（G-SYNC/FreeSync 生效），画面无撕裂；需从窗口创建（`DwmSetWindowAttribute`/`SetWindowDisplayAffinity` 场景）与交换链行为两方面落地 |
| F32 | 游戏中与桌面 VRR 隔离 | 播放器窗口为**独立窗口**（非游戏内叠加）；桌面 VRR 依赖 Windows 全局开关（G-SYNC 桌面模式/FreeSync），我们只保证**窗口本身不破坏 VRR** |
| F33 | 可变刷新率下的同步播放 | 播放节奏以主时钟为准；VRR 可变刷新率下同步步进的**帧基准仍是媒体时间/帧号**，不需要为显示器刷新率校准 |

> 关键依赖与风险：需要确认 **3FP 交换链是否开启 VRR 相关标记（`DXGI_SWAP_CHAIN_DESC1::SwapEffect/Flags` 支持 `DXGI_SWAP_EFFECT_FLIP_DISCARD` 与 `DXGI_PRESENT` 参数，以及 Present 节奏是否跟随媒体帧率而非固定 60Hz）**；若 3FP 使用固定刷新率 Present，VRR 只能作为“窗口层不干扰”的子集支持，不能保证 VRR 全时刻生效（见 [06 风险](06-风险与依赖.md) A8/A9）。MVP 阶段以“静态刷新率≤显示器上限、不主动挡 VRR”为验收。

### 3.8 音轨（可选，P2）

| 功能 | 说明 |
| --- | --- |
| 音轨选择 | 透传 3FP 的 `SelectAudioStream` / 外部音轨 |
| 音频同步 | 同步模式下主时钟仍由画面驱动；是否输出声音可由用户选择单路 |

> 视频评测场景多以画面为主，音频属低频需求，P2 排期。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | **9 路** 1080p 同步步进无明显延迟；步进操作单次 < 100ms 以内反馈（解码热数据时）；合理 GPU 显存占用 |
| GPU | 优先 GPU 解码（CUDA/D3D11VA），自动回退 CPU；**多路硬解需评估显存**；支持**多显卡指定解码 GPU**（见 F26） |
| 内存 | 播放会话内存模型稳定（3FP 有 8 帧视频队列 + 128MiB 预算约束） |
| 稳定性 | 会话异常不拖垮 UI；播放线程与 UI 线程隔离（3FP 事件走 SynchronizationContext） |
| 可维护性 | 后端能力封装为独立模块（`Backend.3FP`），未来可换成其他实现 |
| 兼容性 | Windows 10 22H2+；.NET 11 运行时（或 NativeAOT 自包含，无需运行时）；Shared FFmpeg DLL 与 FFF.Native 由用户目录随附 |
| 色彩/广色域 | 支持 Windows Advanced Color：RGB10A2 HDR/广色域输出、显式色彩空间、DWM/ACM 显示侧色管理；**探针/截图/UI 覆盖层在同一色彩语义下工作** |
| 显示同步 | 支持 VRR（G-SYNC / FreeSync）：交换链不破坏 VRR、不强制固定 60Hz；播放节奏独立于刷新率 |

## 5. 优先级与验收要点

| 里程碑 | 验收 |
| --- | --- |
| M0 MVP | **2 路 1080p 同时打开**、同步 PTS 步进、方向键**按帧步进/按秒步进**双组前进后退、帧号/时间显示稳定 |
| M1 | **5~9 路网格布局（1x1~3x3）**、独立偏移校准、选中高亮、单屏视图 |
| M2 | 同步播放/暂停/变速、**硬件编解码开关（含多显卡指定）**、区间循环、Seek 条 |
| M3 | A-B 滑块、同步缩放/平移、放大镜、像素探针 |
| M4 | **二级设置窗口**（硬件加速/GPU 选择/步进步长/窗口全屏）、会话保存恢复、书签导出、快捷键 |
| M5 | 打包分发（NativeAOT 自包含/单文件 + 外部 FFmpeg DLL）、文档、性能回归；**ACM/广色域与 VRR 验收**（见下表） |

### 5.1 ACM / VRR 专项验收

| 项 | 验收方式 |
| --- | --- |
| ACM SDR | SDR 窗口在启用了 ACM 的显示上正常显示，探针回读码值与 3FP 色彩模式一致（不依赖 DWM 后处理） |
| ACM HDR | HDR 源在真实 HDR 显示上正确呈现（R10G10B10A2/PQ·BT.2020）；无 HDR 能力时自动降级 SDR 并提示（`色彩模式变化`/快照.实际色彩模式） |
| 覆盖层色彩 | 放大镜/探针标注/A-B 分隔线等 GDI+ 覆盖层在 HDR/广色域窗口上不产生明显偏色（走 SDR 叠加合成语义，需在 ACM 显示器实测） |
| VRR 帧刷新 | 全屏播放 60fps 源时，窗口不强制 60Hz 固定节奏（若 3FP 暴露 Present 节奏参数，VRR 生效）；暂无法验证时以「不主动挡 VRR + 无撕裂」为通过线 |

## 6. 不做的事（本次范围外）

- 不做网络协议（3FP 本身不支持网络输入）；
- 不做屏幕录制、转码、剪辑；
- 不做真正的“逐像素比对引擎”（P 帧差异语义）；仅提供像素探针与可选逐点差绝对值视图；
- 不做「游戏内叠加/注入类 VRR 工具」（如 RTSS 图层）；本软件是独立窗口，VRR 支持仅限于**窗口/交换链不破坏桌⾯ VRR** 的范畴；
- 不自行实现显示侧色彩校正（ICC/校准/SDR 亮度映射）——统一交给 DWM/ACM，与 3FP 契约一致。
