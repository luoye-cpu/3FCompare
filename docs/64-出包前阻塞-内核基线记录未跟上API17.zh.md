**磁盘 DLL 的 sha256 == 清单里的 `dllSha256`**（防"事后替换内核"）。
现在磁盘是 `84fcf247…`、清单是 `8c083265…` ⇒ **该条判红**。

## 为什么我没有顺手修

两条"一行改绿"的路都不该由我走：

1. **只有当基线迁移完成（新内核验收 + 记账）时，pin 与清单才该更新。**
   我手里没有这 3 笔 HDR 提交的验收记录 —— 替它声明"已验收为发布基线"
   等于越过验收环节，正是本项目明确禁止的那类声明。
2. **重跑 `tools/构建全部.ps1`** 能让清单自洽，但基线迁移按惯例要带
   tag（`3fcompare-kernel-YYYY.M.D.N`）与 `PATCHES.md` 记账，是一个需要决策的动作。

⇒ **交由正在做内核对齐的作业者处置**：更新 pin 到 API 17 那笔基线、重跑内核构建写清单、
按惯例记账。之后 `pack.ps1 -Mode full` + 门禁才有望全绿。
