## P0 · 注入语义三缺陷 + 夹具守卫

### 改动点（全部在 `third_party/fff_project/FFF.Native/3FP/`）

**D1 —— 帧号取错操作数。** `Hdr/HdrProcessor.cpp:336` 用 `frame->pts` 充当 `frameIndex`，
而 `Api/FFF.Player.Api.h:659-662` 明文按 `FFF3FPSnapshot::frameIndex` 匹配。
修法：`ProcessFrame` 增加 `const std::int64_t frameIndex` 形参（哨兵 `kUnknownFrameIndex`），
`Hdr/HdrProcessor.h` 同步声明，注入查找用传入值，pts 仅作缺省回退；
调用点 `Render/VideoRenderer.cpp:4740`（`Render()` 内，`:4730` 已拒空帧）传会话维护的帧序。
把注入块抽成 `ApplyInjectionLocked(frameIndex, next)`，使"装表时"与"来帧时"走同一段代码。

**D2 —— 装表后无新帧即完全无效，却返回 Success。** `injectedActive_` 唯一写入点在 `ProcessFrame`
（`:334`/`:348`），EOF / Paused 下装表无任何效果，`FFF3FP_GetHdrMetadataSource` 仍报 Bitstream。
修法：`SetInjectedMetadata`（`:583-608`）在写入 `injected_` 后调 `ReapplyInjectedMetadata()`，
对**已持有的上一帧状态**重放注入；Clear 路径保持现状（只清标志）。
> 取舍：备选是"无持有帧时返回 `NotReady`"。选重放不选报错，因为报错会把"暂停时校曲线"这个
> 头部广告过的用法直接打死；且重放不动 ABI、不动导出面。

**D5 —— 注入态峰值混挂。** `:326` 由比特流置 `dynamicSourcePeak`，注入块只在 `:352` 置位、从不复位
⇒ 注入项无有效 maxscl 时，曲线是注入的、`sourcePeakNits` 跟比特流，而 source 仍报 Injected。
修法：注入生效后若 `ValidPeak(next.dynamic.windows[0].signalPeakNits) <= 0`，把 `dynamicSourcePeak`
置回 false（`fix-proposal.md` D5 段的两行）。

**D4 —— 夹具守卫（防同类假红/假绿）。** `3fp/tools/hdr10plus_inject_test.cpp` 的行为断言按墙钟排程，
没有"播放仍在推进"的门；账本那 6 条 FAIL 出自 77 KB / 实测 `decoded=1 hdr10plus_frames=1` 的
FATE 样本（`testmedia/media/hdrmeta/hdr10_plus_h265_sample.hevc`）。
修法（两条都要）：
1. 套件**默认夹具**换成多帧真样本 `testmedia/media/hdr10plus/real_hdr10plus_rolloff.mp4`（10 s）；
2. 断言开始前加 fail-closed 前置：先读快照，若 `presentedVideoFrames` 增量 < 5 或
   `hdr10plus_frames` < 5 则**直接判红并打印夹具实况**（不许静默跳过）。

## P1 · 绑定层与出包

### 1. 宿主绑定（C#）

事实：出货内核导出 90 个函数、含 `FFF3FP_Set/ClearHdrDynamicMetadata`、`GetHdrMetadataSource`；
但宿主 `src/3FCompare.Core/Backend/` 的 P/Invoke 面（27 个名字）里三者**零声明、零调用者**
（`grep -rniE "SetHdrDynamicMetadata|InjectedHdr|HdrDynamicMetadata" src/ tests/` = 空，
正对照在同串对 TP 源码命中 4 个文件）。

办法：
1. 在 `IPlayerEngine` 加一条能力方法（如 `TrySetHdrDynamicMetadata(ReadOnlySpan<…>)`），
   照现有 P/Invoke 三件套补 `NativeRuntime.cs` 声明 + `Fff3FpEngine.cs` 实现；
2. 结构体按 TP 的 `FFF3FPHdrDynamicMetadataEntry`（含 ≤3 个 `FFF3FPHdrMetadataWindow`）逐字段镜像，
   `size`/`version` 用内核返回值而非字面量；
3. 判据：**用 `GetHdrMetadataSource` 做闭环**——装表→读回 `Injected`→清表→读回 `Bitstream`，
   这是"写进产物的元数据要被第二个读者读回"的同一口径；
4. 加一个 Core 单测只验 marshal 布局（不启进程），端到端仍走探针。
> ⚠ 这一步会改 `IPlayerEngine`/`FakeEngine`（`tests/3FCompare.Core.Tests/Infrastructure/FakeEngine.cs`
> 当前是并发脏文件），落地前先与并发会话对表，避免撞写。

### 2. 出包

事实：最新两个包 `publish/3FCompare-v0.3.2-beta-x64[-full].7z` 打在 10-07 04:36/04:37，
其 `publish/build/…/FFF.Native.dll` = 775,168 B / **87 导出 / 0 条 DynamicMetadata**；
HDR10+ 提交在 10-08 14:53 ⇒ 发布件里没有该能力**纯粹是出包过期**。

办法：先完成 P0（否则包里是能装表但语义错的内核），再走
`tools\构建全部.ps1` → `pack.ps1`（三道门禁：版本 / 布局 / 文档引用）→ 新包自测。
**发布到 Releases 属远端动作，要单独点头。**

## P3 · JXR 非浮点像素格式（表已到位：`_3fc_tmp\handoff-20261008-lanes\laneB-jxr\README.md`）

裁决在前：**docs/15「GUID 表只认 8bpp Gray」在现役 DLL 上已不复现**（15 条可解，含 8/16-bit 整数全套）；
**交接 §一④「4/4 彩色全通」读过头了**——那 4 个夹具 `ffprobe` 全是 `rgbaf16le`
（`headerSize=8`、码 `0x0B/0x0C`），验收集里**一个非浮点真实样本都没有**；唯一的非浮点真实样本
`12a_srgb`（24bppRGB）FFmpeg 与 jxrlib 自家 `JxrDecApp` 双双 0 字节 ⇒ 文件本体坏，不能证真也不能证伪。

### 出货性前置（主循环 21:3x 实测，两条都要先读）

1. **本轮全部 JXR 读数是在实验树构建上量的，不是出货内核。**
   `3fp/build/FFF.Native.dll = 69599183F6A10CFD`（API 19，`3fp/kernel@782736e` 的产物）；
   出货链那份是 `third_party/.../x64/Release/FFF.Native.dll = e5a7adcb…`（API 17，90 导出）。
   且 **TP 树里根本没有 JXR 浮点通路**：`grep -n "RGBAF16LE\|layout == 3\|floatRgb" third_party/fff_project/FFF.Native/3FP/Render/VideoRenderer.cpp` = **0 命中**。
   ⇒ 交接 §一④「JXR 走 FFmpeg 已工作」要限定主语：**工作的是实验树**；出货内核里 fp16 JXR 会落
   `DescribeInput` default → sws 量化 → **钳位 + `transfer=0` 错曲线**（即下表 B-4 那一类行为）。
   与 P1 那条不同性质：注入是**出包过期**，JXR 浮点是**功能没移植**（属 P2 路线 A 的账）。
2. **FFmpeg 侧不是瓶颈**：`runtime/avcodec-63.dll` 与实验树同一片 `C6163B23AF0CACC6`（含 libjxr），
   `publish/build/3FCompare-v0.3.2-beta-x64-full/ffmpeg-full/avcodec-63.dll` = `638121325D45C308` 也带 libjxr。
