## 1. External Dependency List

| Dependency | Source | Version policy | Notes |
| --- | --- | --- | --- |
| `FFF.Native` source (submodule) | [FFF_Project](https://github.com/Lake1059/FFF_Project) `FFF.Native`, **MIT license (confirmed)** | pin commit via git submodule; add extension patches on top (see 03 §6); stay mergeable with upstream | core backend: decode/render/clock/subtitles |
| Shared FFmpeg DLL | [BtbN FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases) (`...-win64-gpl-shared.zip`) | pin to a commit compatible with upstream; **don't mix DLLs from different versions** | avcodec/avformat/avutil/swresample/swscale/avfilter |
| libass | upstream `tools/prepareFFmpeg.ps1` pinned | via build script | ASS/SSA subtitles (not needed for MVP but needed for release) |
| .NET 11 | Microsoft | **NativeAOT self-contained single-file (enabled & verified)**; framework-dependent as fallback | faster startup, no runtime dependency; interop layer `[LibraryImport]` + JSON source-gen context (JsonAotContext) already compatible |

> FFmpeg update policy: users may replace the entire directory of FFmpeg DLLs to enjoy newer FFmpeg features (3F family trait),
> but must keep ABI compatibility with `FFF.Native` (stated in upstream README). This project's UI layer doesn't call FFmpeg directly.

## 2. Risk Matrix

| ID | Risk | Probability | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R1 | ~~third-party reference license unclear~~ → **fork patch & upstream merge cost** (submodule rebase/conflicts) | low→medium (depends on upstream cadence) | medium | MIT confirmed; patches maintained in separate commits (03 §6), periodic rebase + run E3/upstream regression |
| R2 | playback speed API missing (A2) | medium | medium | "pseudo-speed" frame-sampling playback; or defer F10 |

| R4 | full-frame readback channel missing (A4, screenshot/difference frames) | medium | medium | limited use of single-pixel probe (slow row-by-row); or a separate FFmpeg instance re-decodes for frames (mind license & consistency) |

| R6 | HWND/D3D flip-model lifecycle errors (dual chains on one window, resize not re-bound) | low | high | strictly follow 3FP README contract; PlayerSurface unit-ized; integration tests cover resize/minimize/DPI |
| R7 | "same frame" semantic ambiguity from different frame rates/start points | medium | medium | PTS time baseline + frame table; UI shows "frame index mode" explicitly |
| R8 | 3FP API version evolution breaks compile | low | medium | version-check function at startup; upgrade review |
| R9 | performance not meeting goals (9-stream 1080p step lag / VRAM shortage) | low→medium | medium | 60Hz snapshot polling, command batching, correct only on difference; **fall back to CPU decode**; performance benchmark gates (2/4/9 streams) |
| R10 | English/Chinese resource & platform differences (message boxes, file paths) | low | low | keep UTF-8; path handling locale-independent |
| R11 | 3FUI private-protocol/collaboration capability depends on upstream | low | low | optional P2; doesn't block the mainline |
| R12 | **VRR depends on 3FP swap-chain support (A8/A9)**; if 3FP presents at fixed 60Hz then G-SYNC/FreeSync fails full-time | medium | medium | test first; if insufficient, downgrade to "window doesn't interfere with desktop VRR" and document; suggest API to upstream if needed |
| R13 | **ACM/wide-gamut depends on 3FP swap-chain contract** (SDR/HDR color spaces); self-implemented color correction leads to "multi-stream window display differences" | medium | medium | unify via 3FP contract + DWM; probe/compare use "pre-color-management" code values, decoupled from display side |
| R14 | overlay (GDI+ compositing) color semantics on HDR/wide-gamut windows (SDR text/graphics overlay) may be amplified by ACM display mapping | low | medium | overlays don't write HDR metadata; special acceptance on ACM displays; switch to D3D overlay if needed (extra work) |
| R16 | **multi-GPU specified decode (A11)**: picking a GPU per session needs kernel support for D3D11 adapter selection; complex if swap-chain creation needs changes | medium | medium | do "system default GPU" first; multi-GPU selection as extension patch (03 §6), fall back to default GPU on failure |
| R15 | **NativeAOT limits**: P/Invoke needs static resolution (`LibraryImport`/`DynamicDependency`), reflection/`WinForms Designer` serialization limited; compile may fail if P/Invoke signatures & reflection usage are incompatible | medium | medium | interop layer uniformly uses `[LibraryImport]` (no runtime `LoadLibrary`/`GetProcAddress`); settings serialization avoids `BinaryFormatter`; designer uses framework-dependent in dev, AOT in release |
| R17 | ~~WinForms + NativeAOT unavailable under .NET 11 preview~~ → **resolved**: used official `_SuppressWinFormsTrimError` to suppress NETSDK1175, AOT publish succeeded; real video render + selftest passed | eliminated | medium | `PublishAot=true` + `_SuppressWinFormsTrimError=true`; WinForms/IL analysis warnings (IL3053) kept visible; 21MB native single-file verified runnable (see README engineering status) |

## 4. Quality Strategy

- **Automation**: `Core.Tests` (sync conversion, offsets, clamp, frame table, settings serialization); E3 smoke as CI prerequisite;
  optional D3D/UI smoke tests run manually in the 3FP upstream test style.
- **Performance gates**: establish baselines before M5 (2/4-stream 1080p open time, step P95, peak memory, VRAM usage).
