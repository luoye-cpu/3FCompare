# 10 · UI 结构审查与布局优化

> 审查对象：`src/3FCompare`（Avalonia 11 / .NET 11 / NativeAOT）
> 审查范围：主窗口骨架、底部栏组、工具侧栏、传输栏、时间轴、中央对比网格、设置窗口
> 结论日期：2026-09-14

---

## 1. 审查方法

本项目无法用“看截图”做 UI 审查（本会话模型不可读图，且 `--screentest` 抓的是播放器**子 HWND**
帧而非窗口 chrome）。因此改为**从 XAML + 代码还原布局树**，再与主流软件的实际布局做逐项对照。

被通读的布局相关文件：

| 文件 | 作用 |
|---|---|
| `MainWindow.axaml` | 窗口骨架（`DockPanel` + `Grid`） |
| `MainWindow.axaml.cs` | 侧栏几何、全屏切换、状态栏更新 |
| `Controls/ToolsSidebar.cs` | 工具侧栏（导航 + 内容 + 折叠） |
| `Controls/TransportBar.axaml(.cs)` | 传输栏三区布局 |
| `Controls/TimelineView.cs` | 时间轴自绘（刻度/播放头/A-B） |
| `Controls/CompareGridView.cs` | 1~9 路网格布局 |
| `Controls/PlayerSurface.cs` | 单路表面（`NativeControlHost` 子 HWND + GDI 覆盖层） |
| `Views/SettingsWindow.cs` | 二级设置窗口 |

## 2. 改动前的结构

```
DockPanel
├── Menu                        Dock=Top
├── StatusBar      H=24         Dock=Bottom  ← 声明第 1 个 → 视觉最底
├── TimelineHost   H=34         Dock=Bottom  ← 声明第 2 个 → 倒数第 2
├── TransportHost  H=54         Dock=Bottom  ← 声明第 3 个 → 倒数第 3
└── MainArea  Grid[264, Auto(4), *]
    ├── SidebarHost   (ToolsSidebar)
    ├── GridSplitter  W=4
    └── CenterPanel   (CompareGridView / AbSliderView / MagnifierOverlay)
```

> `DockPanel` 的 `Dock=Bottom` 是**反向堆叠**：先声明者落在更下方。
> 故改动前的视觉自下而上是 `MainArea → Transport(按钮) → Timeline(拖动条) → StatusBar`。

窗口：`W=1600 H=900 MinWidth=640 MinHeight=400`。

## 3. 主流软件布局对照

| 软件 | 类别 | 顶部 | 中央 | 底部自上而下 | 侧栏 |
|---|---|---|---|---|---|
| **PotPlayer** | 播放器 | 标题/右键菜单 | 视频 | **进度条 → 控制按钮** → 状态条 | 无（右侧可折叠播放列表） |
| **MPC-HC** | 播放器 | 菜单 | 视频 | **进度条 → 工具栏** → 状态栏 | 可选播放列表 |
| **VLC 3/4** | 播放器 | 菜单(仅 3.x) | 视频 | **控制条：进度条在上、按钮在下** → 状态栏 | 播放列表（可折叠） |
| **Premiere Pro** | NLE | 菜单 + 工作区切换 | Source / Program Monitor | Monitor 底部：时间码 + 传输控件；下方**独立** Timeline 面板 | 右侧 Project / Effect Controls，**可拖拽 + 折叠 + 几何记忆** |
| **DaVinci Resolve** | NLE/调色 | 菜单 + **7 页页面栏** | Viewer | Viewer 底部 transport + 信息条；下方 Timeline | 右上 Inspector，**可折叠 + 宽度记忆** |
| **VS Code** | IDE | 菜单/标题栏 | 编辑器 | **状态栏单条 22px**，信息靠右 | **活动栏 48px 图标（折叠态仍保留入口）** + 可拖拽侧栏 |
| **Figma** | 设计 | 工具栏 | 画布 | 底部状态/缩放条 | 左右面板可折叠，折叠后为图标条 |

### 抽出的七条共性

1. **进度条紧贴画面，控制按钮在其下** —— PotPlayer / MPC-HC / VLC / QuickTime 一致。
2. **状态栏永远是最底部唯一一条**，不放中间。
3. **侧栏折叠后仍保留工具入口**（VS Code 活动栏 48px、Figma 图标条），而不是留空白。
4. **侧栏宽度可拖拽且持久化**（Resolve Inspector、VS Code、Premiere 面板组）。
5. **面板开关在菜单内分组**（Premiere「窗口」下 20+ 面板；VS Code「视图」→ 子菜单），
   而不是 8 个平铺在主菜单里。
6. **窄窗口自动收起侧栏**，且有合理的最小窗口尺寸。
7. **分辨率 / 缩放 / 帧率等常驻信息放状态栏右端**（Premiere Program 信息条、PotPlayer、Figma）。

## 4. 问题清单

| # | 级别 | 问题 | 与共性的偏差 | 影响 |
|---|---|---|---|---|
| A1 | **P0** | 底部顺序为「按钮在上、拖动条在下」 | 违反共性 1 | 拖动时视线要跨过一整行按钮；时间轴与画面之间多了一层阻隔 |
| A2 | **P0** | 侧栏折叠后是 **44px 空白条**，只剩右上角一个 `▶` | 违反共性 3 | 折叠本意为省空间，结果既没省多少（44px）又丢掉 5 个面板的直达入口 |
| A3 | **P1** | 侧栏宽度写死 264，拖拽后**不持久化**；折叠态也不落盘 | 违反共性 4 | 每次启动都要重拖 |
| A4 | **P1** | 窗口 `MinWidth=640`，但传输栏三区撑满需 ≈1000px | 违反共性 6 | 640~1000 区间中间那排播放按钮被挤压/重叠 |
| A5 | **P1** | 「视图」菜单下 8 个面板开关平铺 | 违反共性 5 | 主菜单纵向过长，常用项（全屏）被推到最底 |
| A6 | **P1** | 全屏只隐藏 Menu/Transport/Timeline，**状态栏留一条 24px 亮条** | 违反共性 2（沉浸） | 与 `docs/02` “全屏隐藏时间轴/工具栏”的意图不一致 |
| A7 | **P2** | 分辨率 / 缩放混在状态栏中间那串诊断文本里 | 违反共性 7 | 需要横扫整条状态栏才能看到 |
| A8 | **P2** | 真机模式下**无法在画面上叠加任何 UI**（Airspace 限制） | —— | 每路缺少文件名/序号/分辨率角标，3×3 时无法分辨哪路是哪个素材 |

### A8 的根因（重要，决定了优化边界）

`PlayerSurface` 是 `NativeControlHost`，真实模式下每路是一个**真实的子 HWND**，
而 Avalonia 的所有内容都渲染在父窗口 HWND 上 —— 子窗口永远盖在父窗口之上。
因此：

- `CenterPanel` 里的 `MagnifierOverlay` / `AbSliderView` 在真机模式下**会被画面盖住**；
  `ThumbnailPopup` 之所以单独做成 `Window + Topmost = true`，正是为了绕开这一点。
- `PlayerSurface` 自己的 GDI 覆盖层（文件名、`D3D11` 角标、小地图）在
  `isRealModeActive`（真实模式 + 会话正常）时**被显式跳过**，因为 GDI 画在
  D3D11 SwapChain 的 HWND 上会干扰 Present 管线导致卡死。

→ **真机模式下加多路角标，必须走“独立的 Topmost 覆盖窗口”方案**（同 `ThumbnailPopup`），
不能简单地往 `CenterPanel` 里塞一个 Control。此项本文只记录，不实施。

## 5. 已实施的优化

| 项 | 改动 | 文件 |
|---|---|---|
| A1 | 底部顺序改为 **画面 → 时间轴(H=40) → 传输栏 → 状态栏**；时间轴由 34 提到 40（拖动命中区更大，刻度/时间码不再与时间码标签挤在一起） | `MainWindow.axaml` |
| A2 | 折叠态改为 **48px 图标导航栏**（VS Code 活动栏同宽）：5 个面板图标 + 放大镜开关，点击 = 展开并激活；当前面板图标高亮 | `ToolsSidebar.cs` |
| A3 | 新增 `AppSettings.SidebarWidth` / `SidebarCollapsed`，折叠时记下当前实际宽度，展开原样还原，启动恢复 | `AppSettings.cs` / `ToolsSidebar.cs` / `MainWindow.axaml.cs` / `SettingsWindow.cs` |
| A4 | `MinWidth/MinHeight` 640×400 → **960×540**；传输栏加响应式收缩 | `MainWindow.axaml` / `TransportBar.axaml.cs` |
| A5 | 「视图」菜单重排为 **视图模式 / 面板(子菜单) / 网格布局 / 全屏**，新增 `Menu_Panels` 双语键 | `MainWindow.axaml` / `LanguageManager.cs` |
| A6 | 全屏时状态栏随 chrome 一起隐藏 | `MainWindow.axaml.cs` |
| A7 | 状态栏**右端**新增常驻区：选中路渲染分辨率 + 当前缩放 | `MainWindow.axaml(.cs)` |

### A2 图标取字说明

刻意**不用** Unicode 符号字体（`⌖ ★ ♪` 等在 Segoe UI 下字形覆盖不稳，缺字会显示豆腐块），
改为中文取名称首字、英文取两字母缩写，由 `RailGlyph(key)` 提供：

| 面板 | 中文 | 英文 |
|---|---|---|
| 探针 / Probe | 探 | Pr |
| 书签 / Bookmarks | 签 | Bk |
| 偏移 / Offset | 偏 | Of |
| 媒体 / Media | 媒 | Md |
| 音频 / Audio | 音 | Au |
| 放大镜 / Magnifier | 镜 | Mg |

### A4 响应式收缩规则

| 传输栏宽度 | 行为 |
|---|---|
| ≥ 1180 | 全量：倍速 82 + 色彩 172 + 时间码 + 说明文字 |
| 1020 ~ 1180 | 隐藏说明文字，色彩模式收窄到 132 |
| < 1020 | 色彩 104、倍速 68（时间码与播放按钮优先保全） |

时间码宽度 208 → 168（Consolas 13 下 `00:00:00:00 / 00:00:00` 实测约 137px，208 属过度预留）。

### 侧栏自动折叠

窗口宽度 < 1100 时自动收起侧栏；变宽后自动展开。
**用户手动折叠/展开过一次后即交还控制权**（`ToolsSidebar.LastToggleByUser`），
不再与用户意图打架。

## 7. 验证结果

| 项 | 结果 |
|---|---|
| `dotnet build -c Release --no-restore` | **0 错误**（仅既有 `AVLN3001` 警告：MainWindow 无公共构造函数） |
| 单元测试 | **53 / 53 通过** |
| `--screentest` 真实 4K（`real_4k_h264_60m.mp4`） | exit=0，PNG 3,301,414 B |
| `--selftest` 真实 4K | exit=0，全部断言通过 |

`DockPanel` 的 `Dock=Bottom` 是**反向堆叠**，改 XAML 声明顺序极易改反，
所以在 `--selftest` 里新增了「布局」步骤做回归断言：

```
selftest[布局]: 布局 ✓ 时间轴(782) → 传输栏(822) → 状态栏(876)，侧栏 264px
```

782 + 40 = 822、822 + 54 = 876、876 + 24 = 900 —— 自下而上正确，时间轴紧贴画面。

侧栏持久化两种场景实测：

| 预置 `settings.json` | 断言输出 |
|---|---|
| `SidebarWidth=300, SidebarCollapsed=true` | `侧栏 48px（折叠）` |
| `SidebarWidth=300, SidebarCollapsed=false` | `侧栏 300px` |

> 实现过程中发现并修掉一个缺陷：窄窗自动折叠原本会在窗口够宽时无条件展开，
> 把用户在宽屏下主动折叠（且已持久化）的偏好冲掉。现改为只由 `_autoCollapsedByUs`
> 标记的、我们自己收起的侧栏才会被自动展开。

### 构建环境坑（本次新发现）

沙箱里 **`APPDATA` 为空**，会导致 `ResolvePackageAssets` 报
`NETSDK1060: 读取资产文件时出错 … Value cannot be null. (Parameter 'path1')`——
**与 `dotnet restore` 那条同源，不是代码问题**。构建时补上即可：

```bash
APPDATA="C:\\Users\\20210\\AppData\\Roaming" dotnet build ... --no-restore
```
