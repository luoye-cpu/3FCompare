## 1. 接入形态判定

3FP 存在两层接口：

- **Native C API**：`FFF3FP_*` 系列（`FFF.Native/3FP/Api/FFF.Player.Api.h`，当前版本号 10），
  面向 C/C++/P/Invoke 调用方。
- **托管内核**：`FFF.Player` 程序集（`播放器会话`、`播放器控制器` 等，.NET 11，VB.NET），
  内部已封装 Native 调用并提供事件同步、取消、异常化错误处理。

**本项目接入方式（已决策）：直接基于 `FFF.Native` 源码开发（MIT 许可已确认）。**

核心理由：

1. `LICENSE.txt` 为 MIT（作者已确认有效），可自由修改/再分发/商用；
2. 我们需要 **VRR 交换链 / 视口子区域 / 全帧回读** 等上游当前未开放的能力，只有改内核才能拿到；
3. 与其把 `FFF.Player` 托管程序集当黑盒（受其 API 与事件语义约束），不如自带极薄互操作层，
   完全掌控 ABI 与扩展 API。

> 托管 `FFF.Player` 可作参考实现：其事件模型、错误处理、`播放器会话` 的线程纪律值得借鉴，
> 但我们不依赖其程序集。**

## 2. ICAT 功能 → 3FP 能力映射

| ICAT 功能 | 3FCompare 需求 | 3FP 能力支撑 | 获取途径 | 备注 |
| --- | --- | --- | --- | --- |
| 加载最多 4 个视频/图像 | F1/F2 | 多实例 `播放器会话`；静态图按单帧媒体 | 每路一个会话 | **1~9 路 = 1~9 个会话+1~9 个 HWND** |
| 对齐 (Sync/Offset) | F9 | PTS 精确（位置100纳秒）；无内嵌时间锚时用帧号 | 快照.位置/帧序号 | 偏移由编排层换算为 PTS 后 Seek |
| 帧步进 | F7/F8/F12 | `StepFrame(±1)`、`SeekFrame(帧索引)`、`Seek` | 控制器方法 | 按帧步进=Step/SeekFrame；**按秒步进=Seek(±N 秒)** |
| 播放/暂停/停止 | F6/F10 | `Play/Pause/Stop` | 控制器 | |
| **硬件解码开关** | F26 | 每会话 `解码模式.CPU/GPU`；GPU 自动回退 CPU | 会话配置 | 全局/每路可切换；多路硬解测试显存 |
| **指定解码 GPU** | F26 | D3D11 设备由调用方/或指定适配器创建 | ❌ **2026-09-16 确认：未接线**（见 A11）——UI 能列能选能存，但根本没传给内核，选择**静默无效** | 生效需内核加 `FFF3FP_Create` 适配器参数或 `SetAdapter`；在此之前 UI 应提示"暂不生效" |
| 播放速度 | F10 | 无显式速率 API | — | **待确认**：需评估用"伪变速"（高频 Seek 取帧）还是其他手段；见风险 |
| 循环 | F11 | 无原生循环 | 编排层 | 区间 A/B 由 SyncController 检测边界后 Seek 回起点 |
| 平移/缩放重点区域 | F15/F16 | D3D11 渲染器支持 1:1/Lanczos3 缩放；`ReadVideoPixel` 支持任意坐标 | 需确认视口子区域 API | 见"视口裁剪"风险；兜底为回读+UI 缩放 |
| A/B 滑块 | F14 | 两个 sehssion 并行渲染 | UI 叠加 | 分隔线为覆盖层，不碰 D3D |
| 像素探针 | F17 | `FFF3FP_ReadVideoPixel`（1x1 回读，BGRA8/RGB10A2 原值） | `原生视频像素探针` | 必须等待帧稳定（暂停后取） |
| 截图 | F19 | ⚠ **`GetSnapshot` 是状态快照，不是画面截图**（2026-09-16 更正）：画面导出走 `FFF3FP_ReadVideoPixelRegion` 区域回读 | 回读的是「颜色管理前」的**已呈现帧** ⇒ **不含 UI / OSD / 显卡合成**；分辨率 = 呈现分辨率（随窗口变化），**不等于源分辨率** | `--screentest` 实测导出 1995×1122 PNG。要源分辨率需内核新增"读解码帧" API（见 `docs/11`） |
| 时间戳/帧号显示 | F4/F5 | 快照.位置、帧序号、原始帧PTS、帧时间基、已呈现帧数、解码器、色彩模式 | 快照 | 帧率来自 媒体信息.流[].帧率 |
| 媒体信息 | F3 | `GetMediaInfo` JSON | `当前媒体信息` | |
| 音轨选择/外挂音轨 | 音频(可选) | `SelectAudioStream`/`LoadExternalAudio`/`ClearExternalAudio`/`SetExternalAudioOffset` | 控制器 | |
| 字幕/弹幕 | 未纳入 MVP | SRT/ASS/SSA/SUP/XML 弹幕全套 | 控制器 | 可选增强 |
| 多路色彩一致性 | 差异叠加(F18) 前提 | `色彩模式`（映射SDR/原始HDR/PQ HDR）、`ReadVideoPixel` 回读的是"颜色管理前的视频缓冲" | 配置 | 探针回读 path 独立于 DWM/ICC，适合做像素级一致对比，但注意色域映射参数需统一 |
| ACM/广色域 | F24–F26 | 3FP 已按 Advanced Color 契约输出（SDR BGRA8/RGB10A2、HDR R10G10B10A2+PQ/BT.2020）；`色彩模式变化`事件 + 快照.实际色彩模式 报告降级 | 配置 + 事件 | 显示侧校色交给 DWM；本项目只需保证「探测能力 + 透传配置 + 覆盖层不污染」 |
| HDR↔SDR 切换 | F26 | `色彩模式变化`事件（SDR 会话在 HDR 后继开 SDR 须先重配交换链，3FP 已处理） | 事件 | 多路 SDR/HDR 混播在 ACM 显示上各自独立呈现；探针回读统一以「颜色管理前」保证可比 |
| VRR（G-SYNC/FreeSync） | F27–F29 | ~~**待确认**：3FP 是否在交换链上支持 VRR~~ → **2026-09-16 已确认支持**：内核已暴露 `FFF3FP_SetPresentConfig`（撕裂呈现）与 `FFF3FP_SetPacingConfig`（媒体率节奏），selftest 实测「显示器链支持 ✓」「媒体率节奏已启用 ✓」 | 配置（`SetPresentConfig` / `SetPacingConfig`） | 见 A8/A9；兜底为"窗口不干扰桌面 VRR" |

## 3. 核心 API 速查（由托管控制器对外暴露的形状）

> 以下对照 `FFF.Player.Api.h`/互操作层整理为本项目需要的语义；**最终签名以引用的程序集为准**。

### 3.1 会话生命周期

| 需要的能力 | 3FP 对应 | 说明 |
| --- | --- | --- |
| 创建会话 | `播放器配置`(输出窗口、解码器、色彩模式、SDR/HDR 峰值、音频端点、事件同步上下文) + `播放器会话` | 每路的 `输出窗口` 为该路 PlayerSurface.HWND |
| 打开/关闭 | `打开Async(路径)`（支持取消）/ `Dispose` | 用异步避免 UI 卡顿 |
| 状态 | `当前快照.状态` (Idle/Opening/Ready/Playing/Paused/Ended/Failed/Closed) | |
| 错误 | `最后错误消息` / `播放器异常` | 统一转 UI 提示 |

### 3.2 播放控制

| 操作 | 3FP |
| --- | --- |
| 播放/暂停/停止 | `播放()`/`暂停()`/`停止()` |
| 静音/音量 | `SetVolume(音量, 静音)` |
| Seek（时间） | `Seek(位置100ns)` |
| Seek 关键帧 | `SeekKeyframe(位置100ns)` |
| Seek 按帧 | `SeekFrame(帧索引)` |
| 步进 | `StepFrame(方向±1)` / `StepKeyframe(方向)` |
| 流选择 | `SelectVideoStream(索引)` / `SelectAudioStream(索引)` |

### 3.3 诊断/读取（高频轮询安全）

| 数据 | 3FP 快照字段（要点） | 用在哪 |
| --- | --- | --- |
| 播放位置/时长 | `位置100纳秒` / `时长100纳秒` | 时间轴 |
| 当前帧号 | `帧序号` | 帧号显示/书签 |
| 原始 PTS | `原始帧PTS` + `帧时间基分子/分母` | PTS 对齐（04） |
| 已呈现/丢弃帧 | `已呈现视频帧数` 等 | 性能诊断（可选） |
| 解码器/色彩模式 | `解码器`/`请求色彩模式`/`实际色彩模式` | 设置面板/一致性 |
| 音频诊断 | `音频缓冲100纳秒`、`音频欠载次数` | 可选 |

| 字幕/弹幕状态 | `GetTimedTextStatus` 等 | （可选） |
| 媒体元数据 | `GetMediaInfo` JSON（流、编码、像素格式、码率等） | 媒体面板 |

| 事件 | 用途 |
| --- | --- |

## 4. 互操作与数据流注意事项

1. **UTF-8 指针/位图固定地址只在同步调用期间有效**（托管互操作层会处理固定）；
   本项目如自行增加 P/Invoke 调用需遵守该契约。
2. **高频读取 `当前快照` 安全**；严禁在播放线程里直接访问 WASAPI 对象（我们不会）。
3. **播放器命令对状态敏感**：不适用命令抛 `播放器异常`；编排层需先查询快照状态再发命令。
4. **SDR/HDR 切换**：当前媒体 SDR→HDR 需要重配交换链（3FP 内部处理）；
   多路中某路 HDR、其余 SDR 时，`比较工具`（探针、差异）基于"颜色管理前缓冲"读值，
   需在相同 `色彩模式`（如都映射到 SDR 的 BT.709 码值）下对比才语义一致。
5. **每路独立 HWND**：flip-model 交换链不能同窗口并存；PlayerSurface 需保证互不嵌套。
6. **ACM/广色域**：探针回读（`ReadVideoPixel`）与截屏路径都走「颜色管理前」缓冲，
   因此**不依赖显示器是否启用 ACM**即可取得一致的视频码值；显示器侧呈现由 DWM 完成。
7. **VRR**：本软件不创建"覆盖在其他应用之上的图层窗口"（RTSS 式叠加），
   因此 VRR 只与**交换链参数 + 窗口 Present 节奏**有关；是否彻底生效取决于 3FP（见 A8/A9）。
   > **2026-09-16 实测**：已支持。`--selftest` 两条断言 `VRR 撕裂呈现: 显示器链支持 ✓`、
   > `VRR 媒体率节奏: 已启用 ✓`（对应 `SetPresentConfig` / `SetPacingConfig`）。
   > 这两项也是内核基线校验的 4 项扩展 API 中的 2 项。
