## 第一部分 · 现状解剖（实测）

### 1.1 六个线性流程，全部是"单 try 剧本"

| 流程（命令行模式） | 内部步骤 | 整轮实测 | 现在谁在跑 |

| `--comparemodetest <视频> [路数]` | 29 个已隔离单元 + 若干内联块 | 2 路 **3.5 s** / 4 路 **12.5 s** | **不在门禁里** |

| `--magnifybench …` | 阶段计时，外部脚本采样 | 分钟级 | 手工 |

`对比-*` 11、`会话往返-*` 9、`screentest-*` 4、`模式-*` 2、`放大镜浮窗坐标` 2、`基准-*` 2、
`UI消息注入-*` 2，`多路*` 5，其余 28 个各 1 处（布局 / 侧栏三态 / 帧步进 / 秒步进 / 倍速切换 /

### 1.2 已隔离单元的实测成本（4 路，`cost-r4.log` 原样）

| 单元 | 实测 | 单元 | 实测 |
|---|---|---|---|
| 对比-加减路契约 | **375 ms** | 对比-滚轮无缝放大 | **940 ms** |
| 放大镜浮窗坐标 ×3 | 186 / 1 / 207 ms | 对比-左右互换 | **741 ms** |
| 无缝放大 z=2 | **321 ms** | 对比-轮换画面 | **734 ms** |
| 对比-分割驱动重排 ×2 | 0 / 17 ms | 对比-对齐模式 | **730 ms** |
| 对比-切换 <模式> ×10 | **全部 0 ms** | 对比-模式变体 ×2 | 573 / 496 ms |
| 模式-分屏入口 / 网格入口 / 对比-退出 | **0 ms** | 对比-进入 ×3 | 1 / 0 / 1 ms |

**隔离单元合计 ≈ 5.3 s，整轮 12.5 s ⇒ 约 58 % 的钱花在单元之外**（起盘 4 路解码、等待就绪、
`EnterCompareMode` + 固定 delay、收尾清理）。

### 1.3 三条结构性事实（这才是"混乱"的所指）

1. **12 / 29 个单元测出 0 ms** —— 不是它们快，是**贵的前置在单元外面**：`对比-切换 Ab` 的
   0 ms 是因为 `EnterCompareMode(m)` + `Task.Delay(150)` 写在循环里、单元外。
   ⇒ 成本归因现在不可信，"这条单元要不要真解码"也看不出来。
2. **单元靠继承活着**：`对齐模式` 依赖上一步已经把放大开着；`轮换画面` 依赖上一停在哪一格；
   `退出` 依赖前面没人改过 `CellOverride`。⇒ 不能单跑、不能重排、一处红全部作废。
3. **文件级 117 处 `Task.Delay`，合计 45 775 ms**（`grep -o "Task\.Delay([0-9]\+" | awk` 复算）。
   绝大多数是"等布局/等 AfterRender/等落盘"，没有一处是**等产品的"确实重算过"信号**
   ⇒ 固定时长既是成本来源，也是偶发红/假绿的来源（本轮 `子 HWND 尺寸` 1/7 竞态即此类）。

### 1.4 已经改掉的部分（切片 0，见 `CHANGELOG.md` [未发布]）

`--comparemodetest` 的 20 处单行调用点包进 `StepAsync` + 末尾汇总表。验牙：强制「左右互换」抛异常后，
其后 轮换 / 对齐 / 变体×2 / 分屏 / 网格 / 退出 全部照常执行并逐条上报，整轮 exit=1。
**fail-fast 掩掉后面这一条已经解决**；本节 1.3 的另两条还没。

## 第二部分 · 拆分的四条硬规则

| 规则 | 内容 | 违反时今天的具体后果 |
|---|---|---|
| **R1 自带夹具** | 单元只声明前置、自己把世界摆好，跑完复原。判据：**单独跑与在批里跑，读数必须相同** | `轮换画面` 判据用 `Bounds` 当"换位代理"，因继承到的旧值而假红；我为了确认归属不得不跑 9 次整轮 |
| **R2 Lane ≠ Route** | `网格路数` 与 `会话路数` 是两个字段，任何单元不得假设相等 | 本轮产品缺陷本体（加路锚在会话数上，A/B 下撤 lane 会销毁素材）；两条历史判据也栽在这里 |
| **R3 单层权威** | 同一条真相只允许一层是权威：算术/规则归 V1，实机层**只断接线与落地** | 实机「对齐模式」判据与 `CompareCropPlannerAlignTests` 互相矛盾（前者要 `crop=view`，后者钉 `crop=view·(1-1/z)`），谁都没发现，因为前者从没被执行到 |
| **R4 SKIP 要写原因** | 缺素材 / 演示模式 / 显示器放不下 ⇒ `SKIP(原因)`，不计入通过，也不混进分母 | `small.mp4` 的 `放大镜-探针一致性` 假红；"工作区只有 2560 宽时放大判据不可能成立"；演示模式下 ✓ 却是降级 |

只列**当前不可单跑**或**成本归因失真**的条目；未列出的按名归入上表同名部分。

| 现 `_step` | 现形态 | 归入 | 拆开后需要做的 |

### 切片 1 落地记录（2026-09-26，实测）

**运行侧**：所有自动化模式共用的 `StartDeadlineWatchdog` 现在先打产物身份，日志能自证出自哪个二进制：

```
[产物] mode=comparemodetest process=…\3FCompare.exe
[产物]   InformationalVersion=0.3.0-beta+549619b0… process-mtime=2026-09-26 07:31:32Z baseDir=…
[产物]   managed-assembly=…\3FCompare.dll assembly-mtime=2026-09-26 07:31:32Z
```

身份以 `Environment.ProcessPath` 为主、`Assembly.Location` 只在非空时附加：AOT / 单文件下
Location 恒为空串（编译器警告 **IL3000** 说的就是这件事），拿它当身份恰恰在最需要溯源的
AOT 包内自测里会打成"(无独立文件)"。这一条是写的时候被警告逼出来的 —— IL3000 还一度把门禁
`[3/11]`"白名单外告警必须为 0"打红（白名单只有 `AVLN3001`）。

**构建侧**：`tools/验证守卫.ps1`。三条判据各有独立退出码，本机各真实触发过一次：

| 退出码 | 含义 | 本机真实现场 |
|---|---|---|
| **3** | 产物陈旧 | 最新输入 `src\3FCompare\MainWindow.SelfTest.cs` 比 `3FCompare.dll` 晚 **763 s**（90 个输入参与比较） |
| **4** | 构建失败且**不回退旧产物** | `MSB3027 … 文件被"3FCompare (70628), 3FCompare (56260)"锁定` |
| **6** | 构建输入枚举不足 ⇒ fail-closed | 故意传 `-SourceExt '.zzz'` ⇒ "源码类别枚举到 0 个，要求 ≥ 20"，不判新鲜 |

第一版在这里栽过，值得留档：`Get-ChildItem -Path 'src\**\*.cs' -Recurse` 在本机
Windows PowerShell 5.1 下**静默枚举不到 .cs**，于是守卫拿一个 09-22 的 `.slnx` 去比，
把"源码比产物新"判成"新鲜"并放行 —— **守卫自己差点成了假绿的新源头**。
现在改用 `[IO.Directory]::GetFiles(..., AllDirectories)` 按扩展名过滤、**逐类别**比较、
每类要求最低数量（枚举为空即拦下），并把两侧究竟比了哪个文件都打印出来。

**尚未做**：把源码内容指纹内嵌进 exe（`--build-id`）。mtime 判据对"跨机器拿来的产物"不适用，
那种场景要显式 `-SkipSourceCheck` 并在结论里写明"未经新鲜度校验"；指纹内嵌需要一个构建期
生成的常量文件，留给切片 2 顺手一起做。
