### 关键坑与纠错

1. **Avalonia `WindowState` 枚举顺序是 0=Normal, 1=Minimized, 2=Maximized, 3=FullScreen**
   (原 handoff 注释写的 1=Normal/2=Maximized/3=FullScreen 是错的)。代码用符号名比较故逻辑正确,
   已修正注释。验证依据:`~/.nuget/packages/avalonia/11.0.0/lib/net461/Avalonia.Controls.xml`。
2. **最大化关闭会写坏窗口尺寸**:App 以 Maximized 启动时 `OnOpened` 不记录 `_lastNormal`
   (那时已是 Maximized),导致 OnClosing 回退到 `Bounds.Size` 把屏幕尺寸存成用户偏好尺寸。
   修法:在 `RestoreWindowGeometry()` 里预置 `_lastNormal`。实机验证 1280×720@200,150 往返正确。
3. **`dotnet restore` 在本机环境失败**(`Value cannot be null. (Parameter 'path1')`,NuGet.targets:796),
   与项目无关——空白新项目同样失败。**一律用 `--no-restore` 构建/测试**。
4. **multitest 偶发原生崩溃**(约 1/5,SIGSEGV/SIGILL,崩在"全路就绪"后播放启动),
   与代码无关,复跑即过;疑似与同时段其他进程占用 GPU 有关。

### 退出期 CLR 断言（已修复）
现象：自测"全部通过 ✓"后进程以 127 退出，报 `coreclr/vm/ceemain.cpp:1750`
"Attempt to execute managed code after the .NET runtime thread state has been destroyed."
根因：托管委托（内核事件回调 `Fff3FpSession._callback` + 日志回调 `KernelLogBridge`）
交给原生后，内核线程在 CLR 停机后仍反向 P/Invoke；自测还绕过 OnClosing。

排查过程中被证伪的假设（都实测过，勿重复走）：
- 只卸载日志 sink → 断言依旧（FFF_NO_KERNEL_LOG=1 仍复现）→ 日志回调不是主因
- 只 Dispose 会话（Clear() 内部其实已经 Dispose）+ 3 秒静默期 → 仍复现
- 关闭窗口销毁子 HWND → 仍复现
- 断言确发生在 Environment.Exit **之后**（静默期结束标记之后）

最终方案 `MainWindow.ExitSelfTest()`：DestroyAllSessions → Uninstall sink → Close()+
`Dispatcher.UIThread.RunJobs()` 销毁子 HWND → 静默期 → flush → **TerminateProcess**。
- `Environment.Exit` 走托管停机，原生线程有机会回调 → 断言
- `ExitProcess` 跑 DLL_PROCESS_DETACH，**在 FFF.Native/D3D11 上死锁**（进程 10 分钟不退出）
- `TerminateProcess` 不跑 detach、可指定退出码 → 真实 4K 单路 selftest 连续 5 轮 exit=0

### 结论更正（重要）
换真实 4K 素材后，多路播放崩溃从"偶发"变**近乎必现**；`HardwareDecode` 开/关都崩
（软解也出现 SIGILL）→ **与硬件解码无关**，此前基于合成素材的判断有误。
单路 selftest 稳定 → 问题在多路并发的解码/呈现路径，属 FFF.Native 原生缺陷，待 dump 定位。
